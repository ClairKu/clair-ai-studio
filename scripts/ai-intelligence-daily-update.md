# AI 行业情报站每日维护契约

## 内容边界

只维护外部公开 AI 行业资料。不要读入、发布或覆盖用户的内部工作、公司资料、浏览器本机上传或收藏。现有报告、机构、语录、对照共享同一情报站，不新增平行门户。

## 每日核验

1. 安全同步远端 main；工作区不干净时使用隔离工作区，禁止强推。
2. 报告优先原始研究机构。核对日期、方法、样本、分母、单位与数字，分别保留结论和局限。
3. 按 `ai-classic-quotes.json` 的 `coverage.organizations` 核验机构代表人物的新观点，再轮换补历史经典。本人博客、官方演讲、论文、原采访者完整问答均可；媒体转述或名言聚合页不是原始证据。
4. 每人保留多条历史记录。人物机构采用发言时身份；不能用今日职位替换历史身份。联合署名不得拆成单人原话。
5. `originalLanguage` 指明原文语言：中文原话配英文译文，英文原话配中文译文。原话必须逐字核对；解释另写。记录日期精度、场合、背景、评价对象、出处定位、适用边界与 `verifiedAt`。
6. 同一原始来源累计英文原文摘引不超过 25 词，中文原文摘引不超过 50 个非标点字符。不要通过不同镜像或 URL 参数绕过限制。
7. 近期内容不等于绝对最新。未找到可核验新材料须保留覆盖缺口，不凭空写更新；`updatedAt` 为资料变更日，不以修改日期制造新内容。
8. `comparisons` 必须有共同议题、左右出处、共同点、分歧、阅读建议与边界。只有同一对象及可比较范围的实质冲突可标 `opposed`，并填写 `oppositionBasis`；其他差异用 `tension`，关系只是编辑分析，不代表双方直接回应。
9. 每条新观点至少连接一个有明确理由的其他观点；对照关系双向写入 `relations`，并核验所有 ID。

## 集成与验证

- 主资料：`public/reports/knowledge-report-hub/data/ai-industry-authority.json`、`ai-classic-quotes.json`。
- 站内入口：`reports/knowledge-report-hub/#quotes`、`#comparisons`，旧 `/quotes/` 链接兼容。不要恢复独立门户。
- 运行 `npm run sync:knowledge-hub`、`npm run validate:quotes`、`npm test`、`npm run build`，维护 public/docs 对应镜像、资源清单和工作台搜索条目。
- 构建前后检查无关生成文件；本次发布只包含已审查的目标变更，不误删或覆盖并发成果。访问密码和加密边界不能因验证便利而放宽。
- 发布前再次比较远端 SHA，正常快进 / Git Data API `force:false`，父提交必须为刚核验的远端版本。
- 等待 Pages 成功。验证入口、代码、资料、搜索条目 HTTP 和内容/哈希，报告数、证据卡数、语录数、人物数、对照数以及新增原文链接。前端仍受密码保护时，核验 gate 与部署字节一致，不伪称已在未授权浏览器里看完内容。
- 仅公开内容有实质新增/更正且检查通过时发布；失败明确说明本地、提交、部署、线上核验分别到了哪一步。每天任务处于启用状态不代表未来每次一定成功。
