System map

它不是网站
是五层生产系统

VESTA 的核心不是“有多少页面”，而是能否把数据、算法、对象、生产工具与对外输出连成闭环。当前前四层已经很厚，第五层已通过 MCP/OpenAPI/嵌入式页面开始外溢。

业务输出层

研究员、投顾、投资经理、机构 SaaS、启明工作台、且慢、MCP/API、报告与小程序。

生产应用层

研报、基金优选、资产配置、组合实验室、固收研究、投资信号、私募集市、AI Skills。

分析算法层

MVO、Bootstrap、RBSA、Brinson、风险收益、择时、HP 滤波、OLS、评分与归因。

投研对象层

基金、经理、组合、指数、资产、行业、债券、信号、报告、市场阶段、评分方案。

数据治理层

FDP、净值/行情/持仓/财务/宏观/资讯/爬虫/内部研究数据，带日期、频率、版本与权限。

原始数据 → 标准化对象 → 指标/模型 → 页面与工具 → 报告/API/MCP → 使用反馈与算法迭代

Data inventory

数据不是一张表
是十二类对象

跨模块最容易出错的是“同名不同源、同值不同频率、同占比不同分母”。VESTA 对外输出时至少应同时带上：对象、来源、频率、截止时间、单位、分母、版本与缺失处理。

净值与收益

基金复权净值、组合费前/费后净值、基准净值、估算净值、策略回测净值；基金年化与组合年化基数并不一致。

行情与估值

指数日频/分钟行情、PE/PB、ERP、期货结算价、债券收益率、外汇与黄金。

基金基础资料

基本信息、分类、规模、费率、基准、管理人、经理、公告、交易规则。

持仓与报告期

资产、股票、债券、行业、评级、期限、转债；季度重仓与半年/年报全持仓必须区分。

组合与调仓

组合信息、成分、权重、费率、调仓草稿/记录、基准、日度清算与 PMS 同步。

宏观与政策

增长、通胀、利率、货币、流动性、FOMC、CFTC、国别周期；混合日/月/季频。

行业与风格

行业指数、盈利、ROE、估值、资金、政策、技术信号；风格因子与 HP 滤波结果。

固收曲线

资金价格、国债/国开/地方债、信用与等级曲线、期限利差、流动性利差与实际取数日。

经理与观点

任职、从业、在管、代表产品、观点、研报与聚合后的经理指数/穿透。

研报与内容

文件、作者、分类、日期、摘要、浏览、下载、发布状态与权限；是 AI 的知识输入。

信号与模型

因子原值/标准化值、分项得分、仓位、系数、预测区间、策略净值、算法更新时间。

配置与治理

时间区间、评分方案、合成指标、基金池、行业池、角色权限、机构映射和算法版本。

Product diagnosis

真正的问题
不在“功能不够多”

VESTA 的功能密度已经很高。当前最需要解决的是：用户如何从对象进入任务、如何理解口径、如何把结果写回业务，以及平台如何证明每个结论可复核。

1. 页面多，任务链仍断

基金、经理、组合、信号、研报都很强，但“选对象 → 诊断 → 形成观点 → 生成报告 → 审核 → 输出”仍需要用户跨页拼装。

2. Chat 共屏但不共上下文

历史实测中 Chat 无法自动读取当前经理页；长任务还出现网络中断。它更像通用问答，不像对象页 Copilot。

3. 口径治理追不上能力增长

250/252、自然日/交易日、总资产/净资产、报告期/估算、排序分位/参数分位等并存，缺少统一口径护栏。

4. API 成功不等于业务可信

存在静默空值、Mock、隐藏必填、枚举不全、错误码不一致；“HTTP 200”远不足以作为能力验收。

5. 权限与外输边界复杂

RBAC、机构、broker、组合可见、云盘和 OpenAPI 并存；必须把身份、数据、功能、导出和调用权限统一治理。

6. 产品价值未被包装成岗位成果

研究员要的是报告、观点和跟踪清单；投顾要的是可解释结论；机构要的是稳定接口和 SLA。页面功能还没有完全转成岗位结果。

Action plan

下一步优先级
不是再加菜单

建议沿“任务闭环、口径契约、AI 共上下文、能力治理”四条主线收敛，先让已有能力变得可用、可解释、可复用。

建立对象页 Copilot

基金/经理/组合/信号页自动注入对象、选中表格、筛选条件、图表口径与数据截止时间，提供“解读本页、生成报告、生成话术、找异常”四个动作。

P0 · 立即

建立统一指标契约中心

每个指标拥有公式、单位、方向、年化基数、分母、频率、来源、版本、缺失处理与示例；页面、API、MCP 共用一份 SSOT。

P0 · 立即

修复 index 批量数组序列化与静默失败

错误必须区分 validation_error / not_found / no_data / permission_denied / upstream_error；无效指数不可再静默 null。

P0 · 本周

把 Skills 做成可审核生产线

输入对象 → 参数模板 → 工具调用 → 图表与结论 → 引用证据 → 研究员审核 → 写回研报/工作台；支持断点续写。

P1 · 4周

统一 VESTA × PMS × 启明 × 且慢的对象协议

组合、持仓、调仓、信号、报告、客户解释使用稳定 ID、版本与状态机；VESTA 负责研究生产，不越过适当性与交易确认边界。

P1 · 6周

建立每周能力变更雷达

自动比对 tools/list、schema、核心样本、口径、错误率、最新数据与页面入口；新增或变更必须带发布说明和回归证据。
