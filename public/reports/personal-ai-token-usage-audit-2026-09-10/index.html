行为判断与下一步

事实

个人电脑是主力

72.1% 的可见用量来自个人电脑，且几乎全部由 Codex 贡献。设备治理和上下文清理应优先从个人机 Codex 开始。

事实

高峰仍集中

双设备可见期 83 个活跃日，前 5 个高峰日贡献 44.9%；38 天同时出现至少两类设备来源。

建议

以后按快照增量同步

保留设备键、事件去重键和截止时间。每次只追加新事件；账号级平台只更新共享桶一次，避免两台电脑重复抓取。

数据边界与可审计来源

已确认

  • 公司电脑：沿用原报告截至 2026-09-11 的四类本地来源。
  • 个人电脑 Codex：累计 token_count 的 last_token_usage；输入拆为新内容与缓存读取。
  • 个人电脑 WorkBuddy：providerData.rawUsage，按 messageId 去重。
  • 个人电脑 Kiro：tokens_generated.jsonl 共 5 条，只有总量。
  • Cursor：官方账号级用量接口，总量只计一次。

缺失 / 不可推出

  • 本地日志留存不完整，缺失日期不等于零使用。
  • Cursor 无设备字段，不能按公司 / 个人电脑拆分。
  • ChatGPT、Claude Desktop、Trae 没有可靠本地 Token 口径，不用会话数估算。
  • 两台电脑如果手工迁移过同一会话，现有聚合快照无法跨设备按消息 ID 去重。
  • Token 吞吐不等于成本、效率或交付质量。
