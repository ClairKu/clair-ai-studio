星耀数智 ETF Skills：银河证券把 AI 交到谁手上

从 ETF 年会现场两页 PPT 出发，对中国银河证券「星耀数智」品牌下的 AI 工具与 Skill 生态做了全链路调研与可行范围内的实测：官方入口、SDK 工具面、开通门槛、野生 Skill 生态与真实用户评测、财报口径核对、券商 Skills 竞局对照。

核 心 判 断

  1. 「星耀数智 ETF Skills」是一次品牌再包装：星耀数智的公开身份自 2023 年起一直是机构/量化客户的金融数据平台（AmazingData SDK）。PPT 把它延伸成 C 端「AI Skill 底座」，这个口径领先于全部公开信源——官网、财报、媒体均无发布记录，大概率是尚未发稿的会议口径。
  2. C 端 Skills 是 APP 内封闭能力，不是开放 Skill：五大能力（金融数据/ETF定投/ETF组合配置/公告搜索/自选股管理）只活在中国银河证券 APP 里，需开户使用；与国泰海通灵犀把 Skills 上架腾讯 SkillHub、华为小艺的开放路线相反。
  3. 真正可被外部触碰的只有量化数据 SDK，且门槛是天花板级：银河 111 开头账户 + 申请权限 + x86_64 Linux + 账密明文直连指定 IP。官方从未发布过 Skill/MCP 包，第三方封装全部来自同一位社区开发者。
  4. PPT 的 ETF 生态数据无一可在公开渠道证实（+70%、650亿、232.81万、3.6倍等 9 项全部「仅见 PPT」），但方向与财报可证实的事实（ETF 保有市占行业第一、买方投顾 70 万人）一致——数字可信，口径需会后新闻稿或年报核实。
  5. 对盈米的镜鉴：银河证明了「券商把专业工具 Skill 化交给客户」已从叙事进入 KPI（查询量较年初 3.6 倍进了高管 PPT）；但其封闭发布、开发者体验缺位、凭证安全粗糙，恰是 OAP「开放安装 + 网关鉴权」路线可以打的差异点。

03

实测记录：外部能摸到哪里，卡在哪里

3.1 官方入口实测

  • 官网下载中心确有「星耀数智服务平台」独立条目，详情页给出定位（量化四环节中承担「数据获取 + 业绩归因」）、业务邮箱 xysz@chinastock.com.cn、「立即下载 / 注册试用」入口；可公开下载 TGW-SDK_V1.0.8.zip（2025-11-20 更新）与《星耀数智服务平台(TGW)开发手册（C++版）》。官方
  • API 文档不在官网：Python SDK 的完整文档托管在第三方站 amazing.ptradeapi.com（「可转债量化分析」博主维护），开通指引也是「关注公众号申请权限」——官方开发者门户缺位。社区
  • 分发闭环：tgw 包曾出现在 PyPI（搜索引擎有收录），实测现已 404 下架；SDK 实际经银河官方云盘/腾讯云 COS 分发 wheel 文件，配 SHA256 校验。即不走公共包管理器，装包即闭环。社区

3.2 工具面盘点：165 个接口 + 92 个算子

基于 API 文档与社区实测报告，SDK 能力分七大模块（InfoData / BaseData / MarketData / Math / Stats / TimeSeries / CrossSection），核心目录如下：

3.3 开通链路与硬门槛：为什么外部跑不通

门槛 1必须是银河证券客户，且资金账户为 111 开头；非 111 账号服务端自动拒绝。开通需人工申请「星耀数智」数据权限，获账密 + 指定服务器（实测社区口径：140.206.44.234:8600）。 门槛 2仅支持 x86_64 Linux——ARM 与 macOS 不支持，本机（Apple Silicon）被硬件层直接排除；需放行 8600 端口，云沙箱环境普遍拦截。 门槛 3凭证走明文：ad.login(username, password, host, port)，账密以环境变量/参数直传外部 IP，无 OAuth、无令牌化——Skill 平台安全检测因此给出 HIGH/红色评级。 门槛 4C 端 ETF Skills 无任何外部入口：无 H5、无小程序公开入口、无第三方平台上架记录，只能在开户后的银河 APP 内体验。 已测项官网入口与下载物验证、API 文档全目录盘点、PyPI 分发状态核实（404）、三个第三方 Skill 页与全部 18 条真实评测抓取、GitHub 生产级用例代码结构审读。社区 Skill 包因平台安全检测标红（红=不安全），按安全边界未下载执行。

结论：银河的「开放」止步于自家客户的开发者化（给客户 SDK），从未开放给公域 AI 生态。这与第 06 节竞品的公域上架策略形成直接对照。

评测共识（好评侧）

  • 数据权威性是核心卖点：直连银河官方服务器、无第三方中转，被多位评测者视为「券商级官方数据 SDK 在 AI Agent 生态中独一无二」，稀缺性普遍打 4–5 分。
  • 接口全量可用：「120/165 个接口和算子全部测试验证通过」出现在多条独立评测中；有评测者用它跑通了 MACD 金叉选股、持仓回测、连板扫描等实战脚本。
  • 供应链安全意识超行业水平：SDK 文件 SHA256 校验、数据流向声明、十条款隐私声明，被评「金融机构合规标准」。

评测共识（差评侧）——每一条都指向银河产品本体

  • 准入即天花板：「对银河客户是神器，普通投资者完全无法使用」「非银河客户优先考虑 AKShare/TuShare（零门槛覆盖 85% 同类需求）」——几乎每条评测都以账号门槛收尾。
  • 凭证安全被反复点名：明文账密传外部 IP 被平台判 HIGH 风险，多人建议「改 OAuth 或令牌化授权」，有评测者「因安全顾虑未敢接入真实账号」。
  • 工程适配粗糙：仅 x86_64 Linux、Python 版本苛刻、闭源 wheel 无法审计、Coze 等沙箱环境完全跑不起来；试用期 2026-06-30 已到期未续。

一个生产级用例：SDK 被拿去建数据湖

GitHub 项目 SindenDev/AmazingData 用星耀数智 SDK 搭了完整生产管道：Airflow 调度每日采集，Parquet(zstd) 落盘，同步 RustFS/S3 + Iceberg + ClickHouse，覆盖 K 线（股票/指数/ETF，2013 年至今回填）、三表、两融、股本分红、指数行业成分。社区 这证明数据面质量足以支撑机构级工作流；但其 README 同时留下了 SDK 工程质量的证词——作者不得不在客户端修补：

SDK 内部 local_path + "infodata" 字符串拼接导致路径错误，需自行规范化；指数权重必须逐个指数请求，「批量调用触发 SDK 异常」；返回值 None/dict/DataFrame 三态混杂，需统一兜底处理。

读法：数据资产是真的强（券商直连、全品类、深回溯），开发者体验是真的糙（闭源、跨平台缺位、接口不稳、文档外包给博主）。这组反差正是「数据中台强、产品化弱」的典型画像。

07

产品深度分析：七条判断

  1. 能力底座是真实的，且同源复用。C 端五大 Skill 的每项原料都能在 AmazingData 接口面找到对应（ETF 净值/份额/IOPV→金融数据；K 线回溯→定投测算与组合回测；申赎与公告数据→公告解读；实时快照→盯盘提醒）。一套机构级数据中台喂两端，是其效率优势。
  2. 「Skill」在银河语境里是产品叙事，不是技术协议。C 端五能力更像 APP 内的 AI 功能菜单；真正协议意义上的 MCP/Skill 只在机构 PB 条线（半年报原话）。对外讲「Skills」蹭的是 2026 年行业热词，产品实体是封闭的。
  3. 商业模式已跑通「AI 直接收费」。财富星-AI投顾按笔 8.8 元/包月数千元档收费，这在券商 C 端 AI 里相当激进；ETF Skills 查询量进高管 PPT，说明内部已把 AI 使用量当经营指标考核。
  4. 安全与合规是最大暗伤。明文账密直连指定 IP 的鉴权设计，放在 2026 年的 Agent 生态里是显眼的落后项；社区平台连续给出 HIGH/红色评级。一旦官方想开放生态，鉴权体系需要推倒重来（OAuth/网关代理）。
  5. 开发者体验外包给了民间。API 文档挂在博主网站、开通靠公众号私信、SDK 下架 PyPI、Skill 封装靠个人开发者用爱发电——与其数据资产的强度严重不匹配。这说明星耀数智内部定位仍是「客户服务工具」，不是「平台产品」。
  6. 数字口径有会销水分,但趋势可信。「+70%」「3.6 倍」全部无分母无绝对值,典型的低基数高增速讲法;不过 ETF 保有市占第一、客户 2050 万是审计过的硬底盘,「AI 查询量指数级爬坡」与全行业观察一致,方向不必怀疑。
  7. 下一步棋可以预判：参照同业节奏与其半年报「PB 已上 MCP/Skill」的伏笔，银河大概率在 12 个月内把 ETF Skills 从 APP 内走向公域上架（腾讯 SkillHub/华为小艺），并补一次正式发布会。届时今天 PPT 里的口径会成为对外基线。
08

对盈米 / OAP 的启示

  1. 「Skill 查询量」已成对外汇报语言。银河把「较年初 3.6 倍、单月创新高」放进行业年会 PPT——OAP 的 Skill 调用量、MCP 工具调用数据同样可以且应该做成对客户/董事会的叙事资产（盈米已有豆包/千问渠道用量基线，口径成熟度反而领先）。
  2. 银河的封闭是盈米的空间。券商 Skill 无一例外只服务「自家开户客户 + 自家产品数据」；OAP 面向投顾机构的开放安装、跨管理人产品数据、买方立场分析，是券商结构性做不了的差异位。竞标或客户沟通中，「券商 Skills=导流工具，OAP Skills=投顾生产力」是一句现成的定位话术。
  3. 鉴权设计是显性竞争力。银河被社区反复打 HIGH 风险的明文账密,反衬 OAP「Key + 网关限定名 + 权限盘点」路线的正确性——这一点值得写进 OAP 的安全白皮书/售前材料,做成可对比的卖点。
  4. ETF 定投/组合回测/公告解读三个 C 端场景已被验证有真实查询需求（银河用查询量证明了）。OAP 的投顾侧 Skill 清单可对照检查：面向投顾的「帮客户算定投」「组合回测讲解」「公告转话术」是否已覆盖——这是被券商验证过的需求清单，值得逐项对齐。
  5. 值得持续盯梢的信号：银河 ETF Skills 的正式发布稿/公域上架动作、2026 年报是否披露 ETF 专区与 Skills 运营数据、「星耀数智」商标向 C 端的延伸注册。建议纳入季度竞品扫描。
