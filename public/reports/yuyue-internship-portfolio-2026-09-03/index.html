指标口径：每个数字怎么来的（页脚原文重现）

看板每一页底部都固定挂一份口径说明，共 11 条。这份口径是整个项目的「合同」，全文如下：

条目口径定义（原文）
① DAU / MAU与小顾发过消息的去重用户数，口径「发过消息」（非仅打开）；MAU 为截至 endDate 滚动 30 天
② 新增使用人数当天第一次发消息且历史从未使用过小顾的用户（小顾无独立注册入口，以首次对话为激活事件）
③ 留存率次日/7日/30日是业务固定周期，全局时间筛选器不改变这些定义
④ 记忆/画像开启率截至 endDate 的累计状态，分母 = 截至该日累计小顾用户（非 DAU / MAU / 总注册用户）
⑤ 对话强度平均对话轮数 = 总轮数/会话总数；QPU = 当日提问总数 / 当日 DAU（daily ratio，KPI 取 endDate 当天值，趋势按区间聚合重算）
⑥ 创建任务数区间内被创建的任务总数量（与「创建任务人数」是不同口径，不要混淆）
⑦ 活跃天数分布跟随全局时间区间，根据区间长度自动生成合理 bucket（短区间 1~7 天，长区间合并分段）
⑧ 报告日均类 KPI环比严格 T vs T-1，不受全局区间影响
⑨ AI 能力 Top3所选区间内后台调用次数汇总重排
⑩ 成本模块原始粒度=月，按全局区间筛选落入区间的月份
⑪ 时间交互顶部全局筛选器决定「分析哪个时间段」；趋势图粒度切换决定「怎么聚合显示」，二者独立

数据引擎设计（Phase 1.1 / 2A）

看板不是「写死几组数字」的静态页面，而是实现了一条真实的 raw data → filter → aggregate 管道：

365 天日粒度原始数据

DAU 从 3,800 自然增长到 6,150（年 +62%），叠加周末 +5%、月初/月末、±3% 噪声；MAU 按滚动 30 天由 DAU 推算。

分子分母分开存储

QPU、平均轮数不存比值，存原始「提问总数/会话总数/总轮数」，切换时间区间时聚合重算，比值才正确。

确定性伪随机

所有噪声用种子伪随机生成，React 重渲染结果稳定，刷新不跳数。

2,000 个模拟用户位图

用户活跃明细用 Uint32Array 位掩码存储（1 bit/天），分低频 40% / 中频 35% / 高频 20% / 新用户 5% 四种行为模式。

会话按需生成

对话会话不预生成 50 万条全局数组，而是按所选日期区间 procedural 生成，控制浏览器内存。

性能与状态设计

只有 active 页面真正 mount（非活跃页的 Recharts 不进 DOM）；GlobalTimeProvider 在 Shell 之上，切页不重置时间区间。

02 · EXECUTION CHAIN PROTOTYPE

小顾执行链 · Debug 交互原型

纯前端可交互原型 · 部署于 Netlify · 支持重播与中断

这个原型回答一个交互设计问题：当用户一句话里塞进多个任务，AI 助理的执行过程该怎么展示？原型模拟了一个复合请求的完整执行链，把「先答核心问题、再做后续处理」拆成两段可折叠的执行轨迹，并设计了中断机制。

模拟场景

帮我看看持有策略的定投和发车情况，记住这次结果，每周一提醒我检查，并生成报告和图表。

一句话包含四个任务：分析、写记忆、建定时任务、产出报告。

执行链全流程重现

✓阶段一 · 前序分析（12 秒，完成后自动折叠）
决策 1：先读取持有策略和最近的发车记录，确认哪些信号已经提醒过。
◇ 查询持有策略 · 2 项
◇ 浏览策略详情与最新估值 · 3 次
◇ 运行发车信号去重检查
已确认：两个策略最近一次发车信号均已提醒，当前没有需要重复操作的新信号。
决策 2：继续核验估值位置和定投状态，形成可直接执行的建议。
◇ 获取最新估值区间 · 2 次
◇ 计算发车阈值与当前位置
◇ 汇总定投与历史提醒数据
判断完成：维持原有定投节奏即可，等待新的发车信号再考虑加仓。
▸ 阶段回答（核心问题先答，不等后续处理）
当前没有需要立即操作的新信号。你持有的两个策略最近一次发车都已经提醒过，建议保持原有定投节奏，暂不重复加仓。
稳健型组合 —— 估值处于合理区间，继续定投 ｜ 普通组合 —— 7 月 14 日的信号已经提醒，等待机会
✓阶段二 · 记忆与定时任务处理（5 秒）
先把本次判断写入记忆，并记录「已提醒信号不重复通知」的偏好。
◇ 读取现有用户记忆
◇ 更新投资偏好与本次执行记录
记忆已更新：以后遇到相同发车记录时，将避免重复提醒。
根据用户要求创建每周一检查任务，并确认执行时间与提醒内容。
◇ 创建定时任务 · 每周一 09:00
◇ 校验下次执行时间与通知渠道
定时任务已创建：每周一 09:00 检查持有策略和新发车信号。
✓最终产出

本轮结论卡片（记忆「已更新」、定时任务「每周一 09:00」、策略估值与发车阈值表）+ 两个可下载文件：持有策略定投与发车情况报告.pdf 与 invest_strategy_report.html。产出文件独立于对话保留——这正是第 06 章「聊天可删、成果可留」方案在交互上的落点。

关键交互设计

分段执行 + 阶段回答

核心分析完成即先给答案，记忆/定时任务在其后异步处理——用户不用等全链路跑完才看到结论。

四类事件的视觉语言

Thinking（思考中）、决策（本步要做什么）、工具调用（带图标与次数）、结果（高亮结论），完成的阶段自动折叠只留「✓ 标题 · 耗时」。

可中断

执行中可随时中断：当前步骤打上「已中断」标签，并明确提示「任务停留在当前步骤，后续操作与报告没有继续生成」。

可重播

原型自带「重新播放」，方便评审时反复演示时序细节。

能力中心的四层能力模型

MCP

平台内置「盈米 MCP」（69 个工具清单，自动调用）；用户可添加自定义 MCP 并单独启停调用权限（示例：hexin-market-mcp 4/4 工具已启用、enterprise-research-mcp、internal-knowledge-mcp 未启用）——「在这里直接开启或暂停智能体的调用权限；连接不会被删除」。

Skills

平台内置「盈米 Skills」清单 11 个（覆盖基金研究、市场解读、财富规划与数据可视化工作流）；支持安装团队/个人 Skill 并控制智能体是否可调用。

Agent

官方能力示例：基金研究助手（自动规划研究步骤，按需调用 MCP 与 Skills）、组合诊断助手（持仓结构、风险暴露、相关性与优化方向）。

组件（且慢 Design Skill）

9 个金融设计组件，每个带使用规范：数据结论卡片、三态重点提示（风险信息始终可见）、金融数据表格（文本左对齐数字右对齐）、收益曲线（只标期末/峰值/谷值）、回撤曲线（负值面积、突出零线）、资产配置环形图（不超过六类，其余归「其他」）、指标对比条形图（≤8 类目）、结构占比堆叠图、用户画像雷达图（5~7 个同口径维度）。

产品叙事：MCP 是通道，Skills 是能力

盈米 MCP

面向金融场景的标准化能力接入协议，统一接入口，五大类能力开箱即用，数据实时更新。两种使用模式：①自建应用（获取 Key 搭建专属金融 AI，适用 AI 开发者）；②平台配置（在 Cursor / Coze 等配置，提问即调用，适用投顾、量化、个人投资者）。

盈米 Skills

覆盖基金研究、市场解读、财富规划与数据可视化的专家工作流引擎，按专家约束沉淀能力，支持下载包自建或平台配置两种模式。

盈米智能体

常见问题（11 条全量）

使用盈米 MCP 服务是否需要付费？
目前使用无须付费。如有大量使用、定制服务或商用目的需求，可联系盈米咨询专属服务。
谁适合用盈米 MCP？
资深投资人（高效解决个性化投资问题）；投资顾问（搭建智能体，自用或服务客户）；更多金融从业人员，包括开发者与业务人员（快速组装高质量金融服务）。
哪里可以用到盈米 MCP 工具？
所有支持 MCP 协议的 AI 应用与 Agent 平台都可接入使用，例如 Cursor、Cline、CherryStudio、Windsurf 等。
为什么要申请 API Key？
只需申请一次专属 API Key，即可长期在多个平台稳定使用。它保障工具使用权益与服务体验，便于跟踪异常、获得技术支持及后续自定义参数或升级。
MCP 是什么？MCP 和 Skills 有什么区别？
MCP 是连接模型与外部数据、服务能力的标准化接入协议。「MCP 解决的是怎么接入，Skills 解决的是接入后能做什么。前者是通道，后者是能力。」
为什么当前只有一个 MCP？
盈米 MCP 作为统一接入口，对外提供标准化的数据与服务访问方式，便于统一管理与持续扩展。
开通后在哪里查看接入方式？其他排查问题
开通后可在个人中心查看服务地址、认证方式与接入配置。Cursor 找不到配置：更新 Cursor 后重试；添加 MCP Server 后无法使用：在设置中确认 Server 状态为绿色可用、处于 Enable 状态后点刷新。
