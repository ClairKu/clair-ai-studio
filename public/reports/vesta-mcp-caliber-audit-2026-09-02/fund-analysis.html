fund-analysis（基金分析，20 工具）指标数据公式口径盘点

盘点日期：2026-09-02。实测 14 次调用（含报错重试），样本基金：005827 易方达蓝筹精选混合、110007 易方达稳健收益债。 资料来源：digest/fund-analysis.md（截断版）+ vesta_tools_full.jsonl（完整工具描述，含出参 schema 与枚举，比 digest 多大量口径信息）+ 实测 JSON。

通用口径（先记住这几条）

项 口径
日期入参格式 绝大多数工具为 yyyy.MM.dd（传 yyyy-MM-dd 直接 LocalDate 反序列化 400）。例外：getFundHolderList / getFundNetAsset / get_fund_return_metrics 的 report/recordDate 为 yyyy-MM-dd
日期出参格式 yyyy.MM.dd（公告工具 reportDate 为 yyyy-MM-dd）
intervalType 枚举 LAST_WEEK / LAST_MONTH / LAST_3_MONTH / LAST_6_MONTH / (LAST_9_MONTH) / LAST_YEAR / (LAST_2_YEAR) / LAST_3_YEAR / (LAST_5_YEAR) / THIS_YEAR / FROM_SETUP_DATE / (FROM_TAKE_OFFICE) / CUSTOMER；自定义区间传 CUSTOMER + startDate/endDate
positionStructure / position semiannual=全部持仓（年报/半年报口径）、quarter=重仓股（季报口径）。传其他值报 0403「持仓结构类型不正确」
benchmarks 数组元素 对象 {code, type[, managerType]}；type 枚举小写：manager(基金经理)/fund(基金)/index(指数)/est(虚拟组合)。est 的 code：semiannual_noAdj(全持仓-不调仓)/semiannual_adj(全持仓)/quarter_noAdj(重仓股-不调仓)/quarter_adj(重仓股)。type=manager 时 managerType 必填：ALL/STOCK/BOND
指数代码 queryFundPerformance 的 indexCode 示例为 000300.CSI（带交易所/指数源后缀）。裸传 000300 后端报 0413「计算任务异常」——实测 3 次均失败即此因
收益率量纲 不统一：get_fund_return_metrics 返回百分数数值（-25.0037 即 -25%）；getIntervalReturnComparison / getFundPerformanceComparison 返回小数（-0.250037）。两者同源（实测严格 ×100 对应）

逐工具盘点

1. get_fund_return_metrics ✅ 实测（005827）

  • 入参：fundCode*；recordDate 可选（yyyy-MM-dd，默认最新净值日）。
  • 出参（实测）：returnOneWeek / returnOneMonth / returnThreeMonth / returnHalfYear / returnOneYear / returnTwoYear / returnThreeYear / returnThisYear（今年以来）/ returnFromSetupDate（成立以来）/ returnAnnualizedFromSetupDate（成立以来年化）。
  • 单位：百分数数值（-0.317209 = -0.32%）。returnFromSetupDate 仅保留 2 位（50.84），其余 6 位小数——精度不一致。
  • 公式线索：区间收益 = 复权净值区间涨跌幅（与 getIntervalReturnComparison 小数值 ×100 完全一致，后者基于复权净值曲线）；年化 = 几何年化（成立以来）。
  • 疑点：年化天数因子（365 自然日 vs 252 交易日）未标注；多期收益（近两年/三年）为累计非年化。

2. getIntervalReturnComparison ✅ 实测（005827 + 000300）

  • 入参：fundCode*、startDate*、endDate*（yyyy.MM.dd）、benchmarks（对象数组，可传 []）、intervalType。
  • 出参：data[] 每个 code 一组 labels：{label, ret}。label 实测枚举：LAST_WEEK/LAST_MONTH/LAST_3_MONTH/LAST_6_MONTH/LAST_YEAR/LAST_2_YEAR/LAST_3_YEAR/YTD（注意 YTD 与入参枚举 THIS_YEAR 不同名）。
  • 单位：小数收益率（-0.250037 = -25.0%）。
  • 注意：传入的 startDate/endDate 不影响 labels 的区间锚点——返回的仍是"截至最新净值日"的固定阶段区间（与 get_fund_return_metrics 数值一致），CUSTOMER 区间本身不出现在 labels 里。
  • 实测坑：benchmark {"code":"000300","type":"INDEX"}（大写）不报错但 labels 返回空数组——type 必须小写 index，且 code 疑需 .CSI 后缀（同 queryFundPerformance）。指数腿未复测成功（配额）。

3. getFundPerformanceComparison ✅ 实测（005827，2026.06.01~08.31）

  • 入参：fundCode*、startDate*、endDate*、benchmarks、excessBenchmarks（结构同 benchmarks，做超额曲线）、intervalType。
  • 出参两块：
    • benchmarks[].trends[]：{recordDate, value, valueDiv}。value 为复权净值归一化曲线，起点=1（描述明确"复权业绩走势"）；valueDiv 实测 null，推断为对超额基准的比值/超额曲线（配合 excessBenchmarks 用）。仅交易日出点。
    • indicators[]（每条曲线一行）：intervalReturn（区间收益，小数）、mdd（最大回撤，负小数）、geomReturn（年化几何收益，实测 3 个月区间收益 -5.07% 对应 geomReturn -19.04%，与 (1+r)^(365/91)-1 量级吻合）、vol（年化波动率，小数 0.160185）、sharpe、sortino、calmar。
  • 公式反推（实测数值）：sharpe×vol = -0.20538 = calmar×|mdd|，且 geomReturn - (-0.20538) ≈ 0.0150 → 夏普/卡尔玛共用同一超额收益分子（年化几何收益 − 无风险利率），无风险利率 ≈ 1.5%/年。calmar = (年化收益−rf)/|mdd|（含 rf 的变体，非教科书 calmar）。sortino 分母为下行波动。
  • 疑点：vol 年化因子（√252 或 √250）未披露；rf≈1.5% 为反推值，具体基准（一年定存/国债）未标注。

4. getFundRankTrend ⚠️ 实测打通但数据为空

  • 入参：fundCode*、freq*（枚举 Q=季度 / M=月份，完整 schema 才有；实测误传 MONTH/WEEK 时不报错、静默返回 data:[]）、categoryLevel（1=一级分类, 2=二级分类）、startDate*/endDate*、intervalType。
  • 出参 schema：[{startDate(区间起点), fRet(收益率), rank(排名), num(同类个数), max(同类最大值), min(同类最小值)}]。
  • 排名口径：按 categoryLevel 一/二级分类排名；分类体系工具描述未写明（同组债类指标注明"招银基金分类"，此处疑同源，未证实）。
  • 疑点：fRet/max/min 是小数还是百分数未实测确认；错误 freq 静默空数组是易错点。

5. queryFundPerformance ❌ 3 次实测未打通（0413 计算任务异常）

  • 失败原因定位：indexCode 传裸 000300；完整 schema 调用示例为 000300.CSI。日期用 yyyy-MM-dd 时报 0403（LocalDate 解析失败）→ 确认 yyyy.MM.dd。isCustomized 与 intervalType=CUSTOMER 配套。n=区间个数（默认 8，疑似分段计算用）。
  • 出参 schema（仅 schema 盘点）：intervalReturn（区间收益率）、intervalReturnRank（区间收益同类排名）、yearReturn（区间年化收益率）、maxDrawdown、maxDrawdownRank、yearVolatility（年化波动率）、downsideRisk（下行波动率）、calmarRatio、sharpeRatio、sortinoRatio、alphaRatio、betaRatio、treynorRatio、m2Ratio（M2 测度）、trackingError（跟踪误差）、informationRatio、count（同类基金个数）。
  • 口径线索：Alpha/Beta/Treynor/M2/TE/IR 均相对入参 indexCode 的市场指数计算——"基准"由调用方指定，非固化业绩比较基准；排名分母为 count（同类基金个数），分类体系未写明。
  • 疑点：全部比率的 rf、年化因子未披露；量纲（小数/百分数）未实测。

6. getFundEstNvGap ❌ 2 次实测 0403（持仓结构类型不正确），正确枚举已从完整 schema 确认

  • 正确入参：positionStructure = semiannual(全部持仓) / quarter(重仓股)（实测误传 ALL/FULL 被拒）；fundCode*、startDate*/endDate*（yyyy.MM.dd）、intervalType。
  • 出参 schema + 官方示例：[{recordDate, gapFromEachPeriod(每期归一差值), gapFromStart(期初归一差值)}]，示例值 0.0123 级别 → 小数。
  • 公式口径（由描述+字段推断）：用最近披露持仓（全持仓或重仓股）构建估算净值曲线，与实际净值同起点归一后作差；gapFromEachPeriod = 当期差值（每期重新归一），gapFromStart = 相对区间期初的累计差值。差值大 → 披露持仓与实际持仓偏离大（隐性调仓/风格漂移信号）。
  • 疑点：估算持仓是否含股价外资产（债券/现金）未说明；"每期"的期界（月末示例）未明确定义。

7. get_fund_duration_estimation ✅ 实测（110007，2025.09.01~2026.08.31）

  • 入参：fundCode*（仅单只）、startDate*/endDate*（yyyy.MM.dd）。
  • 出参（实测）：
    • vol：区间波动率，实测 1.00256842 —— 量纲疑为百分数（债基年化波动 ~1% 合理）；
    • avgDurError：平均测算误差，单位年（0.4268）；
    • trendList[]：recordDate、durEst（测算久期，年，日频）、durEstMa（MA10 移动平均）、percentValue（区间分位数，0~1 小数，如 0.2231=22.3% 分位）；
    • dotsList[]：recordDate、durSensitive（敏感性久期=报告期披露的利率敏感性分析测算值，散点）、durError（该点测算误差）。
  • 公式口径：durEst 为回归/敏感性法日频测算久期；durSensitive 为定期报告披露锚点，durError = 测算 vs 披露 的偏差；percentValue = 当日 durEst 在查询区间内的分位。
  • 疑点：vol 是净值波动还是久期序列波动未说明；测算模型（对哪条利率曲线回归）未披露。

8. get_fund_bond_allocation_indicator ✅ 实测（110007，2024.01.01~2026.08.31）

  • 出参（实测）：avg（区间算术平均，reportDate 用哨兵值 9999.12.31）+ singles[]（各报告期）：
    • fundDuration：组合久期（年），仅年报/半年报有值（实测 2026.03.31、2025.09.30、2024.09.30 等季报期均 null）——基于利率敏感性分析测算；
    • fundLeverageLevel：杠杆水平 = 总资产/净资产（倍数，1.26）；每个报告期都有；
    • bondHoldingConcentration：债券持仓集中度 = 重仓债市值/债券总市值（小数 0.3336）；
    • top5BondDuration：前五大重仓标的久期（年，11.37）；
    • 排名：rankXXX（整数名次）+ totalCategoryFundDuration / totalCategoryOther（同类总数，久期与其他三项分母不同）。同类按招银基金分类（描述明示）。
  • 疑点：avg 为报告期算术平均（非时间加权）；排名方向（久期大=名次靠后？实测 rankFundDuration 633/668 且久期 6.07 偏长，疑升序但未证实）。

9. getAssetAllocation 〔仅 schema 盘点，未实测（配额）〕

  • 入参：startDate*/endDate*（yyyy.MM.dd）、fundCode、intervalType。
  • 出参：interval（区间汇总）+ quarters[]（各报告期）：五大类 equity/fixedIncome/fund/money/other 各出三个字段——xxxAsset（金额）、xxxAssetRatio（占总资产比）、xxxNetAssetRatio（占净资产比，仅 interval 层有）。
  • 口径：双分母（总值比 vs 净值比）并存，杠杆基金两者差异大；金额单位未标注（同组债券明细"已除以 1 亿"，此处疑为元或亿元，需实测确认）。

10. getBondAllocationType 〔仅 schema 盘点〕

  • 券种：bondNational(国债)/bondFinancial(金融债)/bondConvertible(可转债)/bondCorporate(企业债)/bondCentralBank(央票)/bondShortTerm(短融)/bondMediumTerm(中票)/bondAcd(同业存单)/bondLocalGovernment(地方政府债)/bondOther。
  • 三分母口径：totalAssetRatio（占总资产）/totalNetAssetRatio（占净资产）/bondAssetRatio（占债券市值），各有 Avg（区间均值）与 Single（每期）两组。

11. getBondAllocationStyle 〔仅 schema 盘点〕

  • 风格三分法：interestRateAsset（利率资产）/creditAsset（信用资产）/bondConvertible（可转债）；同样三分母 × Avg/Single 结构。
  • 疑点：利率/信用的划分规则（金融债归哪类）未披露。

12. getBondAllocationCreditRate 〔仅 schema 盘点〕

  • 按 longTerm/shortTerm 两评级体系分块 + single[]（各报告期 reports[]：longShortTerm、creditRating(AAA/AA+/A…)、bondType、三分母占比）。
  • 口径：评级来自重仓债披露（对应 detail 工具的 bondCreditRatingType），非全持仓——覆盖率受"重仓债"限制。

13. get_fund_bond_allocation_detail 〔仅 schema 盘点，描述极全〕

  • 每条：reportDate、bondCode、bondName、bondType（一级分类）、bondValue（市值，已除以 1 亿保留 2 位 = 亿元）、bondAssetRatio（占债券市值比，4 位小数如 0.1562=15.62%）、bondValueRatio（占基金净值比）、bondCreditRatingType（短期/长期/null）、bondCreditRating、bondCompanyCreditRating（主体评级）。
  • 返回全部历史报告期，需自行按 reportDate 分组。

14. getFundIndustryAllocation 〔仅 schema 盘点〕

  • industryType 枚举：ZHONGXIN1/2/3（中信一二三级）、SHENWAN1/2/3（申万）、YM（盈米分类）——行业分类体系可选，跨工具比较需锁定同一体系。containsHKStock 默认 false。positionStructure 必填（默认建议 semiannual）。
  • 出参：intervals[]（区间 avgValueRatio 平均占比）+ quarters[]（各期 valueRatio）。占比分母（净值/股票市值）未写明——疑点。

15. getHistoricalStockHolding 〔仅 schema 盘点〕

  • position：semiannual 全持仓 / quarter 重仓（默认 quarter）；industryClassCode 默认中信传 "21"（数字编码，与 industryType 枚举不同一套——口径疑点）。
  • 出参：三分母占比 netAssetRatio（占净值）/equityAssetRatio（占股票市值）/heavyPosAssetRatio（占重仓市值）+ 中信一二三级行业名 + industryChain（产业链标签）。

16. getFundNetAsset 〔仅 schema 盘点〕

  • report 日期为 yyyy-MM-dd（与净值类工具不同）。出参：times（规模变化倍数）、years（年数）、setupAsset/totalSetupAsset（成立时规模/总规模）、totalTimes、setupDate、netAssets[]（reportDate、totalNetAsset(合并规模)、netAsset(本份额规模)、totalShare、fundShare）。
  • 疑点：规模单位（元/亿元）未标注；total vs 非 total = 合并各份额 vs 单份额。

17. getFundHolderList 〔仅 schema 盘点〕

  • report 日期 yyyy-MM-dd。出参：instHoldingRatio（机构占比）/personalHoldingRatio（个人）/etfFeederHoldingRatio（联接基金）/professionalHoldingRatio（内部持有人）+ 对应 Holding 份额。占比量纲（小数/百分数）未实测。

18. get_fund_fee_detail_list 〔仅 schema 盘点〕

  • 出参：maxSubscribeFeeRatio（最大认购费率）/maxAllotFeeRatio（最大申购费率）/maxRedeemFeeRatio + detailList[]（feeType、feeValue、feeUnit——费率带单位字段，rangeFrom/rangeTo 金额或持有期分段 + contain 边界开闭标志）+ subscribeConfirmDays/redemConfirmDays/redemSettleDays（确认/到账天数）。
  • 口径：分段费率有显式开闭区间标志，feeUnit 决定 feeValue 是 % 还是元/笔。

19. get_fund_announcement_page 〔仅 schema 盘点〕

  • param 包装分页（pageNumber/pageSize/orders + param 业务体）。reportType 枚举 5 类；仅返回 PDF（服务端过滤 .PDF 结尾）；默认公告日期降序；无效 reportType 返回空。

20. searchFundCodeAndName ✅ 实测

  • 扁平入参：param*、pageNumber*、pageSize*。返回 list[]：fundMainCode/fundMainName（主代码，A/C 份额归主）+ fundCode/fundName。分页字段实测为 totalPage/totalRow（与 schema 写的 totalPages/totalRecords 不一致——文档滞后）。

疑点汇总

  1. 收益率量纲组内不统一：return_metrics 百分数 vs 其余小数——消费侧极易 100 倍错。
  2. 无风险利率无文档：由 sharpe/calmar/geomReturn 联立反推 ≈1.5%/年，基准（定存/国债）未披露；queryFundPerformance 的 rf 是否同一套未知。
  3. 年化因子未披露：vol/geomReturn 的 252 vs 365、√252 vs √250 无说明。
  4. "同类"分类体系多头：债类指标明示招银分类；getFundRankTrend 的 categoryLevel、queryFundPerformance 的 count 未写明体系是否同源。
  5. 净值复权口径：PerformanceComparison 明示"复权"；return_metrics/RankTrend 未明示（数值同源推断也是复权），分红再投假设未披露。
  6. indexCode 代码体系：需带后缀（示例 000300.CSI），合法后缀清单无文档；benchmarks.code 的指数是否同规则未证实（大写 type/裸代码时静默返回空而非报错）。
  7. 静默失败模式：getFundRankTrend 错误 freq、benchmark 错误 type/code 均返回空数组不报错——数据缺失与入参错误不可区分。
  8. calmar 非教科书定义：分子含 rf（=夏普分子），复用时勿与常规 Calmar（纯年化收益/最大回撤）混比。
  9. 金额单位：债券明细明示亿元；AssetAllocation/NetAsset 的金额单位未标注。
