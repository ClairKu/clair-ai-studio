00 / BOARD ANSWER

董事会先记住四句话

先把最重要的答案说人话

Harness 不是另一个模型，也不是简单工作流；它决定 AI 能不能在真实环境里持续、安全、可审计地完成任务。

核心决策一句话版本

短期买成熟生产力，中期自建控制面，长期保持模型和 Harness 可替换。

先雇成熟团队把活干起来，再把门禁、财务和质检握在自己手里。

Codex、Claude、Cursor、Copilot 更适合立即提升研发与交付效率；DeepSeek Harness、DeerFlow、OpenCode、Qwen Code 更适合学习、定制和构建自主底座。金融企业真正不可外包的是身份、授权、数据边界、审计和结果验收。

可以买现成的“项目团队”，但不能把公司钥匙、客户数据、付款权限和验收章一起交出去。谁来干活可以换，谁能看数据、谁能写系统、谁为结果负责必须由企业决定。

成熟度提醒：DeepSeek Harness 官方仍称 developer preview，明确表示接口可能变化；适合隔离试验，不应因“开源、可插拔”就直接等同于生产安全。[S1][S2]
① Harness 是“生产系统”模型决定上限，Harness 决定完成率、成本、风险和复用速度。
② 没有单一总冠军平台是不同取舍：一体化、可组合、云执行、开源兼容、长任务、业务编排。
③ 真壁垒在控制权企业控制面要凌驾于任何一个模型或厂商之上。
④ 评估要看结果证据“说完成了”不算完成；系统、页面、客户、交易的真实状态才算。
01 / PLAIN LANGUAGE

把 Harness 看成一家微型公司

六个生活类比，一次讲懂

一个能工作的 Agent，不只有“脑”，还需要制度、资源、边界和交付链。

🧠

模型 = 聪明员工

负责理解、判断和表达。模型再强，也不会天然知道公司规则、客户权限和完成标准。

🧭

Harness = 项目经理

把目标拆成步骤，决定下一步做什么、什么时候停、失败后如何恢复。

🧰

工具 / MCP = 手和电话

让 AI 查数据、改文件、调用业务系统。没有工具，它只能“提建议”，不能“办事情”。

🪪

权限策略 = 门禁与印章

决定谁能进哪间房、看哪些资料、是否能对外发送或提交交易。

🏭

沙箱 = 隔离车间

给 AI 一个能动手但不会伤到主系统的环境；发生错误时损失被限制在车间内。

✅

验收器 = 质检与回单

检查页面是否真的上线、订单是否真的成功、数字是否来自正确口径，而不是只听 AI 自报完成。

模型智力能不能想明白
＋
Harness 组织力能不能持续行动
＝
业务完成能力能否安全交付可用结果
1接任务识别目标与边界
2做计划拆步骤和预算
3用工具查数、写入、执行
4过门禁授权、审批、隔离
5验结果测试与外部状态
6留证据审计、恢复、复用

03 / SIX CAMPS

六大流派，没有一派包打天下

真正的选型单位不是“产品名”，而是架构路线与组织目标是否匹配。

像选车：跑长途、拉货、越野和市内通勤，不可能由同一辆车永远第一。

01全栈一体派

大脑、流程、工具一家公司

Codex · Claude Code · Gemini CLI

模型与 Harness 协同优化，成熟度和落地速度高，但供应商依赖更深。

像品牌连锁酒店：入住即用、服务统一，但装修和会员体系由总部决定。

＋ 快、稳、体验完整－ 锁定与议价压力
02插件积木派

每个部件都能换

DeepSeek Harness

Cordis、capability seam、事件日志提供极强组合性，适合 Harness 研发和行业预设。

像乐高工厂：发动机、车轮、驾驶室都能重组，但你也要自己承担装配和质检。

＋ 自由、透明、可研究－ 预览期、组合复杂
03云工位派

给每个 Agent 一台电脑

Cursor Cloud · GitHub Copilot

核心优势是云端隔离环境、并行和 Git/PR 成果链，适合规模化研发任务。

像外包团队每人有独立工位和门禁卡，干完提交成果、录像和验收单。

＋ 并行、证据、易推广－ 云成本、平台绑定
04开源兼容派

一个壳接多种模型

OpenCode · Qwen Code · Trae Agent

模型和协议自由度高，便于国产化与私有适配；安全、运维和产品完整度需自行补齐。

像组装电脑：零件选择多、价格透明，但兼容性、售后和安全要自己负责。

＋ 成本、自由、可私有－ 集成与治理负担
05长任务超代派

为小时级复合工作而生

DeerFlow · SuperAgent stacks

将记忆、文件系统、沙箱、Skills、子代理和消息渠道组合成完整长任务运行时。

像会自己组项目组的总包商：研究、写作、数据、设计分工，最后交一个成品。

＋ 复合任务、成果导向－ 链路长、故障面大
06业务编排派

把流程画出来交给业务

Dify · Coze Studio · 企业 Agent Builder

低代码工作流、知识库和发布能力强，适合确定性业务流程；不等于深度自主执行 Harness。

像流程审批系统：看得见、改得动、适合固定路线，但遇到开放式复杂任务不如专业项目经理。

＋ 可视、可运营、易普及－ 长任务与环境能力有限

07 / BUSINESS EXAMPLES

三个例子：有无 Harness，差在最后一公里

真正价值不是“写得更像”，而是减少跨系统手工、降低错误、留下责任和证据。

案例 A · 基金研究报告

从“生成文字”到“交付报告”

只有模型根据用户描述写一篇看似专业的分析，数字来源和截止日可能不清楚。
有 Harness授权取数→核对口径→计算→画图→合规检查→发布→验证线上地址。
验收对象：数据日期、公式、图表、来源、生产页面，而不是最后一段回答。
案例 B · 顾问客户服务

从“提供建议”到“受控服务”

只有模型生成千人一面的建议，可能看见不该看的客户信息。
有 Harness身份/用途校验→字段脱敏→调用 Skill→顾问复核→触达留痕。
企业壁垒：不是 Prompt，而是权限、顾问方法、业务数据和合规链。
案例 C · 软件缺陷修复

从“给代码片段”到“可合并变更”

只有模型输出一段可能能用的代码，让工程师自己找文件、测试和提交。
有 Harness读仓库→定位→修改→跑测试→浏览器验收→生成差异和 PR 证据。
生产力来源：把十几个动作连成闭环，并能失败恢复和并行。
08 / DECISION TREE

别问“谁最强”，先问“我们要什么”

从业务目标出发，答案会比横向堆参数清楚得多。

这次投资最重要的目标是什么？
目标 1

三个月内提升研发交付

优先：Codex / Claude / Cursor / Copilot

选择成熟产品，小范围量化任务成功率和人工节省；不要先自研内核。

目标 2

做自己的 Agent 产品

优先：Codex App Server / Claude SDK

快速产品化；同时把身份、数据、策略放在自己的控制面。

目标 3

国产化、多模型、深度定制

优先：DSH / DeerFlow / Qwen / OpenCode

先隔离试验再生产化，预留安全、评测和运维投入。

目标 4

让业务人员编排固定流程

优先：Dify / Coze / 企业工作流

适合可视化运营；复杂开放式任务另配执行型 Harness。

09 / PORTFOLIO & ROADMAP

建议 70 / 20 / 10，不做单点豪赌

既要今天产生结果，也要逐步形成自己的控制能力和未来选项。

70% · 成熟生产力在研发、研究、内容和运营中买成熟 Harness，直接验证业务结果。
20% · 企业控制面身份、授权、MCP 网关、审计、验收、成本和评测。
10% · 前沿试验DeepSeek Harness、DeerFlow、多代理和国产模型路由。
0–30 天

选三类任务做真实基线

固定任务、权限与验收器；记录成功率、时间、人工中断、成本和风险事件。

31–90 天

建立最小企业控制面

统一身份、工具目录、分级授权、审计事件和生产验收，不追求大而全。

3–12 个月

形成多 Harness 路由能力

按任务、风险、成本和地域选择执行引擎，持续用真实回放集评估替换。
