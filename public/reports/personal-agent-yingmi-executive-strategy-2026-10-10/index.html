01
EXECUTIVE VERDICT

这不是一个新聊天入口，而是一次客户关系重分配

当通用 Agent 开始掌握用户记忆、跨应用权限和支付凭证，搜索、推荐、比较、购买、售后会被压缩进同一条对话。谁代表用户做决定，谁就更接近客户关系的上游。

事实：来源可核验推断：基于事实推演建议：供管理层决策红线：需制度约束
判断 01 · 入口

通用 Agent 会截走“问题入口”

ChatGPT Apps、Gemini Personal Intelligence、千问、豆包手机助手都在把应用变成对话内能力。用户可能不再先打开金融 App，而是先问自己的 Agent。03050708

判断 02 · 价值

金融优势不在模型，而在责任闭环

通用 Agent 可以研究和比较，却不天然拥有持牌资质、适当性责任、账户服务能力和争议处置机制。“谁承担后果”比“谁回答更聪明”更难复制。

判断 03 · 窗口

协议窗口正在关闭

MCP、A2A、Agentic Commerce 已从概念进入大规模采用；能力如何被发现、调用、授权和计量正在固化。现在不把金融能力做成 Agent-ready，未来就只能做被动数据供应商。101112

判断 04 · 合规

新规把“外部获客”和“持牌服务”切得更清楚

2026 年 9 月 30 日生效的新规限制第三方平台介入适当性、销售合同、资金划转和金融产品互动咨询，并要求算法推荐可关闭。生态入口可以开放，受监管动作必须收回自营边界。14

判断 05 · 护城河

最值钱的是“个人金融上下文”

四笔钱、家庭目标、风险舒适区、账户持仓、服务历史、用户授权和顾问判断共同构成连续上下文。它不是一段聊天记忆，而是可校验、可授权、可删除的长期服务资产。

判断 06 · 战略

双入口、一个底座、四道闸

自营入口升级 AI 小顾为个人财富智能体；生态入口把 OAP / MCP / Skills 做成可信金融能力层；共用上下文与证据底座，通过身份授权、适当性合规、关键确认、审计回退四道闸。

一句话立场

不做“大而全”的通用 Personal Agent

把有限资源集中在财富管理的理解、责任和行动闭环。

对用户

从“随问随答”升级为“持续发现并推进财务任务”。

对生态

从“给接口”升级为“给可授权、可解释、可交付的金融能力”。

对组织

从“AI 项目”升级为业务 Owner 对结果负责的经营流程。

02
WHAT HAS CHANGED

六个变化，让 Personal Agent 从演示走向基础设施

单看模型能力会低估这轮变化。真正的跃迁发生在记忆、分发、协议、支付、硬件入口和安全控制同时成熟。

MEMORY从会话记忆到个人上下文

Gemini 可在用户选择开启后连接 Gmail、Photos、Search 等；OpenAI 也把对话、记忆与连接应用组合成主动更新。0405

PROACTIVE从等待提问到主动发现

Pulse 明确提出由 AI 先发起沟通；千问、Android 和手机 Agent 开始处理后台、多步骤与计划任务。040607

ACTION从建议到跨应用执行

ChatGPT Agent、豆包手机助手与 Qwen Intelligence 均采用工具 / API 优先、界面操作补位的执行形态。020708

PROTOCOL应用正在变成能力货架

MCP 连接 Agent 与工具 / 数据；A2A 连接 Agent 与 Agent。能力发现、授权、长任务状态和跨平台协作开始标准化。1011

TRANSACTION授权令牌进入交易链

OpenAI、Visa、Mastercard 都在为 Agent 支付设计“限定商户、金额、意图和确认”的凭证与协议。1213

CONTROL治理成为产品能力

豆包强调授权与全链路审计；OpenAI 承认提示注入无法只靠输入过滤，必须限制危险动作和数据外传。0815

关键推断：未来用户面对的不是“很多 App + 一个 AI 助手”，而是“一个代表自己的主 Agent + 一组被它调用的服务 Agent”。App 仍然存在，但越来越像可信能力、交付界面和责任主体。
03
WHERE YINGMI CAN WIN

盈米应争夺第三、四层，而不是复制第一层

大厂的优势是账户、操作系统、设备、流量和通用记忆；盈米的结构性优势是金融数据、投研投顾方法、账户服务、持牌责任与长期客户关系。两者不是同一场战争。

① 主 Agent / 系统入口

ChatGPT、Gemini、千问、豆包、鸿蒙小艺、QClaw：掌握用户时间、记忆、设备与通用任务。

大厂绝对优势
② 协议与分发层

MCP / A2A / Agentic Commerce / 手机服务协议：决定能力如何被发现、授权、路由和结算。

必须兼容与参与
③ 专业金融 Agent

理解用户目标、四笔钱、风险舒适区、家庭资产与行为偏差，主动推进长期财务任务。

盈米核心战场 A
④ 持牌行动与责任层

适当性、投顾服务、产品信息、交易承接、顾问复核、回访投诉、证据和审计。

盈米核心战场 B
⑤ 金融能力底座

基金与组合数据、VESTA / PMS、OAP / MCP、Skills、内容合规、账户与服务事件。

已有基础，需统一

最危险的误判

把 Personal Agent 理解成“做一个更聪明的小顾聊天框”。聊天更聪明只解决回答质量；真正决定客户关系的是持续上下文、触发权、行动权、证据和责任。

最值得放大的资产

盈米已经拥有金融 MCP / Skills、AI 小顾、账户与持仓服务、投研投顾系统和顾问工作台雏形。难点不是从零开发，而是把分散能力组织成同一条任务闭环。

真正的竞争对手

不是另一家基金销售 App，而是“代表用户选择与行动的上游 Agent”。如果盈米只输出数据，不输出带责任边界的能力，客户意图和价值判断将被入口层拿走。

04
THE STRATEGIC DESIGN

双入口、一个底座、四道闸

双入口不是两套产品。它们共享同一套个人金融上下文、专业能力、授权模型和证据链，只是在不同场域承担不同责任。

OWNED EXPERIENCE

且慢个人财富智能体

在自营场景持续理解目标与账户，主动发现变化，解释影响，生成行动方案，并把关键动作交给用户或顾问确认。

  • 从 AI 小顾“问答”升级为任务状态机
  • 围绕四笔钱、目标账户和长期陪伴
  • 保留顾问接管、服务回执和结果复盘
⇄
ECOSYSTEM DISTRIBUTION

盈米可信金融能力层

向千问、豆包、微信 / 鸿蒙和机构 Agent 提供结构化数据、解释、规划与受控行动能力，而不是让外部 Agent 自由拼接高风险业务。

  • Agent Card / MCP / A2A 可发现能力
  • 品牌、资质、来源和时点随结果返回
  • 受监管动作回到持牌自营场域完成

闸 4 · 证据、回退与申诉知道为何这么做、用了什么数据、失败后如何补偿。
05
SCENARIOS, NOT SLOGANS

先打穿三条任务闭环，不铺十个聊天机器人

三个场景都满足：高频或高价值、已有数据与工具、可度量、损失有上限、能体现买方投顾差异。第四条生态链路作为获客与能力分发同步验证。

“这笔钱该放哪？”从一次提问变成可持续计划

已有：四笔钱 / 规划 / 账户能力P0 旗舰场景
1. 触发

用户主动输入或授权识别到大额闲置、产品到期、收入变化。

2. 补全

询问时间目标、流动性、负债、风险舒适区与已有账户。

3. 规划

先分四笔钱和目标账户，再生成资金分配与备选方案。

4. 确认

展示假设、费用、风险、适当性结果和不同方案差异。

5. 持续

执行后记录目标、跟踪进度，在变化时再规划而非重复销售。

北极星指标完成规划并在 30 天内形成合适资金安排的用户比例；同时观察留存、复购与账户健康，而非只看对话量。
红线未完成 KYC / 适当性不得进入具体产品建议；外部 Agent 不得替用户完成销售、划款或适当性步骤。

“跌了怎么办？”从泛化安慰变成账户级行动

P0 旗舰场景反诱导 / 反追涨杀跌
1. 感知

市场波动超过阈值，并计算对用户真实持仓与目标的影响。

2. 解释

区分事实、历史区间、组合暴露、缺失数据与推断。

3. 判断

识别恐慌赎回、集中度、期限错配或现金流压力。

4. 分流

稳定用户给解释与观察；高风险 / 高情绪用户转人工顾问。

5. 复盘

记录用户决定、后续行为和结果，形成个体化陪伴策略。

北极星指标高波动期的任务闭环率、顾问首响时间、非理性赎回下降、解释证据覆盖率。
红线禁止借恐慌推销、不预测收益、不把短期或局部业绩包装成确定性建议。

“计划还有效吗？”从净值盯盘变成目标管理

P1 场景需要跨账户质量验证
1. 检测

目标期限、现金流、风险舒适区或资产配置发生实质偏离。

2. 归因

说明偏离来自市场、用户行为、数据缺失还是原方案假设变化。

3. 方案

给出“不动 / 调投入 / 调期限 / 调配置”等可比较选项。

4. 审批

AI 准备材料，用户与顾问决定，系统完成规则和适当性检查。

5. 留痕

生成新版本规划，旧版本与决策理由保留可回溯。

北极星指标目标偏离被及时识别的比例、方案采纳率、调整后目标达成概率改善和投诉率。
红线不得用“优化”名义制造频繁交易；缺少跨账户数据时必须显示证据缺口。

“在千问 / 豆包问理财”如何合规地回到盈米

P0 分发场景持牌边界清晰
1. 发现

主 Agent 通过 Agent Card / MCP 发现盈米的金融事实与规划能力。

2. 调用

返回结构化数据、来源、时点、资质、适用范围和拒答条件。

3. 解释

外部场域只完成中立事实、教育和一般性框架，不做变相销售。

4. 转接

需要个性化建议时，明确展示盈米 / 且慢身份并进入自营服务。

5. 归因

记录渠道、授权、任务阶段和转接结果，形成可审计经营漏斗。

北极星指标高意图问题的合格转接率、首次价值时间、授权完成率、任务闭环与长期资产净流入。
红线第三方平台不得介入互动咨询、适当性、合同和资金划转；品牌与责任主体不得混同。
06
AUTONOMY BOUNDARY

金融 Personal Agent 不是“越自动越先进”

正确目标是把低风险、可逆、可验证的动作自动化；把高风险、难逆转、涉及适当性和资金的动作送到明确的人类决策点。

L0

事实与教育

查询公开数据、解释概念、展示来源与时点。

可自动
L1

分析与准备

账户摘要、影响分析、方案草稿、待办与材料准备。

可自动 + 抽检
L2

建议与提交

个性化方案、顾问话术、再规划建议；必须过规则并由人确认。

受控放行
L3

持牌动作执行

在自营场域、明确授权与限额下，由用户 / 顾问确认后执行。

强确认 + 留痕
L4

全自主资金决策

AI 自主选择产品、完成适当性、划款或交易且无人确认。

当前禁止
新规 01

第三方平台必须停在技术服务边界

不得介入或变相介入销售合同、资金划转、适当性测评等环节，也不得就金融产品与消费者进行互动咨询。14

产品含义：外部主 Agent 可发现和转接盈米能力；个性化投顾与交易必须回到清晰标识的持牌自营场域。
新规 02

算法推荐必须允许拒绝与关闭

不得设置诱导过度消费的算法模型；使用个人特征推荐时，要同时提供不针对个人特征或便捷关闭的选项。14

产品含义：主动服务要有频控、解释、退订和非个性化模式，不能把“更懂你”变成持续营销。
新规 03

金融机构仍对营销内容负责

网络营销内容需要总部统筹、审批备案与合规审查；第三方不得擅自改变，相关材料需留档。14

产品含义：Agent 输出不能只做文本审核，要保存内容版本、来源、规则版本、调用链和审批结果。
新规 04

个人数据授权不等于无限代理权

合作平台提供客户信息与数据，需要客户授权并保障传输保密、完整；同时仍受个人信息保护要求约束。14

产品含义：授权应按能力、数据、场景、金额和期限拆分，支持查看、撤销、到期与删除，而不是一次勾选永久通行。

安全设计不是“装一个 AI 防火墙”

OpenAI 在 2026 年公开说明：真实提示注入更像社会工程，单靠识别恶意文本无法解决。金融 Agent 必须假设某次判断会被诱导，从系统上限制后果。15

最小权限默认只读；写入、对外发送、交易凭证逐项授权。
来源—动作隔离外部网页 / 邮件内容不得直接触发敏感动作。
确定性约束金额、产品、区域、适当性、频次由规则引擎硬限制。
可中断与补偿用户可暂停、接管；失败需回滚、补偿并通知。
07
90-DAY ATTACK PLAN

90 天不是交付一个“AI 小顾 4.0”，而是证明一条业务闭环

用真实任务、真实系统和真实责任验收。若不能形成可观察的用户结果和经营结果，就不算 Personal Agent 项目。

DAY 0–14

定战场、定边界、定样本

  • 董事会 / 管理层确认双入口战略与“不做通用 Agent”
  • 选择“资金新变化”“市场大波动”两条 P0 闭环
  • 建立不少于 100 条真实任务的评测集与红队样本
  • 确定业务 Owner、数据 Owner、合规 Owner 和技术 Owner
  • 完成第三方平台 / 自营场域的责任与数据边界图
退出条件每条流程有输入、动作、确认点、失败处理、结果证据与唯一负责人。
DAY 15–45

Shadow Mode 跑通闭环

  • Agent 在后台给建议，但不触达客户、不执行动作
  • 与顾问真实判断逐条对照，记录错因和证据缺口
  • 打通账户 / 事件 / 任务 / 报告 / 沟通回执主链
  • OAP 能力增加 Agent Card、来源、时点、风险与拒答
  • 完成权限分级、行为审计、回退与人工接管
退出条件高风险任务无越权；关键事实可追源；失败可定位；业务负责人确认可小流量试点。
DAY 46–90

小流量、真用户、真结果

  • 自愿授权用户 + 一线顾问联合试点，设置硬限额
  • 上线一个外部 Agent 的“中立能力 → 自营转接”链路
  • 每周复盘成功任务、失败任务、过度动作与用户投诉
  • 只扩展通过验收的能力，不按部门铺 Agent 数量
  • 形成下一季度场景复制模板和合规审查模板
退出条件业务结果显著改善且重大错误为 0；否则停止扩张，先修复底座。
用户结果任务闭环率不是回答完成，而是用户问题进入可验证状态。
经营结果净流入 / 留存按合格任务用户观察长期资金与服务价值。
服务质量一次成功率首次给出可用方案，减少返工、转人工与等待。
风险底线重大越权 = 0适当性、资金、营销、隐私和证据红线单列。
停止指标污染：不再用 Agent 数、Skill 数、调用量、Token 量、活跃账号或 Demo 数量替代业务成功。它们只能说明“被使用”，不能说明“替用户把事情办成且没有越权”。
08
DECISIONS REQUIRED TODAY

建议会议结束前拍板六件事

如果只形成“要重视、要加快、要协同”，这次会议就没有完成任务。以下六项可以直接成为会议决议底稿。

D01

战略定位：是否确认“双入口、一个底座”？

且慢个人财富智能体负责自营客户关系；OAP 负责生态分发；共用金融上下文、权限、能力和证据底座。

建议：确认
D02

主战场：是否明确“不做通用 Personal Agent”？

不和大厂争操作系统、全生活入口与通用模型，把资源集中到财富管理专业性、持牌责任和任务闭环。

建议：明确不做
D03

P0 场景：是否只选两条 90 天闭环？

建议“资金新变化 → 规划 → 承接”和“市场大波动 → 账户解释 → 顾问接管”；生态转接同步做最小链路。

建议：2 + 1
D04

自治边界：是否批准 L0–L4 动作分级？

L0 / L1 自动，L2 受控，L3 强确认且仅在持牌自营场域，L4 当前禁止。

建议：作为红线
D05

组织机制：谁为业务结果负责？

每条闭环只设一个业务 Owner；产品、AI 平台、数据、合规、投研、顾问 / 客服组成小队，按周复盘真实失败。

建议：BU Owner 负责
D06

验收口径：是否停止按调用量和 Agent 数验收？

用任务闭环率、一次成功率、用户行为改善、净流入 / 留存、人工接管、越权与重大错误验收。

建议：经营 + 风险双指标
质疑：大厂都会做，我们做了也没用。

大厂会控制入口，但它们不会自动获得基金投顾资质、账户服务责任、长期投顾 SOP 和争议处置能力。

回答：不与大厂同层竞争；把大厂入口变成盈米能力的分发渠道，同时守住自营责任层。

质疑：先把所有平台都接上，抢速度。

没有统一的授权、来源、拒答、品牌和持牌转接边界，接得越多，经营价值越散、风险越难收回。

回答：先定义“能力合同”，再复制渠道；以一条真闭环验证，不以平台数量庆功。

质疑：让 Agent 自动交易才算真正先进。

金融价值不是自治率最大化。自动化越接近资金与适当性，错误成本、法律责任和提示注入风险越高。

回答：先进性体现在主动发现、完整准备和把任务推到正确的人类决策点，而不是取消人类责任。
