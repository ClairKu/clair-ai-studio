盈米内部公募基金数据能力盘点
面向「封装对外 MCP」的可行性评估 · 截至 2026-08-24

调研方法：图谱定位（finance-api / ias / bmdj / fdp）→ 本地源码下钻（FDP 81 个 mapper、bmdj fund-data MCP controller）→ 生产 dw-tidb 实测（表存在性 / 行数 / 历史深度 / 更新新鲜度）→ Stargate 注册表核实（ying99_oap 公开库 + ying99_oap_internal 内部库）。全部结论有真实库表或代码证据，非名称推断。数据查询走 redash 兜底（prod-db-query 未灰度）。

〇、执行摘要

总体判断：盈米内部已具备一条覆盖「公告事件 / 基金经理 / 持有人 / 历史持仓 / ETF 日频」的完整公募基金数据底座，主体是 FDP 数据平台（dw-tidb ying99_fdp 库，81 张 ads/dwd/dim 表，上游为恒生聚源采购数据），经 finance-api（REST+GraphQL，数智团队）与 ias/coral/juniper（蜂鸟 ITS 投研）双通道对外供数。其中 15 个基金数据工具已经通过 Stargate（qieman.com/mcp）对 外暴露且日均真实调用。六大类中 4 类「已有可直接封装」，2 类「部分已有需补齐」；ETF 实时行情与基金公司股东信息「未找到可靠证据 / 不宜对外」。
三个必须写进需求文档的口径事实：① 持有人结构/单一持有人是定期报告披露口径（年报/中报，半年一更），不是实时数据；② 历史持仓是定期报告持仓（季报前十大+半年报全量），非全时点真实持仓；③ ETF 资金流是交易所成交按单笔规模拆估的估算口径，且仅覆盖 2022-04 之后。

四、权限 / 采购 / 牌照 / 个人信息 / 行情授权限制

限制类型事实与影响
数据采购授权（最核心）FDP 库上游 = 恒生聚源（tws-api 节点 evidence 明证「FDP=聚源」；公司另采购 Wind、通联）。聚源数据授权通常按「内部使用」计费，封装为对外 MCP（尤其商业输出给第三方）需与供应商重新谈判授权范围，否则构成转售违约风险。建议对外工具优先：① 监管公开披露数据的重整（公告标题/类型/日期导航）；② 盈米自研加工指标（明确标注口径）。
行情授权ETF 实时行情（交易所 Level-1/2）受交易所信息服务授权约束，内部未发现有授权落表证据 → 不建议、也不具备条件封装实时行情 MCP；IOPV/估算净值类（自算）可内部用，对外需法务评估。
个人信息基金经理 resume/学历/照片为自然人信息（公开披露来源）；对外封装建议字段级开关，默认不带 head_img，resume 摘要化。
基金销售牌照边界盈米持有基金销售牌照；对外数据工具若叠加「推荐/评级」表述（如经理评分、公司能力分）可能触及投顾/销售适当性边界，建议对外仅提供描述性数据，评分类标注「盈米内部研究口径、不构成投资建议」。
现有授权机制可复用Stargate 已具备 api_key + OpenChannel（OAuth 对外渠道）+ 调用留痕（api_key_usage_details）+ 后台审计（api_operation_audit）+ 用户增长看板（dw-tidb ying99_oap 库），新 MCP 无需重建鉴权体系。
