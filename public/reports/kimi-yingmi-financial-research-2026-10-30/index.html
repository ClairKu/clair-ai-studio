THE THESIS
先给判断

Kimi 没有天然的“非合作不可”。盈米最有力的筹码是一个现有流程中的实质增量，或一项具备负责人、验收与采购路径的获准需求。

01

机构多，先分清他们在提供什么

客户、数据商和共建方，解决的是不同问题。客户数量不等于 Kimi 已获得这些机构的全部业务能力；但已有供给确实抬高了盈米加入的门槛。[1][2]

角色公开举例已经满足什么盈米因此不能怎样讲
模型 / 产品客户易方达将 K3 接入 EWork；汇添富与创投机构评价其研究用途专业客户使用模型或研究工具“缺金融机构客户，所以找我们”；也不能把客户等同于业务服务授权方
数据插件供给方Wind、东方财富、iFinD、S&P 等专业数据和金融取数已有多来源“再接一些基金资料和净值，就形成战略价值”
业务方案共建方中信建投的网关与临时受托报告试点机构准入、受控调用与人工复核有具体实践“你们没有合规能力，我们来补齐”

上述为对官方角色的归纳，不对合同金额、当前活跃程度或排他关系作推断。普通基金比较应降为兼容性演示；除非实测发现已有工具链的具体缺口，否则它不足以支撑新增合作方。

纠正旧版：Kimi 当前发布页明确披露中信建投首轮覆盖 50 余家发行人、100 余只存续债券、60 余份报告，不能写“未披露样本量”。这些是厂商披露的单场景验证，仍不等于独立审计或跨场景普遍效果。[1]

02

Kimi 的特点，决定该找谁、卖什么

对盈米有用的特点，是 Kimi 当前把金融工作包装成可交付的专业产品：已有金融技能、专业数据、可编辑成果，以及 Work 和托管运行载体。切入点可以嵌进这些已有产品。它们都不是排他功能。[2][3][4]

产品公开可见的侧重点对盈米谈法的影响（研究判断）
Kimi金融技能与数据组合；Work 操作文件、浏览器和持续任务；机构受控运行找金融产品 / 插件负责人，谈现有工作流的具体增量；找行业销售，谈获准机构项目。先不索要全站流量。[2][3]
千问品牌智能体、服务发现、账号及经营 / 履约能力更适合围绕用户发现和品牌服务承接组织提案；不能把其入口条件直接套到 Kimi。[10]
豆包 / 豆包工作已有盈米基金分析接入和使用路径的合作方披露“国内 Agent 调基金工具、出分析报告”已有先例。对 Kimi 应带可迁移成品和具体需求，缩短接入成本。[11]
Claude已发布 Financial Advisors；连接组合、CRM 等系统并组织顾问任务顾问服务和金融工作流也有直接对照，不能只靠“更懂金融”区分。[12]
ChatGPT Work插件与外部能力、文件和受控执行；官方有可编辑财务工作簿用例MCP、工具调用、Excel 交付是共性。盈米应证明国内具体业务环节可运行、有人维护。[13]
对 Kimi 的合适角色：
一个能插入现有产品、持续维护的专业部件提供方，或共同完成一单的交付伙伴。
03

重排优先级：两项主切口，一项备选

P1 / 先做可运行部件

金融产物的业务内容检查

用现有 regtech 后端，检查公募 / 投顾客户沟通材料；Kimi 保留生成与修订体验，人工负责复核。

P2 / 有需求才推进

一个获准机构项目

带需求负责人、验收人和采购路径，让对方判断值得投入售前资源。当前尚未证明这笔需求存在。

P3 / 只补实测缺口

基金计算与口径部件

只处理现有组合复盘 / 早报中的失败点；不再新建同类 Agent，也不许诺完整账户现金流归因。

基础基金资料、普通基金比较、通用研报 / PPT、持仓早报和“我们有 MCP”均不作为首谈主卖点。Kimi 已有相邻产品，是否还需新供给取决于同题结果。基金计算也不能凭接口名称或数据来源声称独家优势。

04

把合作具体到输入、部件与输出

优先验证 / 已有后端，需 Kimi 适配

研究或客户沟通稿 → 业务规则检查 → 修订 → 人工复核

Kimi 已有生成内容核验和风险网关。这里限定为公募 / 投顾内容中的业务规则检查，衡量它能否减少正式审核的漏项和返工；不宣称补上全部合规。[1][6]

输入
一份合成客户陪伴稿及引用数据，包含区间不可比、收益暗示、风险提示不匹配或来源口径缺失等待核点。先用可公开样例；真实材料另行获准。
当前可用
盈米公开客户端支持策略选择、文本（≤10000字）或 PDF / DOCX（≤10MB）提交、任务轮询和风险原因 / 修改建议展示。服务依赖 regtech 后端及鉴权。客户端开源不等于后端引擎和规则库开源。[5]
需适配
封装 Kimi 插件；HTML / PPT 先提取文本或转格式，不能承诺原格式无损。基于返回原句定位，补超时 / 失败提示；页码、字符位置、法规引用、规则版本和原文件批注回写均未由公开客户端证实。修订、复查与前后差异保留仍需适配，尚未验证 Kimi 端效果。
输出
初稿、逐项风险原因与建议、修订稿、仍待人工判断的事项。业务审核人员复核后进入原流程；不自动签发或对客发送。
对方得到
为现有金融文档、HTML 和客户沟通成果增加一个可审阅步骤，减少机构用户手工补查。若同题比较没有改善，这个理由就不成立。
找谁 / 换什么
找金融技能 / 插件产品负责人；先要一个测试入口和一名审阅人。盈米承担可安装包、接口适配和样例说明，暂不要求推荐位或战略签约。
第二主切口 / 先核实获准需求

一个明确机构任务 → 联合需求评审 → 有边界的一单

盈米公开 TAMP 有机构工作流程与系统对接基础；这不证明某客户愿意采购 Kimi 或联合方案。当前为建议，尚未带来已确认商机。[6][7]

输入
一份获准对外讨论的需求单：业务负责人、现有步骤与耗时证据、允许数据、系统边界、验收人、预算或采购路径、期望日期。没有这些，就先做需求访谈。
当前可用
Kimi 的 Work / Hosted、文档交付与机构运行能力；盈米公开的业务接口和内容审查服务。各项能力的实际权限、版本与许可仍须确认。[3][6]
需适配
共同限定一个“组合复盘材料 → 客户陪伴初稿 → 业务检查 → 人工确认”任务；列清系统接口、数据传输、责任人和交付费用。暂不加入交易或自动发送。
输出
一页双方认可的任务范围、报价 / 采购步骤、验收标准、接口清单与时间表。客户确认的试用不等于订单，订单也不等于已回款。
对方得到
可进入采购过程的需求，以及盈米承担的垂直业务适配；对 Kimi 行业销售，比覆盖机构数或泛渠道承诺更容易评估价值。
找谁 / 换什么
找金融行业销售 / 方案负责人，请其参加一次三方需求评审并指定一个售前联系人。需求不成立、客户不授权或交付成本不可接受，就不立联合项目。
备选 / 必须先见到失败任务

在已有组合技能里，只补一个可复算的计算点

盈米公开有基金归因、债基指标、策略持仓及交易规则类工具；接口名单不证明优于 Kimi 已有数据源。[8]

输入
由对方提供一个获准的现有失败任务；如基金归因口径、持仓披露时点或份额识别确实出现错误。先给标准答案与可复算依据。
适配与输出
只对该点调用盈米工具，输出数值、数据时点、公式 / 口径、缺失与异常说明，回到 Kimi 原来的复盘 / 早报流程。
成立条件
同样模型与输入下，现有工具链仍有可确认问题，盈米部件确实修复且成本可接受。现有数据商已稳定完成，或盈米端点不能完整支持，就放弃。
不作承诺
不由基金级归因工具推导完整账户资金流归因；不把任何第三方指标称为盈米独家。具体生产接口、许可和计算责任另核验。

接入动作可以先行：按 Kimi 官方流程，先在 Work 创建并测试个人插件，再从详情页的反馈入口选择“申请发布到官方市场”。无需先谈战略签约；审核、上架、推荐位和商业安排分别确认。[4]

最有说服力的证据：同一输入、同一模型、两种条件的实际结果；并让负责使用成果的人指出哪一步少了返工。图示、工具数和伙伴 Logo 都替代不了这份证据。

05

先准备六个样例，再谈十个工作日

不用先承诺一组漂亮百分比。会前准备六份合成材料：三份故意有误、一份信息不足、两份用途与误报对照。明显的收益保证仅作基础检查，不用于证明盈米优于模型自审。真正的增量须在获准的复杂业务材料上验证，不能只挑对盈米有利的题。下列是验证设计，尚未执行。

查看 / 下载合成挑战样例包合成输入与人工预期检查点；非法定结论，未在 Kimi 或盈米后端运行
DAY 01–02

确认真实问题

双方挑选样例和正常稿；机构审阅人先标注待查点。固定模型、输入、既有工具及任务要求。

盈米：材料与当前能力证据
Kimi：一名产品联系人
DAY 03–05

完成受限适配

盈米给可安装插件与失败处理；对方确认测试端、账号权限和一次任务入口。外发材料逐项确认。

共同产物：可运行测试链
暂不承诺市场上架
DAY 06–08

同题两条件比较

运行现有 Kimi 流程和加入盈米后的流程；盲审漏报、误报、修改时间，记录失败和直接成本。

审阅人：业务使用者
不让实现者单独判优
DAY 09–10

明确继续或停止

有真实改善才定产品化范围、负责人和付费路径；没有改善、没有审阅资源或没有需求，就停止定制。

共同产物：差异与决定
没有预设达标结论
记录项怎样记录避免误判
漏报 / 误报每个预标问题是否检出；正常稿和合格句是否误伤；逐项保留人工判断不以“改写很多”当专业，不用样例通过声称生产零错误
修订时间相同稿件由初稿到人工可接受版本所需时间，包括核验、修改与复查不只量模型生成时长；六例只验证可行性
运行与成本失败、超时、重试、工具费用和支持工时完整列出不把接口通了等同于可持续交付
业务采用审阅人是否愿意放进原有流程；需要谁维护、谁付费没有采用意愿时，不用调用量包装成功

十个工作日是拟议期限，由双方同意后才开始；不表示现有项目已承诺资源。阈值应由真实任务的风险和价值共同确定，本报告不先编成功率、节省比例或收入目标。

06

十五分钟，只争取下一步具体资源

  1. 00–02 分

    承认对方已有覆盖直接说明选定的现有金融产物与拟补环节，不演示净值查询和普通基金比较。

  2. 02–07 分

    用两份样例展示差异一份有预标问题、一份正常稿。若尚未运行，明确展示的是预期检查点与适配方案，不能把手工标注冒充模型或接口结果。

  3. 07–11 分

    让对方确认痛点与使用者问哪一类机构用户会用、现有流程是否仍需补查。对方已有成熟方案，就请其给一个实际失败点；给不出来则降低优先级。

  4. 11–15 分

    定三个最小请求一名金融产品 / 插件联系人；一个可获准运行的测试入口；一名有权判断材料可用的审阅人及复核日期。机构项目另由销售参加三方需求评审。

OPENING / 可复制的建议开场
你们现有的数据、研究和文档能力已经很完整。我们想先验证一个小环节：Kimi 做完基金客户沟通材料后，调用盈米现有的业务内容检查服务，标出需要人工复核的问题，再由 Kimi 修订。盈米负责可安装部件、接口适配和规则维护。我们带六份合成样例，与你们当前流程做同题比较；若没有减少漏项或人工返工，就不追加定制。现在希望确认一位产品联系人、一个测试入口和一名业务审阅人。

以上是会谈建议稿，未发送。若当前后端权限、规则维护资源或六份样例尚未准备好，应先补齐，再使用其中的交付承诺。

07

对方拒绝时，怎样回应才有分量

“我们已经有 Wind，也能分析基金。”

“基础数据和普通比较确实重叠，我们不要求替换。先看业务内容检查是否减少人工返工；如果你们现有流程已经做好，这个方向就不推进。”

“我们已经有合规网关和人工复核。”

“我们看到你们已有权限、数据和输出核验。想验证的是公募 / 投顾客户沟通材料中的具体业务规则。请用你们的正常稿与历史问题稿比较；没有改善，就保留原流程。”

“你们的 Skill 已经开源，为什么要合作？”

“公开仓库提供客户端和调用流程，服务依赖后端。是否需要合作，要看策略适配、审核质量、维护和成本；若你们已有同等能力，也无需重复采购。”

“先免费接进来，之后看量。”

“可以讨论有期限、额度和支持范围的验证。先确认使用者与判断标准；试完决定产品化或结束，避免接口接通后长期没有人采用。”

“金融合作已经很多，没精力做。”

“我们先完成可安装部件和样例说明，不要求你们做新产品。只请确认是否存在这类用户需求；若当前没有需求或负责人，我们暂缓，不继续做定制。”

先把一个部件做成可运行、可比较的东西。
若能带来一笔获准需求，再谈联合交付；入口分发与战略签约排在证据之后。
08
