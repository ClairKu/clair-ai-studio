盈米及且慢养老金业务分析

从规模、策略、产品、产品系统、用户与账户六个维度，拆解养老金业务从政策入口走向目标账户化经营的机会。

一句话结论

1
不只是个养开户
养老金业务应从销售入口升级为长期目标账户服务。
2
真正大盘在存量账户
已有养老/退休意图的 UMA 是更大的经营底盘。
3
适合作为投顾 2.0 样板
天然串联规划、配置、执行、跟踪与陪伴。
01 / CORE VIEW

核心判断：从政策账户到目标账户经营

个人养老金账户是入口，长期养老目标账户才是业务经营主场。
主判断

养老金业务不是“开户 + 买基金”，而是一套账户、规划、投顾策略、产品系统与投后陪伴能力。

且慢已有用户在账户命名和资产用途里表达养老需求，业务的关键不是等待政策流量，而是识别这批存量意图，把用户纳入规划、账户升级、策略执行和长期陪伴闭环。

入口层

政策与产品供给扩容

个人养老金全国推开，Y 份额基金、指数基金、国债、养老保险等产品供给继续丰富。

服务层

且慢从专区走向养老投顾

从投教、测算、产品货架，升级到养老规划建议书、养老金计划、账户资产管理。

平台层

盈米沉淀基础设施

PMS、TP、啟明/TAMP 支撑下滑曲线、目标日期组合、交易、账户、审核与 B 端复用。

03 / BUSINESS MAP

业务全景：三层能力共同承载

平台侧提供基础设施，且慢侧完成用户服务，啟明/TAMP 负责能力复用与商户输出。

盈米平台侧

养老财富管理基础设施，支撑账户、交易、策略、组合、审核与数据。

  • PMS / TP / 交易系统
  • 下滑曲线与目标日期组合
  • 个养账户、养老 UMA、协议与收费
  • 投顾审核、调仓、留痕

且慢 C 端 / 投顾侧

承载用户体验，从养老认知到计划、执行和长期陪伴。

  • 养老专区、投教、测算
  • 养老规划建议书
  • 且慢养老金计划
  • 养老资产、储蓄进度、账户分析

啟明 / TAMP / B 端侧

将养老账户、目标规划、交易与数据能力输出给商户。

  • 个人养老金账户产品方案
  • 目标投资规划组件
  • 多账户资产展示与拆分
  • H5 / API / 组件化接入
04 / STRATEGY

策略与投研：下滑曲线是养老金计划的底层纪律

养老策略的核心不是短期收益表达，而是长期风险预算和自动调仓纪律。
生命周期投资

随年龄调降权益风险

下滑曲线根据退休年龄和当前年龄，给出不同阶段的高风险资产比例，使组合风险随退休日期临近逐步下降。

实现方式

纯股 + 纯债基础组合

且慢与研究院用一个纯股组合和一个纯债组合，通过不同比例拼出不同年龄对应的目标日期组合。

用户表达

看到的是“养老金计划”

用户不需要理解底层组合和曲线参数，只需要知道资金被纳入一个长期养老账户与自动调仓策略。

治理要求

投委会、审核、留痕

曲线创建、标准比例调整、运营过会、目标日期组合变更都需要在 PMS 中留痕和审核。

策略规则口径

风险等级：R3 按下滑曲线建议买入 默认自动调仓 研究院发起基础组合调仓 年度年龄下滑 持有期阶梯费率设想 权益占比采用基金类型近似口径
05 / PRODUCT

产品演进：从专区货架到“我的养老金中枢”

2022 到 2024 的主线，是从投教测算逐步走向账户化、规划化、投顾化。
2022

养老专区 1.0

投教、富达测算、养老产品、养老账户与资产管理上线，建立用户侧入口。

2023 H1

账户关联与 1+1+1

个人养老金账户、且慢补充养老金账户、养老保险账户形成组合账户框架。

2023 H2

养老专区 2.0

引入养老投顾策略、养老金计划、下滑曲线、养老规划建议书和自动调仓。

2024+

投顾 2.0 样板

与账户诊断、月度报告、AI 小顾、家庭规划衔接，走向长期陪伴服务。

06 / SYSTEM

产品系统：用户想看一个“我的养老金”，系统要治理多种账户

养老金业务复杂度主要来自账户语义、交易规则、策略治理与数据展示口径。
投教触达解释养老目标、政策、长期投资。
养老测算形成退休缺口与月储蓄建议。
规划生成确认储蓄、权益比例和目标金额。
产品匹配个养产品、投顾策略、保险组合。
账户创建个养、补充养老金、保险账户。
交易执行买入、定投、协议、收费。
投后管理资产、进度、收益风险、调仓。
长期陪伴报告、诊断、AI 小顾、顾问触达。

账户语义治理

政策账户 个人养老金资金账户 且慢养老金账户 养老保险账户 目标账户 普通 UMA 升级

后台能力依赖

UMA / 账户体系 TP / 交易系统 PMS / 组合管理 操作审核 数据服务 啟明 / TAMP
07 / USER

用户与账户：关键是把养老意图转成服务关系

用户已经表达目标，但需要产品系统把目标识别、承接并长期经营。
用户类型 典型特征 关键动作
政策敏感型 关注税优、个养开户、缴存上限。 个养账户开通、Y 份额基金推荐、税优解释。
养老焦虑型 不知道退休要多少钱，也不知道每月该存多少。 测算工具、养老规划建议书、月储蓄计划。
已有目标账户型 已创建养老/退休相关 UMA。 账户升级、资产纳入养老管理、投后诊断。
长期投资型 有定投、组合、投顾经验。 且慢养老金计划、自动调仓、长期费率激励。
高净值 / 家庭规划型 需要综合家庭资产、保险、教育和养老安排。 家庭规划、账户诊断、AI 小顾与顾问协同。
08 / RISKS

核心瓶颈：不是有没有产品，而是链路能否跑通

养老金是低频、长期、强解释业务，断点会出现在理解、计划、交易和陪伴之间。

个养账户活跃度有限

税优是入口，但用户缴存、购买和长期持有动力仍需经营。

规划链路长

用户从投教到测算、从计划到买入，中间容易出现流失。

概念理解成本高

个养、养老 FOF、下滑曲线、权益比例、补充账户都需要用户语言重写。

系统口径复杂

账户、产品、策略、资金限制、交易规则和费用规则必须统一表达。

投后陪伴不足

养老金价值在持续储蓄、再平衡、波动解释和目标进度反馈。

策略信任需要时间

下滑曲线必须通过规则透明、长期数据和可理解解释建立信任。

09 / ACTIONS

建议：把养老金做成投顾 2.0 的样板工程

短期补数据，中期重路径，长期沉淀可复用的平台能力。
短期

补齐业务数据看板

先统一账户、资产、漏斗和策略口径。

  • 个养开户、缴存、交易、AUM
  • 补充养老金账户用户数与 AUM
  • 潜在 UMA 池转化率
  • 测算到买入漏斗
中期

重构主路径

把专区浏览改为计划驱动。

  • 养老测算
  • 计划确认
  • 账户结构建议
  • 产品/策略执行
中期

强化账户语义治理

让账户能被产品、顾问、客服和 AI 一致理解。

  • 是否养老账户
  • 是否个养
  • 是否纳入养老总资产
  • 是否可用于规划建议
长期

平台化输出养老能力

沉淀为 B 端可复用的养老投顾基础设施。

  • 目标规划组件
  • 下滑曲线策略引擎
  • 账户与资产聚合
  • 投后报告与陪伴
