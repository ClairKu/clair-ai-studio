01 / EXECUTIVE TAKE

它填补的不是“聊天机器人”空白，而是 Agent 之间的组织空白

模型解决“一个 Agent 能做什么”；Raft 解决“很多人和很多 Agent 怎么成为一支队伍”。

研究判断：它是协作层，不是模型层、MCP 层或确定性工作流引擎。

核心创新：Agent 是一等成员，不是被人类临时调用的工具。它拥有持久身份、独立工作空间、频道成员关系和个人记忆。

协调机制：消息可以变成任务；任务只有一个 owner；Agent 先 claim 再开工，完成后进入 review，减少重复劳动和不可见执行。

真正壁垒：不是 UI，而是“身份 × 消息 × 任务状态 × 本地执行 × 长期记忆”组成的协议，以及把不同 runtime 接入同一协作语义。

1→N

从个人助手到团队

支持多个 Agent、多个模型、多个电脑同时工作，并在共享线程中交接与评审。

2

双平面架构

Raft 云端保存协作消息与控制状态；Agent 在本地 Computer 上读文件、运行命令、调用模型。

0.1

Agent 计费系数

Pro 年付口径：每个人 1 seat，每个 Agent 0.1 seat；模型订阅与 API 成本另算。

02 / ARCHITECTURE

云端管“谁和谁协作”，本地管“Agent 真正做事”

重要边界：官网“本地执行”不等于全部数据不出境。频道消息、附件、身份与协作状态仍由 Raft 云端承载；runtime 还会直接连接各自模型供应商。
STEP 01人类给目标在频道发消息或直接创建任务，说明验收标准。
STEP 02Agent 认领一个任务同时只有一个 owner，避免重复开工。
STEP 03本地执行读取 workspace、运行命令、调用自带模型订阅。
STEP 04并行与交接Agent @mention 另一 Agent、拆子任务、在 thread 留痕。
STEP 05人类评审状态进入 in review，人类拍板后 done。
03 / PRODUCT

能力地图：真正独特的是协作原语，而不是模型数量

持久 Agent 身份

名称、描述、频道成员、工作空间与记忆跨 session 保留；runtime 可切换但身份不丢。

任务抢占与状态机

Todo → In progress → In review → Done/Closed，Agent 自动 claim，执行过程沉淀在线程。

异构 Runtime

官方列出 Claude Code、Codex CLI、Cursor CLI、Gemini CLI、Copilot CLI、Kimi CLI、OpenCode、Pi 等。

长期工作空间

每个 Agent 一套独立目录，可放记忆、脚本、草稿和仓库；目前绑定单台电脑，不支持跨电脑迁移。

Reminders

Agent 可自己设置一次性或循环唤醒；触发记录在对应频道/线程，适合可观察的周期任务。

Joint Channels

最多连接 3 个 Raft server；只共享指定私有频道，跨组织 Agent 也能协作，但目前没有联合任务板。

Connected Apps

通过 Login with Raft 让人和 Agent 以各自身份访问应用。安装是人类授权边界，token 按 Agent × App × Server 隔离。

外部 Agent

Hermes、Claude Code 或任何能运行 CLI 的框架都可接入；外部 Agent 功能标注为 Experimental。

免费试用门槛低

Free 含任务、Agent reminders、基础 observability、30 天消息与每月 100MB 上传；Enterprise 仍 Coming soon。

￥

一个 5 人 + 20 Agent 团队的 Raft 软件费约为 US$61.60/月（年付标价）

5×1 seat + 20×0.1 seat = 7 seats；7×US$8.80。模型订阅/API、云 VM、联网工具、MCP 服务与人工审核成本均另算。Agent 多起来后，真正的大头很可能是 token 与治理，而不是 Raft 席位费。

五个不能忽略的红线

  • 条款：用户 Contributions 可被视为非保密，并授予平台极其广泛、永久、可转授权的使用许可。
  • 出境：隐私政策明确服务器位于美国，数据可能由托管、数据库、对象存储和 AI 推理供应商处理。
  • 治理：私有部署、SSO、高级访问控制仍在 Enterprise “Coming soon”。
  • 执行面：本地服务可启动 Agent、读写文件、运行命令；权限设大后，风险半径就是整台机器。
  • 保障：条款是 as-is / as-available，平台可变更、暂停或终止，未看到 SLA、SOC 2/ISO 证据或企业 DPA。
数据/动作可否进入当前 Raft 公有版本理由

05 / MARKET MAP

Raft 不是 Slack 替代品，也不是 Codex 替代品：它位于两者之间

路线核心对象强项弱项与 Raft 的关系
飞书 / Slack / Teams + Bot人类组织与聊天企业治理、组织目录、审批、合规生态Agent 通常是插件；身份、长期记忆、任务抢占不是原生语义Raft 是“Agent-first IM”；现阶段企业能力反而弱很多
Codex / Claude Code / Cursor单个执行 Agent代码、文件、终端、工具执行深多人/多 Agent 的共享任务与交接不是核心是 Raft 的 runtime，而非替代关系
CrewAI / AutoGen / LangGraph开发者定义的多 Agent 工作流图编排、确定性控制、测试与部署对普通团队不够自然；人类对话与组织记忆偏弱Raft 偏“社会协调”，框架偏“程序编排”
YingmiWork / WorkBuddy / OpenClaw个人数字员工与技能运行本地能力、企业技能、MCP、个人任务闭环跨人、跨 Agent 的团队协同尚非主轴可被 Raft 式协作层包裹；也可在现有 IM 内吸收其原语
Raft人 + Agent 的混合团队身份、频道、任务、claim、review、记忆、本地执行统一治理、合规、SLA、私有化、生态仍早期新类别：Agent-native collaboration layer
06 / PRODUCT IMPLICATION

对盈米/且慢最有价值的不是“部署 Raft”，而是抄走它的协作协议

01

Agent 必须有可治理身份

名称只是 UI。真正需要的是 owner、角色、授权范围、运行时、预算、数据域、审计记录和生命周期。

02

对话必须能变成承诺

消息 → 任务 → 唯一 owner → 评审 → 完成。没有状态机的人机群聊，只会产生更热闹的聊天。

03

记忆必须有边界

不要建“全公司一个大脑”。每个 Agent 保留自己的专业记忆，通过消息传递；共享空间保留可审计决策。

04

人与 Agent 使用同一权限模型

每个 Agent 以自身身份访问 MCP/应用，禁止借用人类 token；安装/授权由人类管理员完成并可撤销。

05

审查者应与执行者分离

投研、内容合规、合同检查要把“写的人”和“验的人”分开，避免同一模型既生成又自证正确。

06

先嵌入现有 IM，再谈替换

盈米更优路线是让企业微信/飞书获得 Agent 成员、任务 claim、review gate 与 MCP 身份，而不是另起一套无治理 IM。

◎

北极星指标不应是“人机消息数”

建议看：跨 Agent 任务完成率、从请求到 in-review 的时长、重复开工率、人类介入次数、证据缺失率、评审驳回率、越权/敏感数据事件、单位完成任务总成本。消息越多，可能只是协调越差。

07 / ACTION PLAN

7 日隔离试点：验证协作增益，不验证“能不能聊”

Day 0｜隔离

  • 单独 macOS 用户或云 VM
  • 不挂载内部目录
  • 不配置生产 MCP/token
  • 只允许公开互联网资料

Day 1–2｜组队

  • Research：搜集一手证据
  • Analyst：归纳与对比
  • Reviewer：查错与反证
  • Publisher：生成交付物

Day 3–5｜跑任务

  • 3 个公开竞品调研
  • 1 个跨 Agent 交接任务
  • 1 个 reminder 周期任务
  • 记录 token、时长、返工

Day 6–7｜复盘

  • 是否减少手工转述
  • 是否减少重复工作
  • 评审是否真能发现错误
  • 本地权限是否可控

进入企业评估前必须书面确认的 10 个 Gate

数据处理协议 DPA明确处理者、子处理者、数据用途、责任与通知机制。
数据驻留与跨境是否支持中国区/指定区域，消息、附件、日志分别在哪。
训练与二次使用承诺客户内容不用于训练、广告、产品改进或人工审阅的合同保证。
内容权利条款修订企业私有内容保持保密与归属，不接受现有广泛永久许可。
SSO / SCIM / RBAC组织目录、离职回收、细粒度角色与最小权限。
审计与导出消息、任务、Agent、工具调用、文件访问、审批可查可导。
安全认证与渗透测试SOC 2 Type II / ISO 27001、漏洞管理与应急响应证据。
私有部署与网络边界控制平面、对象存储、日志与模型出口都可放入企业边界。
保留、删除与备份消息、附件、workspace、凭据、备份的可验证删除时限。
SLA 与退出预案可用性、恢复、数据导出、停服与供应商退出保障。
✓

Go / No-Go 标准

继续：相对单 Agent 流程，任务周期缩短 ≥25%，重复开工率 <5%，Reviewer 至少发现 2 个实质问题，且无敏感数据/权限事件。停止：Agent 互相“水群”导致 token 显著上升、同模型共识制造虚假确定性、上下文泄漏、权限边界不可验证，或最终仍需人类手工搬运所有信息。
