IDENTITY ≠ PLATFORM

身份渠道和客户端平台，必须分层

OAP 现在更擅长记录“从哪条身份通道授权”，不擅长记录“用户在哪个 AI 客户端发起”。

A

已注册 OAuth 客户端

能直接证明客户端来源

B

OpenChannel 身份通道

能证明产品/身份路由，不等于平台

不要误用：platform_type = 0008 是且慢 broker 代码，不是千问、豆包或 WorkBuddy 的平台来源。把它当渠道字段，会让几乎所有申请都被误归到同一“平台”。

FIX THE MEASUREMENT

补一层归因，下一版才能真正数用户

不需要重做全链路。把平台身份从“Key 名字里的文字”升级为服务端的标准字段即可。

P0 · 立即

建客户端登记表

每个 OAuth client / API Key 必须绑定 client_surface、client_family、auth_mode，历史 Key 批量回填。

P0 · 本周

在调用明细落来源

把不可变的 client_surface_id 写入 usage details；不要只信 User-Agent 或自由文本 Header。

P1 · 两周

打通用户与调用

OAuth 场景记录匿名 subject；共享 Key 场景至少记录平台侧匿名用户或会话，形成“平台→用户→调用”链。

客户端平台→授权主体→服务端 Client ID→API Key / Token→成功调用
