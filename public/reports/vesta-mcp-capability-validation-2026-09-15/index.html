Defects & contracts

一个确认缺陷
七类契约摩擦

失败不是都归咎于调用方。复测先纠正入参，再判断是 schema 描述问题、后端业务边界，还是网关序列化缺陷。

P1 · index__searchIndexByCodes 无法正确传递数组参数

按 schema 使用 indexCodes 数组，分别以单元素与双元素重试，均被上游判定为“缺少 indexCodes”。相邻指数接口正常，故更像 MCP 网关到 HTTP 查询参数的数组序列化桥接问题。

合法输入：{"indexCodes":["000300","000905"]}
稳定返回：HTTP 400 / Required request parameter 'indexCodes' … is not present
CONTRACT 01

条件必填未进入 required

收益分布需 target_return；调仓复盘需 trade_date 或 after_adj_duration；市场阶段工具另有隐藏组合条件。

CONTRACT 02

命名风格不统一

组合实时工具多数使用 snake_case，但产品详情改用 prodCode / prodType；调用代理容易产生首轮 400。

CONTRACT 03

枚举与示例不足

行业分类、持仓周期、定投频率等字段需要特定枚举或联动参数，schema 没有完整暴露可接受值。

CONTRACT 04

错误语义可再统一

不存在的组合可能返回 400、404、422 或空数组；客户端难以统一分辨“参数错、无数据、对象不存在”。

CONTRACT 05

Mock 能力必须显式隔离

实时组合拟合工具描述仍带 Mock 属性。接口返回成功只能证明链路，不等于数据已具备生产可信度。

CONTRACT 06–07

客户端挂载与私募域缺口

当前 Codex 会话未原生挂载 VESTA；在线清单仍未出现 private-fund 服务域，需分别处理接入和授权。
