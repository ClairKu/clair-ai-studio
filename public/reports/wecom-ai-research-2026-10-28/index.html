02优先测试投入：较低

官方 wecom-cli / MCP：优先打通在线文档与微盘

可读范围 · 有权限的文档正文 / 表格 / 微盘文件

扫码授权后，让支持终端工具或相应封装的 Agent 搜文档，再按 docid 读正文。文档搜索支持标题、正文或二者；普通微盘文件可下载到本地后解析。长正文可能返回 file_path，需要继续读取文件。

适合：想让 Codex、Claude、Cursor 一类 Agent 真正使用在线资料，而不是只给企微推通知。

04 / 把宣传词翻译成事实

这些“已经接通”，需要再追问一句

“这个 MCP 支持历史消息”

它查的是企微原始历史，还是自己上线后收发过的记录？

Webhook MCP 可能只保留发送记录；回调 MCP 则可能只搜索接入后保存的 SQLite。atttx123 的历史工具依赖回调和持久化；loonghao 的底层主要是出站 Webhook。

atttx123/wecom-mcp-server ↗ · loonghao/wecom-bot-mcp-server ↗ · 传统群机器人 Webhook ↗

“有文档列表，AI 就能读文档”

拿到的是标题、URL、搜索片段，还是实际正文？

在线文档、智能表格、普通微盘文件要分别处理。下载 URL 也不等于解析成功；长文 file_path 要继续读取，PDF 扫描件要验证 OCR，表格要保留行列含义。

官方文档正文 Skill ↗ · 官方微盘 Skill ↗

“本地运行，数据就不会外发”

数据获取在本地，与模型推理在本地，是两个问题。

本机检索工具本身不上传，也可能被上层 Agent 把结果交给云模型。评估时明确模型去向、返回内容与日志范围。只读 CLI 也可能附加客户端进程，不能省略兼容和干扰测试。

BobbyCats/wecom-local ↗ · WeCom Agent 本地读取文档 ↗

“升级 / 换插件 / 开存档就能补齐”

权限限制、拉取窗口、本地缺失，分别需要不同答案。

853006 目前有官方策略限制证据；会话存档拉取窗口是 5 天，微信客服是 3 天；本地解析只能处理已有缓存。三种缺口都不会因为换一个模型自动消失。

另外别混淆：个人微信 iLink / 微信机器人、个人腾讯文档、公众号 MCP 与企业微信，是不同的数据域和授权体系。第三方平台上的文章，也不等于腾讯官方能力承诺。
05 / 推荐顺序（研究者建议）

个人先取到可用资料，企业再补长期管道

先试原生搜索与指定来源总结

用一个你记得答案的真实问题测试：能否找到来源、准确引用、限定聊天或文档。低成本确定现成产品能解决多少。

外部 Agent 优先验收官方 CLI 的文档和微盘

分别做“搜标题”“搜正文”“读完整正文”“下载一个普通附件”。记录成功与失败，不因为 chat 返回受限就放弃其他可用能力。

保留本地附件索引，补齐文档来源与版本

已有附件与导出文本可以先用起来。在线最新版本与离线旧版本分别标记；从文件命中推进到正文证据，并明确哪些文件没有缓存。

只有历史聊天缺口确实重要，再评估专门路线

个人历史先核官方 chat 当前权限；仍不可用时，把 Runtime/离线解库作为隔离环境候选。企业长期需求则确认会话存档或专区的开通与持续同步方案。

我的判断：最值得优先投入的是“官方文档 / 微盘 + 本地已有附件索引”的组合。它可以先扩大 AI 可用资料范围。若核心诉求是跨群多年聊天复盘，真正需要补的是历史数据覆盖与来源证据；单换 MCP、工作流平台或大模型解决不了这件事。
06 / 怎么证明真的可用

用四个小测试，拆穿“只接上了壳”

A / 正文找一份已知文档，问标题以外、正文深处才有的事实；答案附原文片段和文档位置。
B / 历史指定一个已知会话和日期，返回消息时间、正文、来源；区分原生历史与机器人自行保存的上下文。
C / 附件从消息或微盘命中 → 下载 → 解析 → 核对一页/一表；把缺缓存、格式失败、权限失败分开记录。
D / 权限与更新用无权资料测试拒绝；改一处文档再查；撤销权限后，检索结果也应按所设计规则失效。

上述为建议验收方案，本次任务仅网上研究与静态核查，未登录、安装、开通、同步或监听用户企微。

交给任何 AI 的只读验收任务

验证当前企业微信连接的读取能力。先列出实际可用工具与授权范围。
用我指定的一份文档、一个会话日期和一个附件做小样本：
1. 文档返回正文证据与来源；标题/链接/片段命中要分别标注。
2. 聊天返回实际消息时间与正文；注明来源是原始历史还是自身回调库。
3. 附件核对下载、正文解析、缺失与版本状态。
遇到无权限、853006、灰度未开或客户端不兼容，记录原始错误并继续其余测试。
不发送消息，不自动回复，不修改文档或客户端，不提取或输出密钥。
最后给能力矩阵和缺口清单，不把工具名称或示例输出当作成功证据。

官方 CLI 的 4 条只读命令形状

供已经完成官方安装与授权的环境参考；本次没有执行。先检索，再把结果里的真实 ID 填入后续命令。下载会在本地保存副本。

wecom-cli doc search --json '{"keywords":["季度汇报"],"search_scope":"title_content","sort_by":"best_match","limit":10}'

wecom-cli doc contents get --json '{"docid":"<真实文档ID>","content_type":"markdown"}'

wecom-cli disk files search --json '{"keywords":["季度汇报"],"file_types":["offline_pdf"],"limit":10}'

wecom-cli disk files download --json '{"file_id":"<真实文件ID>"}'

文档正文可能以 content 或本地 file_path 返回。微盘下载仅用于 type=file 的普通文件；在线文档按其类型使用正文工具。占位符不能原样执行。
