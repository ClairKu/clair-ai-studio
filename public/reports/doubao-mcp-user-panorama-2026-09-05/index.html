01

接入方式：传统 Key 与 OAuth 的口径边界

豆包接入盈米 MCP 有两条通路，但两条通路在数据上可见度完全不同——这决定了本报告每一节能回答什么、不能回答什么。

通路机制可归因性规模（8-28 以来）
OAuth 授权 豆包个人版 MCP 广场一键授权。预注册客户端 doubao（2026-08-28 建），回调地址为豆包 personal 通道，挂在「官方渠道」OpenChannel 下，经且慢账号（IdP）登录授权。 完全可归因：授权记录、绑定账号、令牌活跃全部落库。 336 人 / 469 次授权
传统 API Key 用户在开放平台自助申请 Key，手工粘贴进豆包办公 / 其他任意客户端。 不可归因：申请表无平台字段（platform_type 恒为 0008=且慢），调用明细不落 User-Agent，一把 Key 可在任何客户端使用。 全平台新增 1,087 把
豆包份额未知
「豆包办公」没有独立标识

OAuth 侧只有一个 doubao 客户端且回调为个人版通道；豆包办公用户若经传统 Key 接入则混入全平台申请中无法拆分。同期全平台日新增 Key（58–200 把/日）相比 8 月中旬无豆包上架相关的显著跳升，说明传统 Key 侧未见可观测的豆包增量。本报告的用户级分析均基于 OAuth 绑定的 336 人。

授权链路疑似「双重授权」：59% 的重复授权发生在 60 秒内

469 次授权中 133 次被后续授权替代（superseded），其中 78 次（59%）间隔 ≤60 秒、117 次 ≤1 小时；1 名用户累计授权 12 次。60 秒内的连续二次授权更像豆包侧回调重试 / 双击触发，而非用户主动重绑，建议排查 OAuth 流程幂等性。

用户行为分析

豆包 OAuth 调用不落工具级明细（见 §07），行为分析采用会话令牌（refresh token 签发）作为活跃代理：一次签发 ≈ 一次使用会话。共 2,307 次会话，98% 绑定用户至少用过一次。

怎么读这些曲线

  • 日活持续爬坡：从上架次日 29 人升至 9-04 的 167 人，增速快于绑定增速——老用户在回访，不只是新用户在试。
  • 办公时段主导：9:00–17:00 占 62%（午休 12 点有明显凹口），晚间 20–21 点有第二峰。豆包里的理财对话更像「上班摸鱼查基金」而非睡前理财。
  • 近半用户只来一天（160 人，48.6%），但 98 人（29.8%）活跃 ≥3 天、42 人 ≥5 天；首周绑定用户的次周回访率 41.7%，对一个纯查询入口来说不低。

07

提问清单：为什么给不出，缺口在哪

用户在豆包里的原始提问，任何一层都拿不到

① 协议层：MCP 协议只把「工具调用 + 参数」传给盈米，用户输入的自然语言提问永远留在豆包侧，不出字节的服务器。

② 计量层：豆包 OAuth 通道的调用连工具级明细都不落库——api_key_usage_details 里没有任何豆包聚合 Key 或按授权记账的行（对照：千问渠道有「阿里云千问-通用问答」聚合 Key，9 日 198 万次调用可查）。

③ 参数层：即使是传统 Key 的调用，明细表也只存 route_id + request_id + 时间，不存入参。搜索关键词等「准提问」只存在于 stargate 网关的运行日志（SLS），需工程侧在保留期内提取。

三条建议
  • 补 OAuth 计量（最优先）：为 OpenChannel 流量按 consent_record 记账写入用量明细，与千问聚合 Key 拉齐。否则豆包、以及同通道的小顾 3.0，工具调用量、热门工具、人均调用全部是盲区。
  • SLS 侧做「准提问」抽取：对 SearchFunds / SearchFinancialNews / StrategySearchByKeyword 等带 query 入参的路由，把关键词脱敏后回流数仓，可还原 70% 的用户意图。
  • 排查授权双发：59% 的重复授权发生在 60 秒内（§02），修复后授权数据才能当真实「绑定意愿」看。
08

口径与已知局限

  • 豆包 OAuth 客户端 client_id=doubao 建于 2026-08-28 17:32，首次用户授权 19:17，本报告以此为「上架」时点；9-05 数据为截至约 21:00 的不完整日。取数期间用户仍在实时绑定（约 21:10 已达 338 人），各表之间可能有 ±2 的时点差。
  • 「绑定用户」= ying99_oap.api_user_consent_record 去重 user_id；user_id 即且慢用户 ID（经 account.broker_user_id, broker='0008' 与账户体系打通）。
  • 「活跃」为 refresh token 签发代理口径，豆包客户端令牌轮换节奏未知，人均会话次数不可与其他产品横比；日活跃用户数口径可靠。
  • 「绑定后新增入金」= ROOT 层累计投入（acc_input_amount）最新快照 − 8-27 基线，含既有定投扣款，不能全部归因豆包；「零资产激活 9 户」为 8-27 基线无资产记录且现累计投入 >0，含清仓后再入金，不等于人生首投（首投口径见姊妹看板，绑定后为 0）。
  • 287 名无基金账户的绑定者是否为「因豆包新注册的且慢账号」在本数据源（Redash 41）不可判定——passport 注册库不在其中；工作台姊妹看板《豆包 × 且慢｜绑定用户数据看板》经另一数据通道给出拆分：绑定时新注册 194 人、绑定前已有且慢账号 147 人（21:43 时点，341 人口径）。
  • 豆包办公与豆包个人版共用或不用 OAuth 无从区分；传统 Key 无客户端归因（详见 §01）。
  • 盈米本体（ontology）登录已过期，SLS 日志留存时长等需登录后追问确认。
