# Skill 受控进化规则

1. 每次任务保存人工修改前后的差异、采用理由和任务类型。
2. 相同修改模式累计出现后，只生成“优化候选”，不得直接改写 Skill。
3. 候选版本必须通过历史成功案例、边界案例和失败案例的回归测试。
4. Clair 查看差异与测试结果后，选择发布、继续修改或放弃。
5. 发布使用语义化版本号，并保留上一版本和一键回滚入口。
6. 原始材料、人工意见与评审结果不可因版本升级被覆盖。

页面状态流：

`草稿 → AI 初稿 → 人工修改 → 再分析 → 人工确认 → 成果区`

Skill 进化流：

`人工差异 → 优化候选 → 回归测试 → 人工批准 → 新版本`
