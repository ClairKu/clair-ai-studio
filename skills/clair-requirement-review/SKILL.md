# Clair 需求评审

版本：1.0.0

## 工作流

1. 读取全部材料，建立材料清单；区分事实、推断与缺失信息。
2. 复述目标、用户、场景与成功标准。材料冲突时先列冲突，不替用户选择。
3. 逐项评审：需求价值、用户问题、范围边界、流程规则、异常状态、数据口径、埋点、合规与验收标准。
4. 给出 `可进入研发`、`补齐后再评审` 或 `不建议推进`，并说明置信度。
5. 生成可直接替换的规则、文案或验收条件。
6. 停在人工确认：允许补充材料、修改判断或要求重做。未经明确确认不得进入成果区。

## 输出要求

遵循 [references/output-contract.md](references/output-contract.md)。P0/P1 问题必须指向材料证据或明确标注“材料缺失”，不要用泛泛建议代替具体修改。

## 边界

- 不编造用户数据、业务规则、研发排期或合规结论。
- 原型与 PRD 不一致时分别记录，不擅自认定哪份为准。
- 金融交易、适当性或隐私问题必须列出需业务、合规或法务确认的责任人。

## 质量门

运行 `python scripts/validate_output.py <result.json>`，通过后才提交人工评审。
