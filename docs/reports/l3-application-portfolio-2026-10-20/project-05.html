背景与立项判断

功能上线后，交易规则往往分散在PRD、Wiki和培训材料。一次写完培训文档无法保证后续同步，旧答案仍可能被客服和业务引用。项目应承接“变更发生到知识可用”的完整作业，而非泛化为一个聊天知识库。

C · 拟建闭环与人工边界

首期作业边界

仅处理已批准、已生效或有明确生效时间的产品规则，首期内部只读知识与培训交付；不自主创造交易规则，不替用户确认协议或提交交易，不把员工培训评分用于人事决策。

01 / 拟建步骤批准发布事件触发
02 / 拟建步骤校验权威来源与生效时间
03 / 拟建步骤计算差异并检查冲突
04 / 拟建步骤更新同源知识与培训包
05 / 拟建步骤重建索引并抽题检索验证
06 / 拟建步骤通知订阅角色并记录回执
常规：证据齐全 → 按规则直接交付异常：缺证 / 冲突 / 超时 / 越权 → 保留状态、转责任队列

最终交给谁、完成是什么

客服、业务和运营收到变更摘要、适用版本、入口路径、已批准规则原文引用、异常处理方式与培训题包，能在原知识入口检索到。旧规则明确失效期或保留历史，不能无痕覆盖。

规则与判断依据

来源优先级、生效日、适用客群和版本关系需成文；新旧规则冲突时暂停发布。金额和费率必须逐字段引用批准数据，不由模型推断。检索测试问题独立编制；新规则命中、旧规则降权或失效提示、权限隔离都通过才算交付。

停止 / 收窄 / 降级条件

缺少权威来源、无法辨识生效版本或关键检索错误未消除时，禁止自动写正式知识；不为追求承接率跳过专业规则批准。

验收口径与准入闸门

真实计量单位

一个产品版本或规则变更单，必须完成适用知识更新、旧版标识、索引刷新和交付回执；文档文件生成不等于知识可用。

专项指标

关键规则准确率；旧版本误命中；更新时间；净人工时

当前不可声明已达标。负责人、真实SOP、基线、权限与持续运行证据仍待补齐。

自动交付比例＝无人工介入且达到冻结交付标准的有效任务数 ÷ 全部准入有效任务数。失败、转人工和超时不得从分母删掉；必经逐单审批计为人工介入。客户自主确认是必要步骤，应如实计量，不以“异常”名义排除。

净人工时包括资料整理、规则维护、复核、异常、返工与运维；构建投入单列。独立盲测与同口径人工基线比较，不只让生成模型自评。建议目标先审批冻结，实绩未知时显示待测。
