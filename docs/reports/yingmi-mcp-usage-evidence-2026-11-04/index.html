06 / EVIDENCE & CHECKS

证据、复核与尚未补齐的部分。

  • D-01｜明细统一计数与加总校验

    采用公域Key、内网Key的工具成功落账记录，OAuth MCP success=1明细及Vesta direct status=success原始日志。逐区间验证总数＝内部＋外部＋待归属，逐月合计与累计一致；统计表仅作对账。

  • D-02｜1条历史差异已定位

    公域Key日聚合24,423,719，明细24,423,720，多出的1条在2025年5月、归属待确认。本报告一致使用明细；近30日和其他月份两者一致。

  • D-03｜OAuth不能混用两个口径

    OAuth全部明细47,812条，剔除HTTP179条；MCP请求47,633条中，主表仅取成功43,233条，失败4,400条留在请求补充表。日聚合38,445未用于主表；logical call标识被跨请求复用，未据此全局去重。 源码已确认：日聚合按“日／平台／账户”组内折叠客户端调用ID，成功明细43,233条被折叠4,788条得到38,445；多个会话复用ID会少计，因此申报采用成功明细。

  • D-04｜已核对记录重叠

    公域与内网Key按凭据＋路由＋请求标识重叠为0；OAuth与Key按路由＋请求标识重叠为0。Vesta stargate转发层不追加，小顾专用客户端子集不追加。这不等于跨系统业务任务去重。

  • D-05｜内外归属保守处理

    内部按明确公司组织／自有系统的凭据和客户端归属；外部按已命名合作平台专用凭据及已识别第三方OAuth客户端。自报机构或个人未完成核验的留待归属。不是按工作空间直接判内外，也不是最终投资者归属。

  • D-06｜成功率与价值未外推

    主表已按各系统记录的工具／网关成功定义过滤；这不证明数据内容正确、投资结果或业务办理成功。Key历史日志没有协议字段，仍不能声称全部纯MCP。数据含开发、验证等用途，不由调用量推断成交或收入。

  • D-07｜全部公司服务覆盖仍有缺口

    已查9个工作空间、85个分组，但目录与计量范围不能等同完整资产盘点。小顾知识库及其他独立部署服务尚无完整独立调用统计，未将缺失填零。

  • D-08｜月度峰值方法

    先将可加总来源在同一自然月的记录相加，再在截至2026年10月的完整月中取最大值。2026年11月仅含1—3日；OAuth历史未采集区间是缺失，不是零。
