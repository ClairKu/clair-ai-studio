版本：v1.0 · 2026-08-31 · 调研人：辜腾玉（guty）+ 本体问答服务 对象：盈米MCP（生产实现 = AI 平台 stargate，本地代码 ~/Code/ai/stargate，master 分支最新提交 78a70eb，2026-08-28） 数据来源三轨：① 公司 WIKI（Confluence，wiki.frontnode.net）；② 生产注册表 dw-tidb ying99_oap（经 prod-db-query skill 实查，含 api_route / api_source / api_service_group / api_key_usage_details / api_external_market_tool_pricing / api_open_channel）；③ 上游微服务源码（pmdj-service / bmdj / pomodel / yingchat-api 等，均本地最新 master）。 先说结论（最重要的三条）：

  1. WIKI 没有任何一篇文档系统记载盈米MCP各接口的出参指标口径。WIKI 上只有 PRD/方案/使用教程类文档（共 12 篇相关），真正的“出参指标 SSOT”是stargate 生产库 api_route.openapi_operation_content（冻结快照）+ 各上游服务源码。

  3. 计费口径已在 2026-07-31 变更但文档未更新：文档《MCP积分资源包配置说明》写免费1/T1=3分(20个)/T2=5分(34个)/T3=9分(14个)，生产定价表已全部改为 T0=1分×64个（另 5 个工具未配价），分级体系实际已换轨。

1.3 出参链路架构（口径归因的基础）

MCP 客户端 → stargate /mcp/* (SSE/StreamableHTTP)
  → apiKey 鉴权 → 限流(1000/min+1000/天) → 日额度检查
  → tools/list: 从 api_route.openapi_operation_content(冻结快照) 动态生成工具 schema
  → tools/call: ①有 wrapper_function(20个路由) → VM沙箱执行JS改写 → axios 调上游
               ②无 wrapper → 直接 axios 调上游(base_url+remote_path, 经 api_search/replace 改写)
  → 响应: toon白名单(env MCP_TOON_ENCRYPT_OPERATION_IDS) ? toon编码 : JSON.stringify
  → 计费: shouldRecordMcpUsage() 仅成功才记账 → Redis list → 定时落 api_key_usage_details/stats

出处：~/Code/ai/stargate/src/mcp/initMcpPlugins.ts（mcpToolHandler）、src/mcp/getOpenApiRoutes.ts、src/modules/openai/OpenAIDao.ts（路由 SQL）、src/services/wrapperFunctionService.ts（VM 沙箱）。

二、逐接口逐指标口径明细

说明：完整覆盖 4,386 个工具不现实也无价值（大量是 vesta-reef/tws-api 等内部系统批量导入的管理接口）。本节按业务价值与调用量优先，对上述 12 个业务域的核心工具逐指标展开；每组末尾给出该组其余工具的口径要点与出处。每条指标的字段：指标名/出参字段 → 数据源 → 计算公式 → 口径说明 → 迭代历程 → WIKI与代码差异结论。

2.1 GetAccountHierarchyProfit（用户账户分层收益）— 调用最频的用户数据工具

上游：pmdj GET /v2/internal/user/account-hierarchy-profit（stargate 注册：source=pmdj，base_url=http://nginx.qieman/pmdj，远端路径同本地）。实现：`~/Code/qieman/pmdj-service/server/handlers/internal-v2/user/service/account-hierarchy-profit.service.ts`。

指标 口径
profit / 累计收益（元） 数据源：asset3 服务 GET /serviceAccount/query/intervalAsset/account/profitDetail（pmdj server/models/asset/index.ts:729 doGetUserAccountProfit）。公式：asset3 返回原值透传（asset3 只读不算，计算引擎是 asset4 离线批，读 ying99_asset.dwd_* 数仓表）。口径：ROOT→UMA→CA/Wallet 三层，每层单独调 profitDetail 汇聚。迭代：2026-05-16 首次注册进 MCP（api_route.created_at），2026-05-29 复制到 pmdj-xg3（小顾3.0渠道）。差异结论：WIKI 零记载；schema 的 description 里写了“收益数据来源：doGetUserAccountProfit（asset3 服务的 profitDetail 接口）”——这是唯一的口径出处，且藏在 schema 注释里。
profitRate / 累计收益率（MWR） 数据源：同上 asset3 profitDetail。公式：Modified Dietz 修正迪茨法（同文件 drawdown service 注释：MWR=(期末资产-期初资产-净现金流)/(期初资产+加权现金流)，加权现金流=Σcost−Σ(cost×dayIndex)/(currentDay+1)）。口径：schema description 明确标注"累计收益率（MWR）"。差异结论：MWR 这一算法定义只存在于代码注释与 schema description，WIKI 完全没有——外部客户问“你们的收益率怎么算”时无文档可依。
xirrAnnualizedRate / XIRR 年化 数据源：asset3 profitDetail。公式：asset3 返回值透传。口径：仅 dateType=all 时返回，custom 区间强制 null（service 319 行：dateType === 'all' ? data.xirrAnnualizedRate : null）。差异结论：“仅投资以来才有 XIRR”是重要业务口径，只写在代码里；schema 有注明（"仅 dateType=all 时返回"），WIKI 无。
holdingDays / 持有天数 asset3 透传。差异结论：同上，WIKI 缺失。
wallet（UMA内盈米宝收益） 公式：合并后无法提供 profitRate/xirr，仅返回 profit（service 346-350 行硬编码 null）。差异结论：口径限制未在 WIKI 记载。
benchmark.returnRate / 基准涨跌幅 数据源：pmdj doGetIndexReturnHistory（server/handlers/utils/index.history.js）。公式：区间首尾净值变化率；indexCode 别名映射表硬编码在 service（hs300/csi500=000905.SH/csi800=000906.SH/spxgi=SPX.GI/hsihi=HSI.HI 等）。口径：0.05 表示 +5%。差异结论：别名映射表是代码级配置，WIKI 无。

2.2 GetAccountHierarchyDrawdown（用户持仓最大回撤）

上游：pmdj GET /v2/internal/user/account-hierarchy-drawdown。实现：account-hierarchy-drawdown.service.ts。

指标 口径
maxDrawdown / 最大回撤 数据源：asset3 GET /serviceAccount/query/...profitRateCurve（doGetAssetProfitRateCurveBasicData）。公式（代码 87-97 行，全文档最明确的公式之一）：先逐日算 Modified Dietz 累计收益率序列 mwr = (totalAsset − Σcost − initAsset)/(initAsset + wt)（wt=sumCost−sumCostMultiDays/(currentDay+1)，保留4位）；再 drawdown=(HWM−rate)/(1+HWM)，HWM=历史最高累计收益率；maxDrawdown=−max(drawdown)，返回负值。口径：清仓日沿用前一日收益率；参考 romeo 前端 getMaxDrawdownRanges。迭代：2026-05-16 注册。差异结论：公式完整存在于源码+注释，WIKI 零记载；schema description 只说“负值，如 -0.15 表示回撤 15%”。

2.7 GetLatestQuotations（市场温度计）— 出参公式最完整的工具

上游：pmdj GET /v2/internal/market/quotations/latest。实现：market-quotations.service.ts + models/smartdq/market-temperature.ts。

指标 口径
temperature / 市场温度（0-100，2位小数） 数据源：smartdq GET /market-temperature-by-date（pmdj 恒传 time_range='10y' + FIVE_LEVEL）→ 底层 ying99_dp.market_temperature 表（离线批 commons-processor pybin3/ProcessMarketTemperature.py L114-121 生产）。公式：temperature = (pe_rank + pb_rank + risk_rank) × 100/3，各因子=近10年窗口内 pandas rank(method='min', pct=True) 百分位。base 指标：pe_median/pb_median=当日成分股（聚源 LC_IndexComponentsWeight 月度快照）PE(TTM)/PB(LF) 中位数；risk_premium_rate=10Y国债收益率−1/PE×100。⚠️ 风险溢价是正向入温度（值大→温度高），与常规 ERP 方向相反——疑似原设计笔误，未与 owner 确认。差异结论：WIKI 完全没有温度公式；公式只存在于离线 Python 代码注释，是本次梳理中“公式最复杂但文档最空白”的典型。
rating / 温度等级 五档：≤20=L低估 / ≤40=ML较低估 / ≤60=M合理 / ≤80=MH较高估 / >80=H高估（pmdj FIVE_LEVEL_RATING_TEXT + smartdq 双处实现一致，QMRD-36074）。差异结论：仅代码与 schema。
temperatureList 范围 硬编码仅三大指数：000985中证全A / 000300沪深300 / 000905中证500（SUPPORTED_TEMPERATURE_INDEX_CODES）。差异结论：WIKI 缺。
marketInterpretationsByCategory / 行情解读 数据源：finance-api doBatchGetIndexPriceDailyFromFinance → FDP 数仓 ying99_fdp.dwd_index_price_daily 直返零计算。五指数：000300/399006创业板指/DJIAF道琼斯/IXIC纳斯达克/LBMAGOLDP伦敦金。公式：dailyChangePercent=toFixed 文案；fluctuationDescription=按波动阈值（2/3/2/3/1.5%×点位三段档）套静态文案矩阵。不返回成交量/额。差异结论：WIKI 缺；“行情是 FDP 直返、解读是静态文案矩阵”这两点对理解“为什么解读 sometimes 千篇一律”很关键，无文档。

四、口径维护机制的核心结论（给产品的建议）

  1. 出参口径的真正 SSOT 是“生产库 schema + 源码”，WIKI 天然滞后。stargate 的发布冻结机制（M3，published_route_snapshot）意味着每次 MCP 发布都会把 openapi_operation_content 冻结进快照——这份 schema（含每个字段的 description）事实上就是对外口径文档，但目前没有任何机制把它导出为人可读的文档。建议：把“快照 schema 定期导出生成《接口口径手册》”作为发布流水线的一环。
  2. wrapper_function 是口径黑洞：20 个路由的出参改写逻辑只存在于生产库一段 JS 脚本里（长赢15点过滤、热门基金抽样、申购期文案注入都是业务口径），建议至少在 api_route.description 或独立文档登记“本工具经网关改写”及其规则。
  3. 计费口径需要一次文档对齐：T0 换轨（64 工具×1分）与《MCP积分资源包配置说明》（stargate 仓库 docs/，注意它不在 WIKI）已经脱节，涉及对外售卖价格，优先级最高。
  4. 值得回填为图谱 playbook 的：本调研已验证的查询配方——api_route → api_group_route → api_service_group → api_key_usage_details 调用量统计链，以及 api_external_market_tool_pricing 定价表，可作为“查任意 MCP 工具的注册/调用量/定价”的标准配方沉淀（建议登记到 [[qieman-oap]] / [[oap]] hub 的 playbooks 字段，由人工执行，本次不修改仓库）。
