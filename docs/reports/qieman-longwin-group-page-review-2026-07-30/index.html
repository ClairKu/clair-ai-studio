长赢同路人小组详情页双版评审

选择右版的信息架构，但用混合方案拿回首屏效率。真正的上线阻断项不是圆角和间距，而是“加入小组”背后的资格、协议与异常状态没有闭环。

有条件通过

右版方向正确，不能直接定稿

分层清楚、信任感更强；需压缩头部，并在设计锁定前补齐资格状态机和必要条件披露。

右版视觉方向
2P0 阻断
80–120px建议压缩
01 · EVIDENCE

先确认我们真正看到了什么

本次仅收到左右双版视觉稿，没有 PRD、完整交互、接口或合规材料。因此可以做方向决策，但不能把静态稿当成已具备上线条件。

已确认

页面包含小组介绍、组长、加入条件、公开内容预览、分类标签，以及底部“联系助理 / 加入小组”。

合理推断

小组内容权限可能依赖“跟投客户 + 有效投顾服务协议”，加入动作不是普通社区关注。

尚未验证

资格规则、协议版本、退出/解约、失败恢复、埋点、客服后台和审核留痕均未出现在材料中。

02 · DIRECTION

选右版，但保留左版的效率

右版解决的是结构和信任问题，左版保住的是内容曝光效率。不是二选一，而是以右版为底稿做一次明确的首屏压缩。

LEFT · 不建议定稿

左版：紧凑，但信息挤在一起

内容更早出现，却牺牲了资格信息的可读性与正式服务感。

  • 组长和须知共用半透明框，语义边界不清。
  • 渐变背景上的灰白文字对比不足，长文阅读吃力。
  • 描边像禁用态，“查看更多”链接位置随文案漂移。
  • 后续增加多条件、协议状态或异常提示时容易失控。
RIGHT · 推荐方向

右版：清楚，但首屏过长

白卡分层提升可读性、信任和扩展性，是更好的设计底稿。

  • 组长、条件、预览范围被用户快速识别。
  • 黑白层级更稳，适合服务资格与协议信息。
  • 两个大卡叠加导致第一条内容价值被推到第二屏。
  • 灰色标签控件仍像不可用状态，CTA 语义仍未随资格变化。
维度左版右版判断
信息层级组长与须知挤在渐变区独立白卡，结构清楚右版
可读性低对比灰字、描边弱黑白层级稳定右版
首屏效率内容更早出现页面头部偏长左版
信任与服务感像附属说明像正式服务信息右版
扩展性条件变多后拥挤可容纳更多状态与条款右版
转化闭环CTA 与条件关系弱增加预览提示，但状态仍缺失两版都需补
03 · BLOCKERS

设计锁定前必须解决的事情

以下问题按“问题 → 影响 → 建议改法”排列。P0 未补齐前，页面无法形成可测试、可解释、可恢复的加入流程。

P0 阻断

“加入小组”没有资格与协议状态机

同一个按钮无法覆盖未登录、资格符合、协议待签/失效、已加入、接口失败和解约退出。

建议：逐一指定按钮、提示、接口结果、内容权限与客服可查字段；禁止仅靠前端提示承载服务资格。
P0 阻断

必要条件被省略在“查看更多”之后

影响能否加入的条件不能等用户点击动作后才出现，否则披露时点过晚。

建议：资格条件在加入前完整可见；“查看更多”只承载解释、FAQ 和非关键细则。
P1 重要

“满足任一条件”与只展示一条规则矛盾

用户无法判断是满足这一条，还是还有隐藏的替代条件。

建议：只有一条就改成“加入需满足以下条件”；多条时标注总数并全部展开。
P1 重要

组长名称“E大 / ETF拯救世界”不一致

服务主体、内容署名和客服口径可能出现错位。

建议：确定唯一主显示名，别名放在括号或个人页中，例如“ETF拯救世界（E大）”。
P1 重要

不符合资格的用户仍看到强“加入”动作

可能让用户把购买/签署投顾服务理解成解锁内容的前置消费，混淆服务与内容权益。

建议：不符合资格时改为“查看加入条件”或“了解投顾服务”，独立承接适当性、费用与风险披露。
P1 重要

“解锁全部精彩内容”承诺过满

若不同成员仍有策略、服务状态或内容权限差异，容易产生投诉。

建议：改为“加入后可查看该小组向成员开放的内容”，避免无边界的“全部”。
P2 优化

分类控件和联系助理都偏弱

灰色标签像禁用态；出现资格异常时，恢复入口的可见性又不足。

建议：分类栏吸顶并强化选中态；扩大助理触控区，联系时自动带入具体失败原因。
加入条件 有效服务关系与协议状态摘要

帖子直播课程工具策略
根据资格状态显示主动作

04 · RECOMMENDED HYBRID

右版分层，左版效率

把两个大白卡压成一张紧凑卡，保留资格信息的正式层级；用一条轻提示说明公开预览范围，把内容价值重新拉回首屏。

  1. 组长一行 + 条件两行，总高控制在约 180–220 px。
  2. 必要资格完整展示；条件多时先显示数量，但加入前必须全部可见。
  3. 分类标签滚动后吸顶，底部操作栏保持固定。
  4. 主按钮根据身份、服务和协议状态动态变化。
05 · COPY

可以直接替换的文案

文案目标是让用户在行动前知道“为什么能加入、加入后能看到什么、当前还缺什么”。

加入条件

正在跟投「思远定投全球好资产」，且投顾服务协议处于有效状态。

若确有多条互斥条件，标题改为“满足以下任一条件即可加入（共 2 项）”。

预览说明

你正在浏览公开内容。

加入后可查看该小组向成员开放的帖子、直播、课程、工具和策略。

用户状态主按钮说明
未登录登录后查看资格先建立身份，再判断服务关系
符合资格、未加入加入小组唯一直接加入状态
服务有效、协议待签去签署协议明确动作对象，不伪装成加入
不符合资格查看加入条件不直接驱动投资购买
校验中正在检查资格…禁用重复提交
已加入进入小组避免重复创建关系
校验失败重新检查同时提供联系助理
06 · ACCEPTANCE

研发与测试可直接采用的验收条件

每条都同时覆盖页面反馈、权限变化和追溯字段，避免“前端看起来成功，后台无法解释”。

正常加入

Given 登录、服务和协议均有效，When 点击加入，Then 创建成员关系并解锁内容，And 留存资格快照、协议版本、时间与结果。

不符合资格

Given 用户不符合资格，When 进入页面，Then 不直接显示可执行的加入动作，And 完整说明缺失条件和下一步。

协议失效或撤销

When 用户尝试加入，Then 保持公开预览状态并说明原因，And 联系助理时带入失败原因。

接口超时或失败

When 加入请求失败，Then 不乐观解锁内容，And 提供重试与客服恢复路径。

已经加入

When 再次打开页面，Then 直接显示“进入小组”，And 不重复创建成员关系。

规则版本变化

When 用户再次加入或恢复资格，Then 使用当前有效规则判断，And 历史判断仍可追溯。

07 · METRICS

不要只看整体加入转化

不符合资格的人天然不能加入，直接用全量页面访客做分母会误导判断。核心指标必须限定在“符合资格用户”。

CORE

资格用户加入成功率

符合资格且看到页面的用户中，成功建立成员关系的比例。

DIAGNOSTIC

失败原因与浏览深度

条件查看、资格失败、接口失败、公开内容浏览和联系助理。

GUARDRAIL

误解、退出与投诉

无法加入类咨询、加入后 7 日退出、资格或协议相关投诉。

FINAL DECISION

视觉选右版，产品采用压缩后的混合方案。

补齐 P0 状态机与资格披露闭环后再进入设计锁定。否则它仍是一张“更清楚的静态页面”，不是可以上线的加入流程。
