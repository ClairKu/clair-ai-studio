01 / 研究结论

平台真正出售的是顾问服务的生产能力

以下为基于公开产品资料的综合判断，不是各厂商共同作出的效果承诺。

01

TAMP 承接投资交付

外包的不只是选基金，还包括模型实施、再平衡、组合运营、报告及相关支持。顾问购买的是一套可持续运转的服务分工。

02

工作台组织服务过程

客户关系、目标、人生事件、方案、任务和后续复核需要连在一起。核心问题是“今天该服务谁，以及服务后发生了什么”。

03

个性化依赖规则

同一个模型遇到现金需求、既有持仓、税务成本、禁买限制后，会形成不同账户操作。规模化的难点是处理差异及例外。

04

AI 在争夺工作入口

会议、文档和邮件提供了持仓数据之外的客户语境。AI 若能把事实、承诺及决定写回系统，就可能成为顾问每天先打开的产品。

05

客户需要看见服务价值

客户看得懂的财富路径、关键决策、行动进度及服务时间线，让专业工作有可见载体。账面涨跌只是其中一部分。

06

买软件与买服务并存

按席位、按账户、按资产以及机构定制合同，会形成不同商业模式。工具成熟度相同，也可能承担完全不同的运营责任。

投资交付美国 / 机构级

01 Envestnet / Tamarac

把投资方案、组合管理和顾问技术接在一起的规模化平台。

目标客户
大型财富机构、独立 RIA、机构总部
价值主张
将多管理人、多策略及客户差异纳入统一投资交付流程，支持顾问业务扩张。
产品事实
UMA 支持将 SMA、基金、ETF 等放入一个账户，按 sleeve 管理；Tamarac 覆盖交易、报告、计费、CRM 与客户门户。它们属于同一生态中的不同能力层。 [2][3]
研究判断与可借鉴设计

取舍与边界：适合需要广覆盖和机构治理的组织。采购时应逐个确认模块之间的数据联动、合同及实施范围；品牌统一不能直接证明流程已经打通。

产品启发：学习“策略市场 → 方案 → 账户实施 → 报告”的完整链条；将投资平台与顾问界面分别定义、共同设计。

投资交付美国

02 AssetMark

以投资服务和顾问支持为核心的 TAMP 合作伙伴。

目标客户
希望外包投资运营、同时获得经营支持的顾问与团队
价值主张
让顾问把更多精力投入财务问题、客户关系与业务增长，减少亲自组织投资运营的负担。
产品事实
提供经筛选的投资方案、集成技术与业务支持；Advisor Portal 汇集账户和业务活动。官网介绍的模型管理流程由顾问发布模型更新，再由 Trade Operations 完成后续再平衡执行。 [4][5]
研究判断与可借鉴设计

取舍与边界：核心竞争力包括人和交付组织。比较价格时，要将专家服务、转接支持和运营承接一并计入。官网冬季功能展示不等于每家机构已获相同开通范围。

产品启发：为顾问提供“可拿去服务客户的方案 + 可求助的专家 + 能完成的运营”，而非仅开放工具。

投资交付美国

03 Orion / Orion Portfolio Solutions

顾问技术套件与 TAMP / OCIO 投资服务并行。

目标客户
独立顾问、RIA、券商与财富机构
价值主张
将客户关系、投资操作和外包选择放到同一个业务体系，帮助团队减少系统与运营交接。
产品事实
技术侧包含组合核算、Redtail CRM、交易、规划、报告和门户；OPS 提供开放架构 TAMP，包含策略、UMA、定制指数等选择。官网说明 OPS 按 AUM 的基点收费，具体依机构及服务组合确定。 [6][7]
研究判断与可借鉴设计

取舍与边界：值得研究的是“自己管、部分外包、完整外包”的连续选择。不能因为购买 Orion 某个软件，就认定同时购买了投资管理服务。

产品启发：把工作台、投资生产及专家服务组合成可选择的服务包，支持顾问团队在不同成熟阶段切换。

投资交付美国 / 全球机构

04 SEI / SEI Connect

以托管、投资和运营基础设施支撑顾问服务。

目标客户
独立顾问，以及需要端到端基础设施的银行和财富机构
价值主张
降低财富业务后台复杂度，让投资、账户与服务在统一责任链中运转。
产品事实
SEI Connect 覆盖投资方案评估、提案、开户、顾问中心、模型管理与交易。SEI Wealth Platform 面向机构，把前中后台技术、运营外包和投资服务结合。托管及技术由不同 SEI 相关实体提供。 [8][9]
研究判断与可借鉴设计

取舍与边界：与纯前端产品相比，竞争重点是后台可靠性与运营承接。实施时必须辨清 Connect 顾问能力和机构 Wealth Platform 的合同边界。

产品启发：一个问题有人负责到底；顾问前台能力要有清晰的账户、运营与异常处理承接方。

投资交付美国

05 GeoWealth

使用自研技术、强调 RIA 自主权与定制化的 TAMP。

目标客户
独立 RIA、成长型顾问机构与总部
价值主张
顾问保留投资品牌及模型选择，把实际组合运营交由平台规模化处理。
产品事实
允许顾问自建模型、第三方模型或混合使用，支持 UMA 与 sleeve；已连接多家托管机构。FAQ 说明合同按机构特点和服务需求定制，可含规模阶梯。顾问界面提供业务总览及报告。 [10][11]
研究判断与可借鉴设计

取舍与边界：特别适合研究“策略由我定义，运营由平台执行”的分工。多托管连接并不自动意味着所有外部账户具有相同数据实时性和可操作能力。

产品启发：为总部与顾问提供模型版本、账户映射、批量实施及单户例外，而非每户独立编辑一份配置。

06 SMArtX

可嵌入的 UMA 与 managed accounts 基础设施。

目标客户
多 RIA 平台、券商、托管商、金融科技公司及资管机构
价值主张
让机构用 API、组件或白标界面搭建自己的投资管理产品，缩短重复建设路径。
产品事实
官方 FAQ 列出 sleeve 级组合管理、再平衡、税务叠加、提案、现金管理、策略市场与计费；支持 API、Web Components、白标 UI，并允许选择内部或外包交易和对账流程。 [12]

产品启发：对外输出的单位可以是一段完整服务流程和可审计组件，超越单个查询接口。

投资交付美国 / 企业级

07 Advyzon / AIM

从统一顾问软件延伸到投资管理的一体化平台。

目标客户
追求统一平台的 RIA、集团与机构
价值主张
用统一客户与业务上下文减少系统切换，再选择是否使用投资外包服务。
产品事实
Advyzon 强调统一架构及顾问日常操作；AIM 提供策略市场、SMA/UMA、交易协作、直接指数、税务管理与 OCIO。AIM 是独立说明的投资顾问实体，软件服务与投资顾问服务应分开理解。 [13][14]
研究判断与可借鉴设计

取舍与边界：比较价值在于统一数据模型能否降低集成成本。单一供应商的便利，也需要与迁移、数据导出及模块选择自由度一起评估。

产品启发：先统一客户、账户、任务与服务数据，再让 AI 使用相同上下文；软件与投资服务商业边界保持清晰。

08 Schwab Advisor Center

托管机构提供的账户与交易工作入口。

目标客户
使用 Schwab 托管的独立 RIA 及运营团队
价值主张
把开户、账户维护、资金和交易连接做顺，让顾问更容易经营托管账户。
产品事实
数字开户支持家庭多账户、资料校验与电子授权；技术集成涵盖 API、单点登录、交易集成与日常数据文件，可与第三方顾问系统连接。 [15][16]

产品启发：把客户确认、资料补充、资金到账和异常进度贯通；服务动作必须回到实际账户能力。

09 Fidelity Wealthscape / FMAX

Wealthscape 是账户操作工作台；FMAX 是关联的投资顾问与组合服务平台。

目标客户
托管与经纪机构、RIA、金融顾问
价值主张
分别解决日常账户运营，以及投资方案与组合实施，形成相互连接的服务体系。

10 Altruist / Hazel

把数字托管、组合运营和 AI 工作流结合的顾问平台。

目标客户
独立 RIA；Hazel 也面向未使用其托管服务的机构

产品启发：AI 服务入口可以跨平台分发；真正实施仍要落到准确数据、明确授权与账户执行。

产品启发：用相同服务骨架覆盖标准客户，让顾问时间更多投入复杂判断和关系维护。

数据风险美国 / 全球

12 Addepar

复杂财富的数据、分析与报告基础。

目标客户
高净值财富机构、多家族办公室、银行与投资团队
价值主张
把多托管、公私募资产和复杂所有权转换成可以统一观察及分析的财富视图。
产品事实
平台支持公私募资产建模、分析、客户门户和计费，包含 AI 辅助另类资产数据处理。其数据模型可表达家庭、客户、实体、账户、投资及共同所有权关系，并可与其他业务软件集成。 [22][23]
研究判断与可借鉴设计

取舍与边界：关键壁垒是可信数据和复杂结构，而非页面数量。没有必要仅因“客户 360”就照搬家族办公室全套复杂度；它也不应被简化为传统 TAMP。

产品启发：财富档案先建设家庭、主体、账户、目标和授权关系，再决定显示哪些图表。

围绕组合核算、报告与顾问客户体验组织的财富技术与服务套件。

05 / 工作台设计

顾问真正需要的七个连续场景

场景为综合设计建议，用于评价产品，而非任何一家产品界面的逐屏复刻。

场景 / 页面必须回答的问题输入 → 输出服务价值
01 今日工作我先联系谁，依据是什么？资金与生活事件、目标偏离、未完成承诺 → 排序任务及证据时间投入有理由；不是按 AUM 简单排序
02 家庭财富视图这一家人的钱、目标和约束是什么？成员、资产负债、账户、持仓、目标、授权 → 同一家庭事实图识别关系和需求，减少每次沟通重新询问
03 会前准备 / 会中共看上次说到哪里，这次要决定什么？服务历史、待办、组合和计划 → 简报、议程、互动情景客户感到顾问记得自己，关键决定可视化
04 诊断与方案为什么改变，改后对目标有何帮助？现状、目标、约束、模型 → 当前与建议对比、成本及假设形成可理解、可讨论的选择
05 账户实施确认之后，钱和操作到哪里了？客户确认、适当性与账户规则 → 开户、资金、交易及异常进度减少建议已给出、实际未完成的断裂
06 会后任务与复核谁承诺了什么，何时完成？会议事实与决定 → 经审阅的字段更新、任务、下次检查条件承诺有负责人和结果，团队可接手
07 价值回顾过去一段时间，我得到了什么服务？服务与决策记录、目标进展 → 时间线、财富档案、下一阶段计划既解释投资结果，也让客户看见规划与行动价值

一个例子：客户说“明年可能换房，先别再加仓”

事实

标记“可能”的计划，记录预计时间、金额待确认和原始来源。

判断

重测流动性覆盖与持仓匹配，列出信息缺口；不把意向直接当成确定目标。

行动

生成核实任务和备选方案，顾问确认后更新计划；交易变更走相应授权。

复核

确认客户决定、执行状态及下次跟进时间，写入同一份财富档案。

只做会议摘要，服务会停在文本；只做产品推荐，又容易跳过真实约束。工作台应让事实、判断和行动保持连续。

减少重复操作、提高服务容量、保留投资主张或实现外包、增加持续服务和转介绍机会。

对机构总部

统一策略与规则、提高交付稳定性、监督服务、减少异常返工，并更容易承接团队和客户规模。

对终端客户

更清楚自己的财富与目标，更少重复说明，更快完成决定，更容易看见长期服务价值。

如何检验投入产出

建议按一个客户服务周期衡量：会前、会后及账户操作工时；资料一次通过率；从方案确认到实际实施的时间；每位顾问的有效服务家庭数；任务完成率；目标复核覆盖；客户留存和净流入。厂商宣传的“节省几小时”或“提高多少资产”不能直接作为本机构收益预测。

年度净收益测算 = 已兑现的工时与运营节约 + 可归因的新增服务毛利 − 许可 / 平台 / 迁移 / 运营 / 治理总成本

节省工时、增加容量和新增收入可能重叠，测算时避免重复计入；先区分劳动生产率改善与实际现金成本下降。

07 / 区域差异

美国、英国与澳大利亚，产品重心并不相同

这是样本产品的观察，不表示每个国家所有机构都采取同一种模式。

市场 / 场景样本呈现的产品重心为什么影响产品定位对其他市场的借鉴
美国独立顾问TAMP、托管连接、SMA/UMA、直接指数与税务管理顾问机构可以分别选择投资管理、技术、托管与专家服务，平台围绕分工竞争借鉴投资生产与顾问服务的模块化分工；税务及账户规则本地化
英国建议业务客户事实、现金流、建议文档、持续复核与机构经营intelliflo、Xplan 将建议旅程做成一整套可执行业务流程先明确建议形成及后续服务过程，再建设工具入口
澳大利亚顾问平台投资与 super 账户、managed accounts、费用同意及客户例外账户运营和持续建议紧密连接，组合工具承担大量实施细节借鉴确认、账户与模型实施闭环；不照搬养老金和税务结构
全球银行 / 私人财富复杂资产、全组合风险、统一数字前台和核心记录Aladdin、Addepar、FNZ、InvestCloud 分别切入不同机构级问题根据已有系统选择接入层；统一前台不要求一次性替换全部底座

海外不是一个统一市场。对且慢而言，最值得迁移的是服务组织方式、数据关系和交付规则；美国的税损收割、英国的建议文档及澳大利亚养老金包装，应在本地业务、税制与授权范围内重新设计。

09 / 且慢产品启发

建议定位：让专业投顾服务持续、稳定地交付

这是基于海外样本提出的产品建议，不是对且慢现有系统能力、服务规模或经营结果的审计。

建议的价值主张

帮助顾问看清每个家庭的财富与目标，形成合适的方案，持续完成该做的服务，让客户看见价值。

以家庭财富档案承载客户事实；以顾问工作台组织服务；以投资与运营能力完成交付；以 AI 连接上下文和行动。

产品模块最应参考建议建设的具体能力验收时看什么
家庭财富档案Addepar 的关系模型 + RightCapital 的表达家庭 / 主体 / 账户 / 目标 / 事件关系；区分已连接、客户自述、资料导入和未知；一页现状与关键选择客户能否确认事实，顾问能否解释来源与更新时间
顾问今日工作Salesforce、Fidelity、Practifi按规则生成优先服务队列；每条有触发原因、证据、责任人、截止时间、可执行动作事件到首次有效服务的时间；任务完成与复核比例
方案与持续规划eMoney、RightCapital、Xplan目标与现金流、当前 / 建议比较、假设与压力情景；形成客户确认及下一次复核条件方案是否真的进入行动，客户是否理解关键取舍
组合与账户交付GeoWealth、SMArtX、HUB24、Netwealth总部模型与版本、批准产品范围、账户映射、客户限制、再平衡和资金需求、异常状态同一模型更新影响哪些账户；哪些失败、为什么、谁处理
AI 会前会后Jump、Zocks、Hazel自动组装会前材料；从对话提取事实、决定、承诺；审阅后回写；冲突提示及来源定位字段正确率、顾问修改率、回写成功率、实际工时下降
客户端服务价值Black Diamond、RightCapital财富档案持续更新；展示已完成的规划、沟通、决策和行动；连接年度回顾与未来计划客户是否理解并持续使用；不能用页面访问替代服务结果
能力开放SMArtX、InvestCloud、Jump / Zocks在已有工具基础上，输出诊断、会前、计划更新、任务跟踪等完整服务步骤；保留授权和结果回传外部入口能否完成一个服务过程，失败能否追踪和恢复

优先做三条真实服务链

P0 / 首个闭环

持仓沟通与季度复核

事件触发 → 客户事实与历史 → 诊断草案 → 顾问确认 → 客户沟通 → 任务与计划更新 → 服务记录。

同一流程覆盖会前、会中、会后，避免各做一个孤立工具。

P1 / 从沟通到规划

新增资金与人生目标

识别资金或生活变化 → 核实需求与约束 → 方案比较 → 客户确认 → 账户实施 → 结果和复核。

把目标从一句标签变成持续服务对象。

P2 / 扩展交付规模

总部模型与客户例外

总部发布版本 → 账户适用检查 → 成本与限制 → 审批或授权 → 实施 → 异常处理 → 客户解释。

先跑通标准方案，再逐步增加个性化复杂度。

按验证阶段推进，而非先许诺功能大而全

阶段建议范围完成标准
第 1—4 周：验证现状选一个真实顾问团队和一类现有服务，建立完整步骤、数据及权限清单；抽样测量工时、返工和任务完成情况明确最费时的步骤、最常见断点、基线口径和责任人
第 5—8 周：形成闭环家庭事实、今日任务、会前包、审阅回写、服务记录；复用已有交易与账户系统一条服务可以从事件追踪到实际完成；异常可解释、可人工接手
第 9—12 周：比较效果按客户复杂度和顾问资历分层，与基线或可比团队比较；增加客户端价值展示验证工时、质量、服务覆盖及客户反馈，判断是否值得扩大
验证后扩展模型版本与批量实施、复杂规划、多团队经营、外部服务入口在准确率、权限和运营承接稳定后扩大规模

时间为建议的试点节奏，不是已排期项目。对且慢的落地应结合真实团队、现有系统与权限评估调整。

需要守住的产品取舍

财富档案要成为持续维护的服务记录；客户 360 要呈现来源、权限及未知信息；AI 的建议要可审阅并落入任务；组合运营需要处理失败和例外。把这些连接起来，才可能同时改善客户体验和顾问生产率。

10 / 深度评估方法

用同一个家庭案例，跑完一次真实服务

公开资料适合判断定位与功能范围；以下问题适合下一步产品演示或采购尽调。

评估问题要求供应商展示的证据常见误判
客户是否真的看全？同一家庭多个成员、多个托管账户、外部资产与共同持有；展示数据缺口和时间把资产金额汇总等同于全家庭理解
方案是否真能实施？同一方案遇到不合格产品、停牌、最低金额、资金不足及客户禁买时的流程把生成提案等同于完成交付
规则由谁管理？总部规则、顾问可调范围、客户例外、模型版本及权限审批把“支持个性化”理解成顾问可以随意改动
AI 能做多深？从会议中提取一个不确定事实，展示字段来源、人工确认、冲突与错误恢复把长摘要或演示脚本当成稳定自动化
集成是否真连通？展示同一客户 ID、字段映射、读写权限、同步延迟和失败重试把 SSO 或 logo 墙等同于业务集成
总成本和退出如何？完整报价、迁移工作、数据质量要求、持续服务、数据导出及退出安排只比较软件席位价格
客户和机构如何获得价值？客户看到的计划、服务记录和行动；管理者看到的容量、异常及质量用使用次数和内容产量替代客户服务结果

具体边界也能从法律披露看到：Altruist 说明成本基准数据、最小交易规模和账户暂停状态等会影响再平衡与税务工具；产品评估应覆盖这些实际约束。

[54]

六项可持续的壁垒

可信业务记录：账户、持仓、事实与来源；投资和运营规则：能稳定执行并处理例外；顾问分发与服务网络：迁移、培训和持续支持；深集成：能读、能写并能回传结果；家庭服务历史：知道客户为何作出选择；组织采用：团队愿意每天使用且能持续维护。AI 生成能力本身难以替代这些积累。
