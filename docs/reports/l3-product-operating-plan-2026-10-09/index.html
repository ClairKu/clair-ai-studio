01
EXECUTIVE DECISION

这不是“给小顾加能力”，而是重做任务终点

当前用户已经愿意问，但产品价值仍容易停在答案。L3 应把“查—判—做—验—跟”变成有状态的服务任务，同时保留金融业务所需的人工授权。

01

优先解决“研究后怎么办”

产品研究、市场洞察、持仓诊断是最强的自然需求；它们不是三类内容，而是一条投资决策链。

产品终点：形成有证据、可执行、可持续跟踪的决策任务
02

先做顾问可控闭环

顾问工作台比面向所有用户的完全自治更容易控制风险，也能沉淀规则、评测集和真实失败案例。

落地顺序：影子运行 → 顾问确认 → 小流量用户开放
03

交易需求高，但不是自治起点

交易与赎回相关提问达到 4,918 条、1,717 人；需求越强，越不能把“高需求”误读成“可自动执行”。

首期边界：AI 预演影响，用户显式确认，系统完整留痕
最重要的反常识
用户不会先学会“四笔钱”再表达需求。L3 应从“这只基金怎么看、跌了怎么办、要不要赎回”进入，在后台把自然语言翻译成且慢的方法论。
观测语料中，“四笔钱”仅 3 位用户主动提及；这是产品框架，不是高频用户语言。[D-011]

03
SHARP INSIGHTS

三个判断，决定 L3 做什么和不做什么

场景排序不能只按问题量；需要同时看用户任务连续性、业务价值、系统就绪度和损失上限。

INSIGHT 01

从“答案正确”升级到“决定完成”

产品研究 11,955 问、市场洞察 8,773 问、持仓诊断 4,611 问，实际是一条链：外部变化 → 与我有关 → 我该怎么办 → 之后如何跟踪。拆成内容频道会制造重复追问。

INSIGHT 02

入口有效，任务续航不足

推荐问题能把用户带入深聊，但 84.3% 的提问用户仍只出现一天。应将对话生成可恢复的任务卡、观察清单与下一次触发条件，而不是继续增加推荐问题数量。

INSIGHT 03

投后服务比拉新成交更适合首批 L3

千问存量合格样本中，39.7% 有投资活动、35.6% 有赎回、33.9% 有复投；豆包也呈现相同方向。高价值时刻在持有后的判断与陪伴，而不是让 AI 直接促成首投。[D-012][D-013]

SCENARIO PORTFOLIO

三项首批、一个受控能力、一个后置方向

首批场景必须能在 90 天内形成真实工具调用、结果验真和业务责任闭环。排序不是重要性排名，而是“现在最值得进入生产试点”的顺序。

1

具体产品研究 → 比较 → 适配判断

用户提出基金、ETF、投顾策略或类别；系统补齐目标与约束，自动形成可追溯研究卡。

需求证据3,875 人产品研究；2,616 人点名具体产品；2,008 人比较选择
L3 终点证据卡 + 差异比较 + 适配缺口 + 下一步任务；顾问/用户确认
P0 · 首批
2

市场事件 → 持仓影响 → 陪伴任务

监测市场、策略与持仓变化，识别“哪些用户需要知道什么”，生成个性化解释与观察条件。

需求证据3,565 人市场洞察；1,548 人持仓诊断；存量用户买卖行为活跃
L3 终点影响分层 + 持仓解释 + 顾问待办 + 审批后触达 + 7/30 天复盘
P0 · 首批
3

顾问机会 → 材料 → 执行 → 结果回收

把用户信号、持仓事件、策略节点变成顾问可处理的服务队列，并自动准备证据与合规材料。

价值逻辑先在内部可控链路积累规则、人工判断和失败样本，再开放用户自治
L3 终点优先级队列 + 推荐动作 + 一键批准/改写/驳回 + 结果归因
P0 · 首批
4

交易 / 赎回前决策支持

解释费用、到账、持仓结构与潜在后果，提供替代方案和冷静期提醒；可预填，不可代客决策。

05
L3 OPERATING LOOP

且慢 L3 的终点是“下一步已经被安全推进”

每个场景都使用同一条六段闭环。仅生成答案属于 L1/L2；能执行却不验真，也不算 L3。

01 · SENSE

捕捉信号

用户问题、持仓变化、市场事件、顾问待办和策略节点。

02 · FRAME

澄清目标

识别对象、期限、风险、已有资产与可用授权；缺项先问。

03 · RESEARCH

调取证据

产品、市场、持仓、规则、适当性与历史服务记录均带来源。

04 · DECIDE

形成计划

给出比较、判断、不确定性、替代方案与执行条件。

05 · AUTHORIZE

授权执行

低风险内部动作自动；触达、建议、交易按级别确认。

06 · VERIFY

验真与复盘

检查系统结果、用户采纳、后续状态；失败可恢复、可追责。

AUTO允许自动

取数、证据归集、内部排序、报告草拟、任务创建、结果核验。

CONFIRM执行前确认

对外触达、个性化建议、改变服务状态、任何资金相关动作。

ESCALATE必须升级

低置信度、适当性缺失、规则冲突、异常交易、投诉或敏感用户。

DENY明确禁止

代客投资决定、自动下单/赎回、收益承诺、无授权数据调用、删除审计。

06
PRODUCT BLUEPRINTS

首批两个用户任务的最小产品形态

两项产品不应做成两个聊天入口，而应共享任务卡、证据包、授权中心与持续跟踪机制。

产品研究决策任务

PILOT A
触发

“这只基金怎么样”“A 和 B 选哪个”“适合长期持有吗”

必补上下文

目标、期限、风险、是否已持有、比较对象；不必一开始问完整问卷

自动动作

检索产品事实、收益风险、费用、组合暴露、经理与策略变更；证据去重

交付

结论等级、适配/不适配理由、证据、缺口、可选下一步与复核日期

人类关口

涉及个性化推荐、营销或交易前，由顾问/用户确认并记录依据

验真

引用可打开、指标日期一致、结论与证据无冲突、后续任务已创建

首批不承诺“帮你选出唯一正确产品”；承诺把判断依据、适配条件和不确定性讲清，并推进下一步。

市场 / 持仓事件陪伴

PILOT B
触发

市场急涨跌、策略创新高/回撤、分红/调仓、持仓偏离、用户主动求助

人群识别

按持仓暴露、风险等级、近期行为和服务状态分层；敏感用户单列

自动动作

计算影响、找历史对照、生成“与我有关”的解释、给出观察点和顾问队列

交付

用户任务卡 + 顾问工作台待办 + 可审阅话术 + 7/30 天结果追踪

人类关口

所有外发内容、资产建议和挽回动作必须审批；可修改或驳回

验真

目标人群正确、内容版本一致、实际送达可查、用户动作不做因果夸大

首批重点不是提高消息发送量，而是减少不必要赎回、提升理解与服务完成度；必须用对照实验验证。
07
SHARED FOUNDATION

以场景带底座，不先造一个“大 Agent 平台”

平台能力在两个首批场景中抽取；出现第二次重复实现时再平台化。每一层都要有产品负责人和可测试的服务标准。

适当性 / 合规规则置信度 / 升级全链路审计成本 / SLA / 事故

必须先打通：数据契约

用户授权、持仓、风险、产品、市场、服务记录都要有负责人、更新时间、口径、异常状态和可用范围。

必须先建设：黄金任务集

每个首批场景 ≥100 个真实任务，覆盖正常、缺数据、矛盾规则、极端市场、投诉和工具失败。

必须先明确：责任与回滚

每个对外结论可定位业务 Owner；每个动作可暂停、撤销或补救；每次接管都进入失败分类。

08
METRICS & RELEASE GATES

用“可信任务闭环”而不是对话量评价 L3

下列为首季试点目标，不是历史成绩。两周影子运行后，应按人工基线重新校准，但安全指标不得下调。

NORTH STAR

可信任务闭环数

真实需求被识别，证据与授权合格，系统推进了下一步，结果通过验真，并被用户或顾问采纳。

可信闭环 = 合格任务 × 证据完整 × 授权正确 × 执行成功 × 结果采纳
OUTCOME

端到端闭环率

进入试点的任务完成既定终点。

目标 ≥ 60%影子期后校准
QUALITY

证据完整率

关键事实均有来源、日期与口径。

门槛 = 100%缺一项不得外发
ADOPTION

顾问采纳率

批准或小改后采用的建议占比。

目标 ≥ 70%同时记录驳回原因
EFFICIENCY

任务周期改善

相对同类人工任务的端到端时长。

目标 ↓ 40%按任务复杂度分层
SAFETY

重大合规事故

越权、误导、无授权使用数据或错误交易。

门槛 = 0发生即停用调查
EXPERIENCE

7 天任务续接率

用户查看、补充、采纳或继续同一任务。

先建基线不以对话轮数替代
关口必须具备放行标准不达标
G1 · 场景定义用户任务、终点、损失上限、业务 Owner一页章程签字不得开发
G2 · 数据与权限数据授权、口径、时效、适当性与最小权限关键数据 100% 可追溯仅模拟数据
G3 · 离线评测≥100 黄金任务、红队与工具失败案例关键错误 0；证据完整 100%继续内部修复

90-DAY ROADMAP

90 天目标：证明两个用户任务与一个内部闭环

前三个月不追求“全公司 L3”，而要证明任务、底座、治理和组织可以重复运行，并明确哪些场景应停止。

D1–15

定边界、建基线

把真实问题转成任务，不从功能列表出发。

  • 确定 3 个场景 Owner 与损失上限
  • 抽取每场景 100 个黄金任务
  • 建立人工时长、质量、采纳基线
  • 完成数据/权限/合规盘点
退出：3 项通过 G1，2 项通过 G2
D16–45

内部最小闭环

产品研究与事件陪伴先在顾问侧运行。

  • 接入产品、持仓、市场与证据服务
  • 完成任务卡、授权和审计
  • 支持失败重试、降级与人工接管
  • 每日复盘错误任务
退出：离线通过 G3
D46–75

影子运行与小流量

先比较顾问判断，再向 5% 用户开放。

  • 两周影子运行，不自动外发
  • 记录批准、修改、驳回与原因
  • 一场景一变量做 A/B 对照
  • 建立一键停机与事件响应
退出：通过 G4；重大事故为 0
D76–90

扩量或退出

按证据决定，不为“战略正确”保留低价值场景。

  • 复盘业务、体验、风险和成本
  • 扩至 20% 或回退影子运行
  • 抽取第二次复用的公共底座
  • 决定交易前支持是否进入 P1
退出：形成继续 / 调整 / 停止决议
