03 / RIGHT

真正做对的五件事

不是“做了很多活动”，而是抓住了 AI 金融服务从能力到渠道的关键窗口。

01

比同行更早把金融能力协议化

先做 MCP，再扩展 Skills、Agent、OAuth 与 A2A。协议会变，但“把投顾能力拆成机器可调用资产”的方向是对的，避免把 AI 只做成一个聊天页面。

02

选择生态分发，而不是只守自有 App

持续抢首发、上架、合作，把盈米能力送进百炼、百度、火山、腾讯、千问、豆包、微信等入口。千问 14,488 个绑定账户证明这不是品牌虚火，而是真实获客通道。

03

用小顾承接完整产品，而不是只输出接口

MCP 解决能力调用，小顾解决品牌、上下文与完整服务。这个“平台能力 + 自有 Agent”的双层结构，是 OAP 与纯工具市场的关键区别。

04

形成行业标签与大平台信用

首笔采购、首个机构投标、投顾智能体模型与评测集、金融 AI 联盟和头部平台合作，让 OAP 获得了稀缺的金融专业可信度与合作资格。

05

开始尊重证据边界

后续看板已经主动纠正“1/3 转化”等错误归因，把绑定、调用、持仓、入金、成交分开。这看似保守，实际上是把 OAP 从汇报项目推向经营系统的必要一步。

04 / WRONG

没做好的，不是流量，是经营

OAP 的短板不在“有没有更多能力”，而在流量之后的任务续航、归因、质量、成交与组织责任。

北极星仍被调用量绑架

三项规模 OKR 都超额，但调用可以被聚合 Key、单一渠道或自动任务快速放大。它无法回答任务是否完成、结果是否被采用、用户是否回来。

后果：看起来增长很快，却无法证明用户价值和收入质量。

没有把一次问答变成持续任务

千问新用户提问覆盖 89.8%，说明入口和首问都成功；但 84.3% 只在一天出现，说明服务没有留下观察清单、任务卡、下次触发条件和持续记忆。

后果：最贵的获客窗口被消耗成一次性问答。

商业化只有信号，没有可预测性

已有首笔采购、首个投标和付费咨询意向，但现有证据未显示持续付费机构、合同额、续费率、毛利或渠道结算闭环。

后果：OAP 还是“能力与合作项目”，不是独立可经营生意。

归因底座晚于渠道扩张

截至 9 月 7 日，活跃 Key 平台标识覆盖只有 0.6%；微信链路也未形成贯穿问题、调用、落地、下单、支付的业务 attribution_id。

后果：即使订单增长，也只能证明相关，不能证明 OAP 带来增量。

能力资产治理落后于数量增长

8 月审计仍见官网 69 项、后台 174 条、3 组同 ID 冲突、10 项分类漂移，多数能力缺少结构化业务 Owner、技术 Owner 与 on-call。

后果：授权、计费、质量、下线和 SLA 无法统一到同一资产。

渠道成功没有沉淀为自有关系

千问负责入口，盈米提供服务，但用户后续为什么回来、在哪里形成账户关系、谁拥有持续触达权，仍没有被固化成产品机制。

后果：流量属于平台，OAP 容易退化成后台能力供应商。
05 / MISSED

错过的四个窗口

这些机会并非永久消失，但补救成本已经比 2025—2026 年早期更高。

错过了把“首发优势”变成行业标准

OAP 有模型、评测集、MCP/Skills 和合规场景，本可进一步定义金融 AI 的任务完成、证据引用、授权、审计、回滚与 SLA 标准。现在多数优势仍停留在“先做了”。

本可形成：行业基准 + 认证体系 + 开发者心智。

错过了 Qwen 爆发期的留存产品

8—9 月流量爆发时，若同步推出“产品观察”“持仓事件”“市场影响”任务卡和周度回访，可能把一次问答转成持续服务。现在 84.3% 的一天用户已说明窗口利用不足。

本可沉淀：用户记忆、任务历史、主动服务许可。

错过了最早一批付费产品化

30+ 额度扩充/付费咨询早已出现，却没有迅速固化成个人 Pro、机构版、平台版三类可买套餐，连同配额、成本、SLA、审计和结算一起上线。

本可验证：价格、续费、毛利、客户成功模型。

错过了机构覆盖向账户经营的跃迁

“701 家服务金融机构”是官网覆盖口径，不等于 701 个客户。若缺少法定名映射、销售阶段、任务、合同、收入、SLA 和复购台账，广覆盖不会自动变成机构生意。

本可形成：金融 AI 机构 CRM 与五家灯塔客户。
06 / PRIORITY

当前任务优先级：先闭环，再规模

优先级按「用户价值 40% + 商业验证 30% + 依赖解锁 20% + 时间窗口 10%」排序。P0 必须同时启动，但共同服务一条主链路：高需求问答 → 持久任务 → 跨日复用 → 付费 → 可归因收入。

P0现在—30 天

拿下“会话结束以后”的持续任务

用户不是没需求：6,970 人在同一会话内产生实质追问；断裂发生在会话结束后，84.3% 的提问用户只出现一天。第一优先不是继续优化答案，而是让高价值问题留下任务、状态、下一触发条件和返回入口。

  • 上线 3 类任务 MVP：持仓/账户诊断、产品研究/观察、市场影响跟踪
  • 建立 task_id、完成定义、证据链、提醒许可和回访入口
  • 10% 灰度 → 50% 灰度；只在任务完成率与 D7 复用过闸后扩大
P0现在—30 天

把归因和单位经济性前置成上线条件

历史活跃 Key 的平台标识覆盖仅 0.6%。如果不先贯通 channel → client → user → task → result → transaction，后续再多流量和成交也无法证明增量或计算利润。

  • 所有新任务带唯一 ID、渠道、版本、结果和业务后果
  • 逐任务核算模型、检索、人工复核、通知与基础设施成本
  • 建立完成率、失败率、证据完整度、单位任务成本看板
P0现在—60 天

把付费意向压成三个可买产品

已有采购、投标与咨询信号，但没有可预测收入。商业团队不再卖“定制合作”，而是把个人、机构和平台三类需求压缩为有价格、配额、SLA、权限与审计边界的标准包。

  • 个人 Pro：持续观察与任务额度
  • 机构版：专属能力、审计、SLA 与客户成功
  • 平台版：调用结算、白标/联运、渠道分成
P131—60 天

用五家灯塔机构验证，不再用“覆盖”替代客户

701 家是官网覆盖口径，不是 701 家客户。选择五家有明确场景、决策人、预算和验收指标的机构，形成合同、回款、使用、复购意向四联证据。

  • 每家只验证一个可复用场景，拒绝无限定制
  • 周度客户成功复盘：使用、结果、问题、下一步
  • 第 60 天至少形成 2 个真实付费证明和 1 个可复制案例
P131—90 天

完成能力资产治理与生产 SLA

能力数量已经足够；现在需要唯一 ID、Owner、版本、成本、授权、测试、降级与下线机制。新增能力必须绑定持久任务或付费场景，否则不进入生产。

  • 100% 正式能力有业务、技术与 on-call Owner
  • 高风险任务具备证据、审批、回滚和人工接管
  • 单渠道依赖、失败降级与退出演练纳入月度机制
P261—90 天后

只有双重过闸后，才扩渠道和行业标准

留存与付费都没有过闸前，不再追逐新渠道首发。两项都成立后，才把内部的任务定义、证据规范、授权审计、评测与 SLA 输出为行业标准或认证体系。

  • 先复制已验证任务，不复制一次性问答
  • 优先降低千问集中度，不做无归因渠道
  • 对外标准必须由内部真实 SLA 和客户案例支撑

三类均有已观察到的真实问题量；用户数跨主题可能重叠，不能相加。先把高频意图变成任务产品，而不是再扩充通用问答能力。

06.2 / 90 DAYS

四个阶段，四次生死闸门

以下比例与数量是建议的管理目标和决策阈值，并非当前已经实现的事实；第 7 天完成基线后允许校准，但不能取消闸门。

DAY 0—7

定口径、砍战线

  1. 任命一位 OAP 单一经营 Owner。
  2. 冻结无归因的新渠道与无场景的新能力。
  3. 确定 3 类任务的完成定义、事件字典和实验基线。
  4. 圈定五家灯塔机构与决策人。
G0：口径、Owner、基线、灯塔名单四件齐全
DAY 8—30

交付留存 MVP

  1. 任务卡、观察清单、下一触发和返回入口上线。
  2. 10% → 50% 分层灰度，并保留对照组。
  3. 至少跑完一次真实事件触发与人工接管。
G1：创建率 ≥20%；完成率 ≥80%；D7 复用 ≥15%
DAY 31—60

跑通真实收费

  1. 三类产品包完成价格、配额、成本、权限与 SLA。
  2. 五家灯塔逐家形成方案、合同节点和客户成功台账。
  3. 对每个任务输出单位经济性与质量报告。
G2：至少 2 个付费证明 + 1 个可复制案例
DAY 61—90

决定扩张或收缩

  1. 复核 D30 复用、收入、成本、毛利路径与重大质量事件。
  2. 归因、Owner、审计、降级覆盖全部生产任务。
  3. 只复制同时通过留存与付费的任务。
G3：双闸通过才扩；单闸失败就修；双闸失败即收缩

06.4 / RHYTHM

把计划变成经营机制

不靠月末汇报推动，而用固定节奏暴露阻塞、做取舍和关闭不成立的假设。

MON / 45 MIN

经营指标会

只看任务完成、D7/D30 复用、付费、单位成本、重大失败。Owner 当场给出继续、修正或停止。

WED / SHIP

产品与实验发布

小批量灰度，必须带埋点、对照组、回滚和实验假设；没有测量方案不得上线。

FRI / EVIDENCE

客户与质量复盘

产品、商业、合规共同看真实问题、任务结果、客户使用和失败样本，不只展示成功案例。

立即停止的五件事

  • 停止把调用量、申请量和上架数当作最终成绩。
  • 停止在没有 attribution_id 前扩新渠道。
  • 停止没有任务场景或付费客户的新能力建设。
  • 停止把“机构覆盖”“合作意向”写成客户与收入。
  • 停止无配额、无 SLA、无法复用的免费机构定制。
新北极星
有效任务完成量 × 30 日复用率 × 可变现率

输入指标：申请、调用、曝光；价值指标：任务完成、结果采用、D7/D30 复用；商业指标：付费客户、合同额、续费、毛利；风险指标：严重失败、证据完整度、人工接管与回滚。

最关键的管理动作：指定一位拥有产品、技术、商业取舍权的 OAP 经营 Owner。没有单一最终责任人，三条 P0 会重新退化成三个并行项目。
