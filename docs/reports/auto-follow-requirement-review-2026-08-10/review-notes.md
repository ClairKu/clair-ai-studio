# 长赢自动跟车即时提醒｜需求评审工作稿

## 结论

需补充后再评审：A 有条件通过，B 不建议上线，C 因 B 阻断暂不成立；交易状态、自动 / 手动原子防重、跨 15:00 的交易日承诺、04 验收文档和最小根因治理均为开工前置。

## P0

1. B 的后台筛选条件是“仍未执行完毕”，对客却必须说“已执行完毕”，事实相反。
2. 当前状态模型把排队、执行、提交和结果混用，文案无法与后台事件逐项映射。
3. 自动与手动的同步提交没有服务端原子防重；不能以概率低为由降级。
4. 主文档实施、埋点、验收和待确认均依赖 04，但提交不含 04。
5. 同一发车批次跨 15:00 后的交易日一致性和用户承诺未定义。
6. 7·15 直接根因的低成本治理被放到独立评估，不能阻断下一次同类事故。

## 推荐最小版本

- 先做 CA 精确态，不把 A2 当主能力；A2 仅用于晚发车或异常的高曝光兜底。
- 非终态只说“已受理 / 正在处理 / 结果确认中”，不说“已执行完毕”。
- 未开自动且已过 15:00 的用户保留只读发车记录，不隐藏历史。
- 自动 / 手动共用 `user + CA + signal + trade_item` 幂等域；手动入口只有在可原子接管时展示。
- 同版补上单 CA 异常隔离、首轮 / 重试分离、Job 心跳与卡点告警。
