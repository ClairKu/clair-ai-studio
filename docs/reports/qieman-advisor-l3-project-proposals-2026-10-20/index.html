01 / 立项建议

先做一段能交付结果的顾问服务流程

建议主报：且慢顾问关键事件驱动的客户服务闭环 Agent。

以“策略波动／披露事件触发 → 识别受影响客户 → 生成个性化服务任务 → 顾问审核 → 跟进客户问题 → 核验服务结果”为首期范围。后续沿用同一任务、权限和证据底座，扩展新客承接、账户检视和服务工单。

顾问每天最需要解决的是：今天应该先服务谁，为什么，怎么推进，什么时候算服务完成。工作台应围绕这些问题组织业务。生成报告、问答和话术是流程中的能力，不能单独证明一个 L3 项目成立。

一个主项目

主报“关键事件服务闭环”，集中资源验证从触发到结果的一条真实链路。

三个扩展包

新客承接、定期账户检视、服务工单可以分别提报；依赖与排期独立列清，共享底座不重复计费。

90 天试点

建议用 1 个顾问小组、2–3 个策略、100 个历史案例启动；规模与目标均为提议，立项后校准。

材料状态：2026-10-20 项目建议稿，可用于提报与评审。公司 L3 正式评分表、项目负责人、预算、生产接口及权限尚未确认；本材料不代表已批准或已上线。所有评分、阈值、资源和收益测算均为规划假设。
02 / 顾问业务流程全景

沿客户生命周期找项目边界

业务阶段真实触发场景顾问业务流程可提报切口完成证据
承接服务关系建立、新客转入、首次问询识别来源与需求 → 分派顾问 → 首次沟通 → 约定下一步新客承接与资料补齐客户归属、沟通与下一步确认
KYC客户目标、约束、风险测评待完善资料盘点 → 缺口识别 → 提醒补齐 → 顾问复核 → 客户确认KYC 维护／目标信息更新权威测评状态＋客户确认记录
诊断账户偏离、风险变化、持仓复杂读持仓和现金流 → 指标计算 → 查找原因 → 形成证据 → 顾问判断账户健康检视诊断结论被审核，问题进入任务
规划教育、养老、长期投资、临时用钱澄清用途与期限 → 方案比较 → 约束预检 → 签发 → 客户决定规划实施协同方案版本、签发与客户决策
实施签约／订单待确认、失败或处理中预检 → 客户在正式渠道确认 → 跟踪 → 异常处理 → 回传签约及实施进度跟踪权威系统的确认／失败结果
持有陪伴市场波动、调仓、分红、定期披露识别事件 → 匹配受影响客户 → 审核服务动作 → 处理问题 → 核验关键事件服务闭环（首期）客户问题状态＋服务证据
复盘与延续月季年检视、目标变化、到期用钱汇总事实 → 对照目标 → 复核方案 → 沟通 → 创建下一周期任务定期检视／目标续管复盘交付、理解反馈、后续责任人
异常与退出查询、业务障碍、投诉、赎回、终止辨别原因 → 分类转交 → 跟踪处理 → 验证 → 关闭或升级服务工单与退出协同问题解决证据或客户知情后的决定

定位：工作台承担服务编排、顾问作业与证据管理；客户身份、账户账本、风险测评、签约与交易结果以原业务系统为准。家庭资产只有在客户授权且来源明确时纳入，缺失信息保留为空。

立项的六道门

任务真实

有顾问正在做的任务与明确交付物，能提供真实历史案例；不能只有设想和模拟界面。

主动且持续

事件／周期主动启动，任务跨天保存状态，等待客户后能恢复；无需顾问逐步催 AI。

能判断分支

依据缺失信息、客户需求与接口结果选择补证、合并、暂停、升级或结束。

跨系统执行

在授权范围查询事实、建内部任务、回写状态、取得回执，非只拼接一段文本。

有人负责

业务负责人、审批人、接管人、超时升级和权限范围清楚，关键动作可停。

能验证结果

完成或失败有外部事实和原因，不能以模型自评、已发送、已读代替业务完成。

六项是本材料建议的项目准入条件，不是公司正式 L3 标准。应在 Day 14 前与评审方口径对齐。简单固定流程用规则执行；复杂文本理解与服务路径建议交给模型；客户判断与高风险动作交给人，不为追求自主性增加风险。

项目 A · 建议主报 / 90 天下载提报正文 ↗

且慢顾问关键事件驱动的客户服务闭环 Agent

业务痛点
策略事件发生后，顾问需要跨系统查持仓、辨认客户差异、准备材料、联系客户并追踪问题。任务易堆积，服务是否解决客户问题缺少统一证据。该问题由现有流程资料推导，实际工时和漏服率须在试点前测量。
项目目标
将关键事件转成可追踪的客户服务任务，降低顾问单个有效服务闭环的耗时，提高服务及时率和问题解决率，同时保留顾问判断与客户自主决策。
首期范围
先选择一个顾问小组、2–3 个策略，只上线“波动陪伴”和“正式披露解读”两类剧本。系统识别事实与服务优先级，不自动发起交易、不自动改风险等级、不以阻止赎回为目的。
触发条件
正式净值／公告事件，叠加当前服务关系和客户实际持仓；同一策略事件按事件ID、客户ID、剧本版本去重。客户明确用钱或已有待处理问题时转入相应服务路径。
端到端流程
核验事件与数据时间 → 匹配受影响客户 → 合并同类待办并评估服务优先级 → 生成证据包与分支计划 → 顾问审核服务建议／对客内容 → 授权渠道执行并取回执 → 等待并解释客户反馈 → 跟进问题／转工单 → 核验结案或升级 → 更新下次服务任务。
AI承担
持续监测、读取事实、提出行动计划、补证、合并派单、等待后恢复、催办内部任务、同步结果与审计。客户用途冲突、事实矛盾或低置信判断时暂停并接管。
人工责任
顾问确认客户影响、服务方式和个性化内容；对客发送逐单审核；客户作投资决定；投诉、特殊风险和越权请求升级业务／合规负责人。
数据与系统依赖
权威策略事件、客户身份及服务关系、授权持仓、任务写接口、审批记录、正式触达回执、业务／沟通结果接口。缺任何关键项均须明确替代证据，缺持仓不得推断受影响客户。
验收标准（建议值）
建议门槛：按时有效闭环率较对照提升≥15个百分点，单个有效闭环顾问工时降低≥30%；已核验完成的证据完整率≥95%，事件事实准确率≥98%；越权触达、严重事实错误或隐私泄露为零容忍停机项。第14天冻结口径与阈值。
交付物
两类服务剧本、事件至任务台账、顾问审核页、接管与暂停、客户问题结果码、全过程证据、分组试点评估报告。
责任组织
业务负责人：且慢顾问业务；产品牵头；投研负责策略事实；数据／后端负责接口；合规与信息安全会签；顾问组长负责接管。具体人选待任命。
L3成立依据
任务由事件启动，AI跨系统判断和推进，遇到客户等待／接口失败保留任务状态，人工把关关键动作，最终用客户问题处理证据核验。若只交付机会卡片或话术草稿，验收仍属于辅助能力。
项目 B · 第二批 / 复用底座后 6–8 周下载提报正文 ↗

且慢新客承接与首次有效服务 Agent

业务痛点
新客进入服务池后，客户归属、需求澄清、资料补齐、预约和首次服务容易分散在不同工具，顾问需反复查找与催办，首服时间和流失原因难核验。
项目目标
使每个获得服务授权的新客都有明确责任顾问、有效需求记录和下一步安排，缩短首次有效服务等待。
首期范围
仅覆盖已有服务授权的在册新客；完成归属核验、资料缺口、预约与首服组织。不自动补写KYC答案、不虚构收入资产、不把开户／点击视为有效服务。
触发条件
新服务关系建立或线索经确认转入；先检查是否已承接、是否拒绝联系、是否存在冲突顾问关系。
端到端流程
核对身份与授权 → 分派／确认顾问 → 读取已有资料 → 识别最小信息缺口 → 顾问审核沟通 → 客户补充／预约 → 首次服务准备 → 顾问完成首服 → 保存客户确认的需求和下一步 → 无回应／拒绝／失联分类关闭或升级。
AI承担
归并上下文、制定补齐顺序、安排内部提醒、根据客户反馈更新任务、连续跟进等待与超时。
人工责任
顾问确认归属和问题清单、审核对客沟通并完成服务；客户自己填写／确认资料；归属冲突由主管裁定。
数据与系统依赖
身份／服务关系、授权与拒扰状态、KYC完成状态、沟通渠道及预约、任务与服务记录；信息来源和时间必须可追溯。
验收标准（建议值）
建议：首次有效服务中位耗时下降≥30%；7日内首服完成率提升≥10个百分点；补齐准确率≥98%；重复触达、无授权联系零容忍。需先测基线，再冻结观察窗和目标。
交付物
承接SOP、资料缺口清单、预约与超时机制、首服成果模板、客户确认记录、失败原因与漏斗。
责任组织
业务负责人：顾问服务／新客运营；顾问组长负责分派；产品与数据共建；合规审查信息采集和触达。
L3成立依据
不仅生成新客画像，还持续处理缺资料、预约、等待、改期与首服回执，直到有效首服或明确失败。
项目 C · 第二批 / 复用底座后 8–10 周下载提报正文 ↗

且慢账户定期检视与目标续管 Agent

业务痛点
账户复盘往往耗在取数、对账、做报告，报告交付后是否解释清楚、是否形成后续动作、目标是否变化缺少持续管理。
项目目标
按约定周期完成账户事实核验、顾问签发、客户沟通和后续问题跟踪，使报告成为持续服务中的交付物。
首期范围
首期只做平台内已授权账户的季度检视；家庭外部资产和目标变化仅采集客户确认信息。不自动调整配置与交易，不将市场波动直接等同于目标失败。
触发条件
约定季度到期；目标或用钱时间由客户确认变更；权威规则识别的资产／风险偏离。阈值由投研与业务共同批准。
端到端流程
检查检视到期 → 汇总持仓现金流与历史方案 → 口径对账 → 计算收益／风险和目标差距 → 识别需补证问题 → 生成复盘草稿 → 顾问复核签发 → 沟通与理解反馈 → 创建后续实施／资料任务 → 核验或延后 → 进入下一周期。
AI承担
组织取数和补证、调度已验证计算工具、解释差异、草拟复盘、持续追踪后续任务与版本变化。
人工责任
顾问确认诊断和方案建议并签发；客户确认目标和下一步；涉及个性化方案及执行仍走正式审批和确认。
数据与系统依赖
账户与交易事实、收益口径与校验器、历史方案版本、客户确认目标、报告签发／送达、任务和问题结果。账户／组合／底层基金不可重复加总。
验收标准（建议值）
建议：按期有效检视闭环率≥80%；顾问准备工时下降≥40%；数值与权威系统一致率100%（批准容差内）；所有签发结论可定位数据时间与计算版本。未对账成功则阻断签发。
交付物
季度检视SOP、指标字典与对账器、版本化报告、审核交付记录、目标变化与后续任务台账。
责任组织
业务负责人：顾问服务；投研负责诊断与计算口径；产品编排流程；账户／交易数据团队提供事实与对账。
L3成立依据
从定时检视一直推进到客户反馈和后续动作核验，可跨周期恢复；仅自动生成报告不足以成项。

且慢顾问服务工单协同与问题解决 Agent

业务痛点
客户关于状态查询、签约材料、订单失败等问题常需顾问、客服和后台多次转交，责任人与结案标准分散。
项目目标
让一项客户问题从识别、补证、转交到结果核验都有明确责任人和状态，缩短处理时间，减少重复询问。
首期范围
首期仅选2–3类低风险高频查询／材料问题；工单分类、补证、查询、催办和结果核验可自动推进。赔付、责任认定、退款、争议与投诉最终处理由人负责。
触发条件
顾问转入的客户服务问题、权威业务系统失败状态或工单超时；收到投诉倾向时立即转专责流程。
端到端流程
识别问题类型 → 检索已有工单并去重 → 查询事实／检查材料 → 生成最小补证清单 → 人工审核需对客步骤 → 路由责任团队 → 跟踪SLA → 回读业务处理结果 → 顾问／客户确认解决 → 关闭或升级并保留原因。
AI承担
多系统查询、整理证据、分类与路由建议、跟踪和催办内部工单、结果核验和重复问题归因。
人工责任
人工确认敏感材料请求及回复、裁定争议和赔付；业务团队作实际处理；顾问确认客户问题解决状态。
数据与系统依赖
服务问题目录、工单写接口、SLA、权威业务查询、责任团队回执、客户反馈与审核记录；不得要求客户提供密码或验证码。
验收标准（建议值）
建议：中位处理时长下降≥30%，一次解决率提升≥10个百分点；证据完整率≥95%；误关闭率≤2%；敏感信息违规采集与越权处理零容忍。
交付物
问题目录与SOP、补证规则、工单路由与催办、业务结果核验、重开机制、质量抽检看板。
责任组织
业务负责人：顾问服务／客户服务；工单处理团队承担问题解决责任；产品与数据负责系统衔接。
L3成立依据
围绕一个问题持续执行查询、补证、等待、升级和结果回读；只做问题分类和FAQ仍是辅助工具。
06 / 主项目作业设计

一件服务任务怎样跨天推进

01 · 事实源事件核验正式净值／公告
02 · 授权数据客户匹配实际持仓与服务关系
03 · AI编排服务计划证据、分支与任务
04 · 人工闸门顾问审核判断、修订、签发
05 · 业务协同执行跟进渠道回执与问题处理
06 · 结果事实核验闭环解决／失败／升级
↺ 结果与未完问题回到任务台账，触发下一轮服务 · 全程保留状态、责任人与证据
步骤业务动作／系统协同异常与人工节点必须留下的证据
1 发现事件净值／公告服务核验事件、来源、发生日和数据截至日数据不可用：进入待补证，不生成“真实影响”结论事件快照、来源和规则版本
2 确认服务对象身份＋持仓＋当前顾问关系＋授权决定候选客户无持仓／无归属／拒扰：剔除或进入内部待分派客户匹配快照与剔除原因
3 去重与排优先同客户同事件合并任务，按客户需求与问题紧急度排序已处理或冷却期：合并／抑制；按团队产能限流去重键、容量决策和责任人
4 制订服务计划结合持有期限、实际盈亏、用钱诉求和历史问题选择剧本客户明确用钱优先支持流动性处理；不能统一劝持有事实／推断分栏、行动分支与证据
5 顾问审核显示数据时间、建议、反证、客户差异、渠道和待发版本修改／拒绝／接管；数据或文案变更使旧审批失效审批人、时间、对象、内容哈希
6 执行与回执审核后经正式触达系统发送或由顾问执行，回写业务记录超时先查询结果，禁止盲目重发；无渠道权限则顾问手工执行并回填渠道消息ID或人工操作证据
7 等待与理解反馈任务跨天保持；识别客户实际问题并恢复处理明确拒绝则停止；无回应记状态，不视为成功；有投诉即时升级原始反馈、AI摘要和顾问判断分别保存
8 推动后续处理查询／补证／预约／工单分派／方案签发等在授权内推进超期升级主管；投资建议与交易转正式顾问／客户流程子任务、责任团队回执、决定与版本
9 核验服务结果回读业务结果或客户确认，并由顾问确认结案码证据矛盾则重开；无结果进入未解决／失联／超期，不能补造证明完成证据、失败原因、未解决事项
10 复盘与再触发去重统计有效闭环客户、工时与质量，安排下一次服务规则调整需版本审核与离线回放，不自动上线学习策略试点结果、改进记录、下次任务

贯穿全程的状态机

待核验→待计划→待审批→执行中→待客户／待后台→待结果核验→有效完成

每个状态可进入“待补证、暂停、人工接管、明确失败、取消”；待客户与待后台按回执事件恢复。客户撤回授权、对象变化、方案过期、主数据冲突触发重新校验，不延用过期批准。

流程示例 · 全部为虚构，无真实客户数据

同一策略下跌，三位客户的服务动作不同

甲：长期资金，没有近期用钱需求

核对其实际账户影响，解释策略变化与已知风险，确认是否理解并收集问题；顾问判断是否需要后续检视。

乙：三个月内要支付教育费用

优先澄清流动性与用钱时间，转顾问讨论资金安排，跟踪客户正式渠道的决定和处理结果。

丙：刚服务过，已有未解决问题

合并到原任务，补充本次事件证据，继续原问题处理，避免重复触达和互相矛盾的建议。

三条路径都可能形成有效服务。客户知情后选择赎回也可以是正确完成；单纯“没有赎回”不能证明服务有效。

07 / 工作台承载与公共能力

围绕任务组织六个工作区

① 今日服务队列

按紧急度和顾问产能展示应服务客户、触发原因、截止时间、未完任务；可批量合并／认领，展示抑制原因。

② 客户与家庭上下文

服务关系、授权、账户事实、已确认目标、原始沟通与历史任务。明确数据时间、来源、缺失项和争议项。

③ 证据与服务计划

事实、计算、推断分栏；策略证据、客户差异、下一动作、可选分支与不确定性；可查看反证和原始来源。

④ 审核与执行区

待审批的对象、文本、渠道、时限、方案版本并列展示；修改即重审；批准、拒绝、暂停、接管有记录。

⑤ 问题与进度台账

跨天等待、后台处理、客户反馈、失败原因、子任务和结果回读。已送达／已读／已完成分开显示。

⑥ 质量与经营复盘

服务覆盖、有效闭环、解决率、顾问实际工时、客户拒扰、缺陷与风险事件；可回溯到每件任务。

投诉责任、赔付、争议与敏感异常专责人员接管保存事实与原始表述，按既有流程升级，不由模型作最终裁定

必须演练的五类故障

过期或冲突事实

停止建议／签发 → 补证 → 人工复核；界面保留截至日和冲突说明。

工具超时／重复回调

先查结果再重试；幂等键避免重复建任务／发送；超过重试预算转人工。

客户无回应／拒绝

无回应有明确超期状态；拒绝即停止相应联系，记录而不强行追单。

顾问超负荷／无人负责

限流和合并，转主管分派；高风险事项当日人工处置，SLA以业务日历约定。

严重错误／越权／泄露

暂停相关剧本与工具令牌 → 人工处理存量任务 → 根因修复与回放 → 审批恢复。

内部任务可撤销或纠正；已发送的内容和已发生的交易不能用“回滚”消除影响。需走更正、通知或正式业务补救，保留原版本与处理记录。关键词检查只作辅助，事实、适当性、渠道、权限和签发仍由既有制度及合规人员确认。

客户体验护栏客户有效拒扰／重复触达／投诉数及其客户分母同时报告绝对件数与每千名被服务客户发生数，小样本不隐去风险较对照不恶化，零严重违规

对照试点怎样做

按顾问或顾问小组分组，兼顾客群、任务类型、策略、事件严重度和历史工时；避免同一顾问把AI产出带到对照组。至少预留两周基线、四周可比观察；真实事件不足时延长观察，不用历史回放替代线上效果。基于基线变异和最小可检测效果确定样本量，100个历史案例仅用于回放测试，不代表统计样本充分。

建议用“符合纳入条件的全部服务任务”进行分组比较，单独披露抑制／拒绝／失联／失败及原因；保留同期间市场环境与事件结构。报告各组分子、分母、绝对差、相对差及不确定性，不能把市场上涨造成的资产增长计作Agent贡献。Day 14 冻结纳入规则、主指标、SLA、严重事件定义与目标，试验后不修改标准迎合结果。

经营指标为第二层验证：净流入、服务留存、方案采纳和后续交易可在30／60／90天窗口观察；申请与确认分开、行情收益与净流入分开。未通过对照验证前，不承诺“提升AUM”或“降低赎回”。客户知情后的退出不视为项目失败。

可调整的效率测算（示例，不是收益预测）

节省工时＝任务量×有效闭环率×每闭环节省分钟÷60；等价价值＝节省工时×单位工时成本；经营差额＝等价价值－月运行维护成本。初始示例为175小时、26,250元等价价值、6,250元差额。人力价值未必转化为现金节省；初期研发、基线变化和新增收入均未包含，不能据此直接算项目回本。
