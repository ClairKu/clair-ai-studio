01 / Two problems worth solving

选这两件事：一次服务的深度，与一群客户的覆盖。

以客户目标为出发点，以账户为服务载体；延续投・顾・教与 1+N 的组织方式，让顾问把时间集中在判断、解释和建立共识。

深度 / 计划型作业

客户目标变了，
完整规划服务怎么跟上？

一次年度检视，或一句“明年要用一笔钱”，可能要重新核对家庭情况、账户持仓、风险与目标，再出方案、讲解、跟进。工具已有，串联仍耗费顾问精力。

工作台交付：一份有依据的规划服务包 + 可继续推进的计划。

01
Plan / From a changed goal to a service outcome

年度检视中，客户说：
“新增 50 万，明年还要交孩子学费。”

痛点场景：新资金安排叠加家庭目标变化，需要从现有客户资料和旧计划出发，完成一轮规划服务。

虚构案例 / 金额均为演示假设

陈女士已有且慢账户，希望安排新增资金，同时确认教育金和家庭备用金。顾问要先看清“这笔钱什么时候要用”，再判断长期目标能安排多少。

200 万已有且慢资产，不能当作全家庭资产
50 万新增待安排资金，演示中独立核算
20 万18 个月内学费；已备确定资金 10 万
2 万 / 月家庭支出；现有可用备用金 8 万

真正费力的环节：把事实、判断和后续行动接起来。

服务环节现有作业的断点 / 待试点验证工作台自动完成什么顾问保留的决定
① 会前准备承接 / 客户理解跨页面查账户、历史沟通和上次计划；容易重复问已确认的信息。按服务关系匹配客户，汇总账户快照、最近沟通、旧报告、上次承诺，生成“变化 / 未知 / 冲突”三栏简报，并附来源与时点。确认身份与服务目的；核对重要事实，决定本次沟通重点。
② 补齐信息KYC / 目标已知数据和待追问内容混在一起，难判断哪些信息足以支持下一步。对照 KYC、目标、四笔钱、保障和风险字段，只生成缺口提问；识别“50 万是新增还是已有资产的一部分”等冲突。确认用途、期限、家庭责任与资金边界；客户表达经确认后写入。
③ 账户诊断体检 / 风险不同工具结论需要顾问手工对齐；账户风险和客户感受容易分开看。复用持仓体检；分别呈现法定风险等级、风险舒适区与持仓风险指标，解释偏离与流动性问题，禁止彼此直接换算。判断原因和优先级；信息不足时暂停产品层建议。
④ 规划初稿资金安排 / 方案把诊断结论转成资金用途、目标和配置安排，需反复修改多份材料。调用确定性测算：先补备用金与近期目标，再列长期可安排余额；形成备选路径、假设、冲突项与方案版本差异。选择方案、修正假设；需要时请 1+N 中的投顾或专家协同复核。
⑤ 讲解交付报告 / 客户理解持仓复盘与前瞻规划需分别组织；顾问还要准备重点解释和异议回应。复用报告能力生成“客户版规划 + 顾问讲解提纲 + 关键问答”；每个建议回到对应目标、事实和规则版本。确认表达与建议，讲清取舍，记录客户接受、修改或暂缓的决定。
⑥ 执行跟进账户 / 任务报告已出并不等于客户接受或资金安排已落实；会后还需另记待办。将客户确认事项拆成任务：责任人、截止日、前置条件与回执。交易仅引用自营系统的实际状态。确认任务和对客内容；需要交易时由客户进入机构自营流程完成。
⑦ 持续复盘计划 / 再触发下次服务又从查资料开始，难直接知道“上次约好的事做得怎样”。保存同一计划的版本、报告、已确认纪要和任务，登记下一次检视；新变化直接进入计划差异页。决定何时复盘；认可有理由的暂缓，不把报告生成视为服务完成。

03 / FOLLOW THROUGH

有状态的会后跟进

02
Event / From a signal to timely care

市场发生波动，
今天谁需要顾问真正出面？

痛点场景：顾问名下客户同时出现持仓变化、用款、赎回与服务承诺，工作台需要给出有证据、有行动、有后续的服务优先级。

虚构案例 / 信号代表不同处置路径

同样面对下跌，林女士一周后要用款，许女士是长期资金且计划未变，吴先生则风测过期、复盘即将到期。三位客户需要三种处理方式。

先处理用款到期缺口、客户主动问题、明确承诺
再看风险变化目标与持仓匹配、交易异常、风险资料
合并重复信号一个客户进入一张事件卡，避免重复打扰
允许无需联系计划未变、无行动必要，保留观察依据
作业环节现有作业的断点 / 待试点验证工作台自动完成什么顾问保留的决定
① 发现信号数据 / 事件账户、企微、交易和日历各有信息，顾问需要反复查看。在授权范围聚合用款到期、交易状态、账户变化、风测期限、复盘计划和已确认承诺。保留原始事件与获取时间。设定适合团队的关注规则；确认异常的业务含义。
② 形成队列识别 / 排序看见下跌并不能回答谁最需要服务；同一客户可能重复出现。先校验客户映射、数据时效，再按期限、行动必要性与影响程度排序；合并同客信号，设置冷却与关闭原因。调整优先级、分配任务；选择联系、观察、暂缓或转专业岗。
③ 找到原因客户 / 账户查到变化以后，还需重新查客户目的和上次沟通，才能判断下一步。围绕这一事件准备证据包：目标、资金用途、相关持仓、最近交易、上次承诺、适用投研材料和未知项。判断是正常波动、真实用款、风险不匹配还是交易问题，避免一律挽留。
④ 准备服务行动 / 解释查材料、改话术、组织沟通重点反复发生；通用群发难回应个体问题。生成“联系目的 + 三个必问问题 + 个性化解释 + 可选路径 + 行动边界”，仅引用审核有效的材料。选择路径、复核表达；影响规划的变化转入场景 01。
⑤ 沟通留痕触达 / 反馈聊完再填记录与建任务；浏览、发送和客户确认容易混在一起。根据获授权的沟通内容形成纪要草稿，分开记录顾问发送、客户回复和客户确认，提取新承诺待顾问审核。确认并发送；裁定客户真实意图，认可其赎回或暂缓的选择。
⑥ 持续追踪回执 / 复盘已联系容易被当作已解决；资金是否到账、承诺是否履行还需追问。按真实状态跟进：未联系 → 待回复 → 已确认 → 待落实 → 已验证 / 有理由关闭；超期提醒，失败升级。核实结果与关闭原因。真实用款以用款需求解决为成功，不以挽留为唯一目标。

个性化服务 / 一次对话之后

把“我联系过”推进到“问题有结果”。

待行动：顾问确认资金时效后准备说明。
待验证：客户确认用款安排，记录下一次联系时间。

04 / Deliver and measure

先做出两个闭环，再扩成整个平台。

建议以 5–10 位顾问、连续 4 周试点校准。下列阶段是建议节奏，需结合接口与团队资源排期。

第 1–2 周 / 事实与样本

先拿真实作业做基线

由 VIP 负责人选取两类代表服务样本；核对当前 SOP、字段、报告版本和写回路径。统计顾问实际耗时与常见返工点。

出口：样本可追溯，身份与口径对齐
第 3–4 周 / 规划服务闭环

让计划走到会后跟进

接通会前简报、KYC 缺口、已有诊断与报告工具；顾问确认后形成计划版本、服务记录与有责任人的任务。

出口：同一客户可继续打开并推进
第 5–6 周 / 事件服务闭环

让信号走到结果验证

先接用款、客户主动问题、既定复盘 / 承诺等高确定性事件，再加入市场相关信号；实现同客合并、处置理由与回执跟进。

出口：每个事件能解释、处置、关闭
衡量对象指标与口径试点比较方式
场景 01 / 服务产能单次服务顾问实际投入分钟：会前查找 + 数据核对 + 方案复核 + 讲解准备 + 会后整理；同时看 P50 / P90。对同类型、同复杂度的样本做前后比较。建议目标：准备与整理耗时下降 ≥40%，以基线校准；不预设历史节省时长。
场景 01 / 服务闭环完成有效规划服务的客户数 / 到期应服务客户数；有效需包含客户决定、已确认计划版本及跟进安排。同时抽查事实错误、方案返工和客户理解度；有理由的暂缓单列，不以出报告数代替交付。
场景 02 / 及时与准确SLA 内完成首次有效处置的事件数 / 到期事件数；顾问确认需介入的事件数 / 被推送事件数。SLA 按业务类型设定。对未推送客户抽样，检测漏报；建议推送有效率目标 ≥70%，经试点调整。
场景 02 / 问题解决有验证结果或有理由关闭的事件数 / 已到期应处理事件数；另看超期任务与重复打扰率。区分真实用款、风险处理、客户疑问和关系维护，不把挽留率作为所有场景的成功标准。
共同 / 质量与可信关键事实可追溯率、顾问复核后错误率、写回失败率、无回执却显示完成的次数。关键事实追溯与准确状态显示作为验收要求；零“草稿冒充完成”。生成耗时、顾问耗时与客户等待时长分开统计。

VIP 负责人确认服务判断与质量；顾问提供代表案例并试用；产品负责对象、流程和交互；数据与系统团队提供权威数据及写回；投顾 / 专业岗维护方法与材料，按需参与复核。

管理层演示只抓两段：第一段，从“客户说了一个新目标”到“规划服务包和下一次行动已准备”；第二段，从“今天出现多种信号”到“顾问知道先服务谁，并能验证问题是否解决”。每段约 3 分钟，均保留顾问确认点。
