P0 · 金融口径

申购 / 认购字段写反

fund-screener 要求用 canSubscribe 判定申购；实时 Schema 明确 canSubscribe=认购、canAllot=申购。本次 7 只候选全是 canAllot=true、canSubscribe=false，按 Skill 会全部误判。

修复：统一文档、工具映射、推荐前检查和自动回归用例。
P0 · 上架可用性

10 个待上架 Skill 无法取得

10 个 slug 逐一安装均返回“未找到 skill”；清单给出的 Git 路径也无法访问。当前只能列为路线图，不能列为已可用能力。

修复：完成发布或从“可用目录”移出，补有效仓库和版本号。
P0 · 运行与结果

目标匹配引擎版本漂移

wealth-goalmatch 修复不存在的导入后，实际只推荐“品质生活基金 2,000 元/月”，而清单写两个目标合计 6,941 元/月，属于业务规则实质不一致。

修复：确认业务真值版本，代码、规则、示例三方同步。
P1 · 依赖

OAP 包不是独立可运行

9 个 OAP Skill 默认 HTML 都引用未随包交付的兄弟目录 yingmi-skill。干净安装会 FileNotFoundError，本次只能额外补装共享依赖。

P1 · 契约

工具 Schema 与真实返回漂移

searchInvestAdvisorContent 声明 data.items，实际返回顶层 items；基金分析要求的部分工具当前不存在；热点榜返回重复标题而 Skill 不去重。

P1 · 清单可信度

默认格式与案例来自不同版本

三个财富引擎清单写默认 Markdown，当前脚本默认 HTML；个人 Skill 的清单把“首轮信息采集”写成“一次输入即完整报告”。
