新老板入职读本 · 盈米基金投顾2.0业务

投顾2.0的本质，是把“卖策略”升级为“经营客户账户与目标达成”

盈米的投顾2.0不是一个独立功能，而是一套横跨且慢 C 端、启明/TAMP B 端、PMS/VESTA/交易与数据系统的业务体系。 它用账户、财富目标、风险舒适区、资产配置、诊断纠偏、投后陪伴和 AI 助手，把投顾服务从“组合跟投”推向“长期账户管理”。

一、核心判断

给新老板的最短版本：投顾2.0要看成一套经营系统，不要只看成且慢 App 的产品项目。

业务定义

从产品中心转向账户中心

投顾1.0更像“IP + 组合策略 + 陪伴”的服务，用户跟投某个策略；投顾2.0转向“客户账户 + 财富目标 + 资产配置方案”，围绕每笔钱的期限、风险、目标和现有持仓给出定制化账户方案。

战略意义

把买方投顾做成长期信任基础设施

且慢不与头部平台比流量规模，而是比账户里的真实获得感：盈利占比、持有时长、多元配置、复购率、波动中是否拿得住。这是买方投顾区别于单品销售的核心。

能力形态

C 端自营与 B 端输出是一体两面

且慢负责把账户投顾跑成用户服务闭环；启明/TAMP负责把投顾系统、交易、工作台、合规、培训和运营方法输出给券商、TAMP商户与机构客户。

管理重点

真正难点在跨系统、跨组织闭环

投顾2.0需要产品、投研、交易、合规、顾问、内容、客服、算法、研发同时对齐。管理者应重点盯“方案是否能执行、执行是否可追踪、结果是否能回流”。

二、业务地图

投顾2.0的最小闭环：识别需求、生成方案、执行交易、持续陪伴、复盘再规划。

识别KYC、风险承受力、资金期限、四笔钱、客户分层、账户健康度、行为事件。
规划财富目标、账户目标、现金流、定投/提取计划、达成概率、风险舒适区。
配置资配方案、产品池、复合模型、主被动偏好、KYC/KYP 匹配、调仓规则。
执行签约、交易、定投、分批买入、实时扣款、多账户、合规留痕。
陪伴账户诊断、月报、AI 小顾、顾问工作台、内容触达、偏离提醒与纠偏。

三、C 端：且慢投顾2.0

且慢侧的核心，是把“用户买了什么”升级为“用户每个目标账户是否合理、能否达成、需要怎样调整”。

账户与目标

以财富目标组织账户

新建或存量投资账户都要确认财富目标，并匹配对应投资方案。旅行、养老、长期投资、教育等目标不只是营销入口，而是决定期限、风险、现金流和方案选择的核心变量。

四笔钱

把家庭资金结构显性化

活钱、稳钱、长钱、保障构成用户可理解的资金框架。投顾2.0进一步把四笔钱诊断、配置比例、调整意见落到账户和交易方案，而不是停留在投教概念。

定制方案

从标准策略到资产配置方案

旧模式推荐标准化投顾策略，新模式根据用户场景、风险、期限、偏好、资金规模和持仓，匹配资配方案、产品组合和执行规则。

账户诊断

投后服务的关键入口

账户诊断用风险匹配、多元配置、回测表现、基金相关性四维扫描，发现偏离并把“为什么偏离、怎么调整”连接到定制方案、调仓、月报和运营提醒。

AI 小顾

扩大陪伴半径

AI 小顾承担 7x24 小时的智能陪伴入口，下一步与财务规划、四笔钱规划、投资规划、诊断优化和定制方案底层逻辑打通，形成个性化、可记忆、可执行的投顾助手。

真人顾问

承接高净值与复杂需求

平台顾问和 VIP 顾问承接存量经营、高净值转化、财务规划、私募/海外/信托等复杂需求。AI 和工作台的价值，是降低顾问服务摩擦并提升服务一致性。

四、B 端：启明 / TAMP / 投顾输出2.0

B 端不是简单卖系统，而是把盈米的投顾方法、交易能力、合规框架和运营经验模块化输出。

业务对象 客户/场景 关键能力 管理关注点
启明 TAMP 投顾团队、主理人、TAMP 商户、中小独立顾问 店铺、交易、理财多账户、定制账户、投顾会员收费、投顾报告、客户服务关系、权限角色、消息通知。 是否从工具堆变成可复制的六维服务体系：策略、系统、合规、培训、运营、咨询。
券商投顾输出2.0 证券公司投顾业务输出，中航等券商场景 H5、OpenAPI、多账户模式、分批延迟买入、定投、资产收益统计、实时扣款、券商与盈米资产口径一致。 券商系统协同、实时支付依赖、定投方案适配、项目优先级冲突和商户配合节奏。
买方投顾转型项目 券商分支机构和投顾团队培养 KYC、目标账户、持仓采集诊断、资配建议、投后陪伴、账户调优、合规留痕、H5 SaaS、API。 交付不能只做工具上线，还要形成投顾团队训练、标杆孵化和业务经营指标。
AI 开放平台 / MCP / Skills 金融机构、投顾、客户经理、AI 产品、大模型平台 持仓诊断、家庭财务规划、投资规划建议书、产品转换分析报告、投研数据与业务能力组件化输出。 定价、权限、数据授权、服务质量、合规边界，以及与投顾2.0主链路的协同。

五、系统与数据底座

投顾2.0能不能规模化，取决于底座能否把投研结论、账户方案、交易执行和服务触达连成链路。

PMS

投研结论变成可运营投顾产品

PMS 是组合运营管理与账户管理中台，承接策略、组合、复合模型、资产配置方案、调仓/发车、风险监控、审核与权限。投顾2.0中，它从“组合管理”延展到“账户方案管理”。

VESTA

投研工业化与算法供给

VESTA 提供目标规划、基金诊断、组合优化、达成概率、产品评价、投研观点、信号和报告生产能力，是投顾2.0方案质量和可解释性的上游来源。

TAMP / OpenAPI

前台服务与机构输出通道

TAMP H5、OpenAPI、tws-api、apollo-tamp、luna-tamp、adproxy 等承接商户侧服务、交易、支付、账户和数据统计，是 B 端输出能否落地的工程链路。

SCRM / 顾问工作台

服务运营与顾问提效入口

顾问工作台、SCRM、慧客通、企微侧边栏 Copilot 等，把客户标签、商机、待办、话术、质检、报告生成与服务记录联动，支撑真人顾问和 AI 助手协同。

六、业务演进线索

2021-2022
公司级投顾系统建设启动，启明 TAMP 投顾系统 v2.0 建设信号类策略、理财多账户、定制账户、投顾会员收费、工作台、PMS、交易平台等能力。
2023
且慢用四笔钱和小顾问诊强化投前/投后资金规划，在资产页引导用户逐步完善活钱、稳钱、长钱、保障配置。
2024
且慢投顾2.0产品方案成型：从投顾策略转向投顾账户，建设基于目标、风险、期限和资产配置的定制账户体系。
2024-2025
账户诊断、月度账户报告、AI 资产分析升级，把风险匹配、多元配置、回测、相关性等诊断结果接入投后服务闭环。
2025-2026
B 端投顾输出继续升级多账户、定投、分批买入、实时扣款、资产统计等交易基础能力；C 端 AI 小顾与投顾2.0能力体系进一步整合。

七、商业模式与经营指标

C 端经营

核心不是一次交易，而是长期账户质量

  • 投顾规模、投顾收费、用户复购、净流入、留存和账户目标数。
  • 盈利客户占比、持有时长、多元配置比例、波动中行为稳定性。
  • 高净值客户的财务规划、私募、海外、信托等全品类承接。
B 端输出

系统、方法、投研与运营共同收费

  • TAMP / SaaS / API / OpenAPI 项目交付与持续服务。
  • 投研 SaaS 账号、算法 API、投研共建、机构定制。
  • MCP / Skills / AI 开放平台的个人、机构与平台化商业化。
管理上不要只看“功能上线数”。投顾2.0更应该看四类结果：账户配置质量有没有改善、用户是否更能长期持有、顾问服务效率是否提升、B 端输出是否形成可复用的交付包。

八、风险与管理议题

风险类别 具体表现 建议管理动作
合规边界 投顾建议、AI 输出、资产诊断、调仓意见、营销内容、人员展业身份都靠近合规边界。 建立“建议生成 - 用户确认 - 交易执行 - 留痕 - 复盘”的规则；AI 只做辅助时也要明确边界和审计。
方案质量 资配算法、产品池、KYC/KYP 匹配、达成概率和调仓规则若不可解释，会削弱信任。 让投研、算法、产品、合规共同维护方案规则，关键指标可解释、可回测、可追踪。
系统割裂 且慢、TAMP、PMS、VESTA、SCRM、交易、AI 平台各自推进，容易形成数据口径和流程断点。 以账户为主对象梳理端到端链路，统一客户、账户、目标、方案、交易、服务事件的数据字典。
组织承载 顾问、内容、客服、投研、研发、合规若没有共同经营指标，投顾2.0容易变成局部项目。 用跨团队指标管理：覆盖率、入金转化、账户健康度、顾问人效、投诉率、合规事件、复购。
B 端交付 券商/商户系统节奏、支付、定投、资产统计口径、接口适配会影响项目落地。 项目立项时明确商户依赖、验收口径、应急方案和“标准包 + 定制项”的边界。
