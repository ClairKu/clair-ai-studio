我是怎么查到的

流程的关键不是搜文件数量，而是先识别每个平台真实的计量字段，再按会话累计值或消息 ID 去重，并做平台总量、逐日总量、模型总量三路复算。

1 · 定义区间

统一为 Asia/Shanghai，冻结到 2026-09-10 17:55:11。

2 · 只读提取

本机会话日志、SQLite；Cursor 额外读取已登录官方用量接口。

3 · 去重 / 增量

累计计数按相邻增量；消息 usage 按唯一 message ID。

4 · 统一字段

拆成非缓存输入、缓存写、缓存读、输出；reasoning 不重复。

5 · 三路复算

平台合计 = 逐日合计 = 模型/事件合计；公开版脱敏。

各端明细口径

  • Codex：读取会话与归档会话的 token_count；同一会话累计值取相邻正增量。input_tokens 已包含 cached_input_tokens。
  • Claude：读取项目 JSONL 的 message.usage；按消息 ID 去重；总量含 input、cache creation、cache read、output。
  • Cursor：本地会话确认有调用但 token 为 0；再通过客户端已登录凭据只读官方 DashboardService 的聚合、逐日与套餐接口。
  • WorkBuddy：读取项目 JSONL 的 rawUsage，按 messageId 去重；credit 与本地 session_usage 交叉验证。
  • YinmiWork：读取内置 Codex runtime 的累计 token_count 增量；cache 字段恒为 0，按“未上报”处理。

不能越界推断

  • 本机数据不含已删除记录、未同步到本机的网页/其他设备记录。
  • 计量事件不是用户提问数；Agent 在工具调用后会继续推理。
  • Token 不能直接代表模型质量、成功任务数或业务价值。
  • Cursor $487.31 是标价等价，不是发票；订阅月费也不按本报告自然月精确分摊。
  • Codex 只能识别 pro，无法从本机日志判定 $100 还是 $200；WorkBuddy 套餐同样未识别。
