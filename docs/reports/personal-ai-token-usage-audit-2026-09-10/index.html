先把“缓存”翻译成人话

你看到的总 Token 不是都在处理新问题。长对话、代码库和 Agent 工作会反复读取旧上下文，所以“复用内容”通常最大。以下三项相加，才是报告里的总调用量。

95.7% 的输入来自复用，并不是浪费。 它说明你经常做长上下文、多轮 Agent 和代码库级任务；复用通常比重新发送同样内容便宜。风险是旧指令、无关文件和过期结论也会被一起带进来，所以真正该优化的是上下文质量，而不是盲目压低 Token。

你目前的使用习惯

这些是从逐日结构能确认的行为模式；“同一天用了多端”只能说明平台共存，不能直接证明同一个任务重复跑了多遍。

01

重度集中在少数工作日

可见期共 40 个活跃日，前 5 个高峰日贡献 48.0%；工作日占 90.4%。你更像“项目冲刺型”使用，而不是均匀聊天型。

02

多平台并行已经常态化

21 天同时使用至少两个平台，这些天贡献 88.9% 的可见用量。多模型互审有价值，但也最容易出现上下文重复加载与返工。

03

长上下文复用非常高

复用内容占可分辨输入 95.7%。这符合代码、报告、Agent 连续作业；也意味着每次新任务若沿用旧线程，历史包袱会持续放大。

04

三大主力清晰，另外两端偏补充

Claude、Codex、Cursor 合计 98.8%；WorkBuddy 与 YinmiWork 更像专项试用或内部入口。

建议 1 · 任务分流

先固定平台职责

Claude：长文与大上下文；Codex：仓库级实施、验证、交付；Cursor：IDE 内快速修改和模型切换。减少同一重任务三端完整重跑。

建议 2 · 控制上下文

里程碑后开新线程

把已确认结论压缩成 1 页 brief，再开新任务；排除构建产物、日志和无关目录。目标不是少用，而是让每次复用都更干净。

建议 3 · 衡量成果

用“交付成本”决定订阅

下月同步记录任务数、一次成功率、返工次数和正式交付物。Token 吞吐只能衡量用量，不能衡量模型是否真正省了时间。

跨平台同模型：谁更值

最接近可比的是 Claude 模型：一边在 Claude Max 5x 内直接使用，一边在 Cursor Ultra 内调用。表中 Cursor“标价等价”来自官方用量计价，不是额外扣款；Claude 订阅是整池月费，无法可靠拆到单个模型。

纯吞吐

Claude Max 更强

相同 Claude 模型族下，Claude 直接端的总量是 Cursor 的 6.2×—20.7×。若目标是长上下文批量处理，Claude 是你现有组合里的吞吐主力。

IDE 价值

Cursor 不是靠 Token 数取胜

Cursor 的价值是代码上下文、编辑器闭环和模型切换。冻结近月官方标价等价 $487.31，相对 $200 Ultra 月费为 2.44×，且当期记录均归入 included。

GLM 暂不可硬比

WorkBuddy vs YinmiWork

两边都有 GLM 5.3 Flash 痕迹，但 YinmiWork 未上报缓存拆分且缺少可归因价格；现在比较“每 Token 多少钱”会制造假精确。

结论： 同模型的“便宜”要分场景。Claude Max 适合把订阅换成大吞吐；Cursor Ultra 适合把 IDE 工作流和多模型整合换成少切换、少手工搬运。若 Cursor 的正式交付物持续偏少，即使 Token 标价等价很高，也应降档；反过来，只要它显著减少返工和人工粘贴，较高的每 M 成本是合理的。

我是怎么查到的

四个平台来自电脑本地记录；Cursor 是例外：本地数据库能确认调用，但 Token 字段为 0，因此使用电脑里已登录的 Cursor 会话，只读查询其官方用量接口。没有去抓公开网页上的账户统计，也没有读取会话正文。

逐端来源

  • Codex：本机会话与归档会话中的累计 token_count，按相邻正增量计算。
  • Claude：本机项目 JSONL 的 message.usage，按消息 ID 去重。
  • Cursor：从本机客户端已登录态，只读官方 DashboardService 的逐日、模型和聚合用量。
  • WorkBuddy：本机项目 JSONL 的 rawUsage，并用 session_usage 交叉核对 Credits。
  • YinmiWork：本机内置 Codex runtime 累计量；缓存字段没有上报。

不能从数据推出什么

  • 本机已删除、未同步或其他设备上的记录不会自动出现。
  • Token 事件不等于你的提问次数，Agent 会在工具调用后继续工作。
  • 高 Token 不等于高质量、高产出或高成本。
  • 1 月至 7 月 16 日是“未知”，不是“零使用”。
  • 跨平台同日使用不等于同一任务重复，只有接入任务标签后才能确认。
