机会、风险与建议

P1 · 立刻做

把五端月度计量统一

当前四端可核验、Cursor 缺数。为 Cursor 增加本地 usage exporter，至少保存时间、模型、input/output/cache token 和费用字段。

P1 · 立刻做

用“双口径”管资源

管理看板同时展示“总处理量”和“非缓存+输出”。你的缓存输入占 96.2%，只看总 token 会高估新增计算负载。

P2 · 一周内

给重任务设上下文预算

YinmiWork 单会话高达 37.57M。建议对长报告任务设置阶段性产物、上下文压缩点与单轮上限。

P2 · 一周内

按产出而非 Token 排名

Token 是资源，不是价值。下一版应补充每端完成任务数、成功率、交付物、返工率与单个有效成果 Token。

P3 · 后续

建立成本换算层

按模型、缓存读写、套餐与 credit 规则换算成本。当前报告不把 token 直接换成人民币，避免错误定价。

风险

日志留存不等于完整账单

本机删除、迁移、客户端版本差异都会造成缺失。Cursor 的本地可观测期从 8 月 31 日开始，早期记录可能已被清理。

口径、数据索引与自检

统一口径

  • Codex：input_tokens（已含 cached_input_tokens）+ output_tokens；每会话按累计值增量求和。
  • Claude：input_tokens + cache_creation_input_tokens + cache_read_input_tokens + output_tokens；按 message.id 去重。
  • WorkBuddy：prompt_tokens + completion_tokens；cache hit 是 prompt 的子集；按 messageId 去重。
  • YinmiWork：内置 Codex runtime 的累计 token_count 增量；cache 字段记录为 0，标记为“未上报”。
  • Cursor：tokenCount.inputTokens / outputTokens 共 2,188 条记录但均为 0；不计入总量。

边界

  • 范围：本机能读取到、时间落在 2026-08-10 00:00 至 2026/09/10 17:55:11 的记录。
  • 不含：网页端未同步到本机的对话、已删除日志、其他设备独有记录。
  • 计量事件不等于用户问题数；Agent 每次工具调用后可能继续触发模型推理。
  • reasoning token 是 output 的子集，不重复计入总量。
  • 报告公开版仅保留聚合值，不包含账号、密钥、会话正文、个人路径与任务内容。
