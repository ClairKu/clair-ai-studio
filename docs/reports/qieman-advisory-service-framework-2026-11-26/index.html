先把一次交接做通

先选教育金试点。客户在千问说过何时用钱，回且慢就能打开原规划。如果同一笔钱还要买房，顾问接到的是两项目标的冲突，可以直接和客户讨论取舍。等另一位顾问、另一个入口都能复用这套方法，再扩大投入。

新客获得第一次有效服务
“孩子以后上大学，这笔钱现在怎么准备？”

千问贡献的是带着具体问题来的客户。且慢能不能接着办，决定这次咨询有没有经营价值。

首轮转化口径
在约定观察窗内，正式系统确认、且能关联到原教育金规划的完整策略买入。分母为入组合格的去重新客，比较试点组与原路径。

  1. 千问小顾先把问题问清楚

    确认用款时间和意愿。客户选择继续，再按授权衔接且慢，有原目标就接着做。

  2. 在且慢 App 接着上次做

    小顾只补影响下一步的条件，调用已有规划服务。本人决定是否接受方案，并在正式流程中确认办理。

  3. 家庭有两种用途冲突时，顾问接手

    例如同一笔钱也要用于近期开支。顾问在工作台比较方案，记录客户决定和复访日期。标准事项可由客户与小顾直接完成。

  4. 按原事项收回结果

    分别记录保存目标、取得方案、开始办理与完整买入。用户暂缓，就按约定时间再跟进。结果在途，就查原订单。

老客理解自己的账户
“这个月账户少了，是投资亏了，还是我取过钱？”

新月报本身就能触发服务。老客此刻想弄清发生了什么，小顾应给出可核对的解释。

首轮服务口径
先用离线案例验收同一账户、同一报告期的解读，确认客户可回看、已了解或关闭后能停止提醒。上线试点后再观察重复打扰与求助。

  1. 正式月报生成，小顾判断是否介入

    核对用户可访问的账户、报告期、阅读状态和提醒选择。有可解释的新信息，才在允许的位置呈现入口。

  2. 在 App 把变动讲明白

    从正式报告区分投资损益和资金进出。客户可查看原报告、提出疑问，也可直接关闭。

  3. 客户提出新问题时，再决定谁跟进

    若提到临近用钱，可新建或接回对应的规划事项。需要家庭层面的判断时，由顾问带着已确认的信息接续。

  4. 解读结束，原提醒随之撤下

    按反馈关闭本期任务，保留回看入口。后续的规划或顾问预约单独记录，月报服务以自身的交付结果验收。

示意旅程。顾问主动检视及跨端接力属于建议设计，两项申报场景的首轮验收范围分别保留。

新增投入，按什么顺序排

先证明一条业务路径有用，再证明人机交接顺畅，最后扩大生产与分发。

经营决策优先补的缺口值得加大投入的证据
先验证转化先跑通一笔教育金规划用小顾 4.0 表达产品方向，主动服务写进能力设计，L3 承担首轮验证。千问承接、App 找回原目标、取得正式回执一起做。看合格新客的完整买入转化相对原路径是否提升，同时看重复打扰和每千项任务人工时。跨端归因打通前，分段报告。
再做深服务让另一位顾问接得住保留 App 和顾问工作台的独立职责。用一次目标变更，打通客户自助、顾问复核、约定复访和结果回写，优先解决重复询问与无人跟进。换一位顾问能从原事项继续，客户确认的下一步到期有反馈。记录按期有效服务占比和包含复核、返工的每案工时。
再扩大覆盖把验证过的方法交给第二个使用者实验室先把一项已验证的方法交给第二支团队。开放平台用已有接入支持千问，也可让合作机构把成熟能力嵌入自己的产品。实验室看第二团队能否独立交付、花多少适配工时。开放平台看第二入口能否持续完成有效任务、每次成功交付成本多少。

谁对交付负责

业务对服务方法和客户结果负责。产品定义跨端共用的事项、体验规则和验收标准。研发接通授权、状态和正式回执，使每一步可以追溯和恢复。
