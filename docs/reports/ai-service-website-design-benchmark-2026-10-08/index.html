01
Executive summary

八个结论，先把方向彻底纠正

上一版偏“通用 Agent 平台”。这一版从金融机构采购、专业用户研究、开发接入和管理治理四个真实决策场景出发。

1

首页应先证明“金融”，再证明“AI”

可信数据源、覆盖范围、更新时间、研究方法、机构客户与合规能力应早于模型参数和技术名词。Morningstar、LSEG、S&P 都把可信数据作为 AI 叙事的地基。

影响：提高机构决策人继续浏览与留下线索的意愿。
2

最强叙事是“数据 → 智能 → 工作流”

不是把数据、MCP、Skill、Agent 平铺成菜单，而是明确它们如何把金融问题变成可审计交付物：报告、模型、组合分析、尽调、预警或客户材料。

影响：让技术能力自然转化为可采购的业务价值。
3

用户入口必须分三条，不要一条万能路径

机构决策人看方案、案例、安全与 POC；业务用户看任务、样例与试用；开发者看数据目录、MCP/API、权限、文档与沙盒。

影响：降低首屏理解成本，缩短每类用户到目标页的距离。
4

MCP 的价值是“带着授权把数据送进 AI”

Morningstar、LSEG、S&P 的共同重点不是协议本身，而是持牌数据、既有权益、引用溯源与权限控制。MCP 详情页必须回答数据口径、可用工具、授权对象和审计方式。

影响：把开发接口升级为企业采购理由。
5

金融 Agent 必须展示过程与证据链

AlphaSense、Hebbia、Rogo 强调多步研究、来源引用、表格/文档/模型交付与可复用工作流。金融场景里“看起来对”远远不够。

影响：减少黑箱焦虑，提升试用后的认可率。
6

广场不是应用商店，是金融能力交易台

卡片要展示资产范围、数据截止日、更新频率、口径、许可、权限、输出样例、SLA、预计成本与验证状态。只有名称、图标、安装量远远不够。

影响：提升广场 → 详情 → 有效试用的转化质量。
7

试用应是“可验证的样例任务”，不是空白聊天框

预置去敏金融场景、固定样例数据与验收清单，让用户先核对引用、数字口径和交付格式，再进入真实数据 POC 与正式开通。

影响：减少无效试玩，增加销售可跟进的高意向线索。
8

积分、预算、权益与产出必须是一套账

借鉴 Manus 的团队用量和 Rogo 的 Credit Center，但要进一步呈现数据许可、API/MCP 调用、模型成本、项目分摊、异常消耗和单位成果成本。

影响：降低费用争议，支撑预算、续费和扩容决策。
最犀利判断
如果首页把“模型、MCP、Skill、Agent”并列成四个大入口，设计一开始就错了。客户买的不是名词，而是带有金融数据权利与责任边界的结果。

建议定位：从“AI 服务官网”升级为“可信金融智能开放平台”。核心承诺是：把权威金融数据、机构方法与可治理 AI 能力嵌入每一个工作流。

四类竞品，不能再混在一张名单里

四类产品解决的问题不同。设计时应分别借鉴其数据信任、研究体验、开放能力和任务式交互，而不是寻找一个可以整站照抄的对象。

Reusable patterns

海外金融 AI 平台真正领先的六个模式

这六个模式应进入产品结构和交互，不应只停留在报告里的“灵感图”。

01

可信数据先于模型

展示数据来源、覆盖、许可、更新和方法论，再说明 AI 如何调用。金融智能的可信度来自可验证地基。

MORNINGSTAR · LSEG · S&P
02

确定性与自适应双路径

简单取数走可重复 API；复杂研究走多步检索与 Agent。不要让所有问题都进入一个不可预测的聊天框。

S&P AI DATA PORTAL
03

来源与中间过程可见

答案、表格、模型和报告都能回到原始来源；用户可看、改、重跑每一步，而不是只能接受最终文本。

ALPHASENSE · HEBBIA
04

Agent 围绕成品命名

“发起覆盖报告”“估值包”“投委会备忘录”比“智能研究 Agent”更具体；样例结果即最有说服力的产品介绍。

ROGO AGENT LIBRARY
05

既有权益自动继承

MCP 与 Agent 应尊重既有数据许可、组织角色和内容权益，不要求客户再建立一套孤立授权系统。

LSEG MCP · MORNINGSTAR MCP
06

预算与 Agent 治理同屏

管理员同时看到模型、Agent、数据访问、政策、成本和 ROI；用量不是财务附属页，而是安全治理的一部分。

ROGO WATCHTOWER · MANUS TEAM

Visual direction

视觉方向：像“机构金融智能”，不要像“AI 发布会”

视觉要传达专业、精确、可验证、可操作。真实产品界面、数据来源、工作流状态和成果证据，比 3D 机器人、宇宙渐变与漂浮粒子更有说服力。

推荐 · 70%

Institutional Intelligence Desk

深海军蓝 + 暖白纸张 + 信号青绿；编辑式大标题与高密度数据界面并存。适合兼顾机构决策人、业务用户与开发者。

备选 · 20%

Financial Operating System

更强控制台感，强调网格、状态、权限、监控和服务编排。适合平台后半段与开发者中心，不建议整站都做暗色。

备选 · 10%

Research Editorial

更像高质量研究机构和财经出版物，适合案例、洞见和方法论内容；若单独使用，会削弱开放平台与产品操作感。

六条必须遵守的视觉规则

✓

Hero 展示真实金融任务

包含标的、数据截止日、调用步骤、引用数、口径提示和交付格式。

×

不要再用无意义机器人

机器人插画会把专业金融数据平台降格成通用 AI 活动页。

✓

数据新鲜度成为视觉元素

时间戳、更新频率、状态和来源徽章不是脚注，而是核心信息。

×

不要满屏同规格卡片

用编辑式层级、宽窄错落和真实界面建立节奏，而不是十二宫格。

✓

动效解释 Agent 状态

只用于计划、调用、授权确认、校验、完成和异常，不做纯装饰光效。

×

不要把“申请演示”放满全站

列表看详情、详情先试用、试用成功再申请 POC；每页只有一个主 CTA。

Roadmap & validation

12 周落地：先完成“可信成交骨架”，再扩大生态

以下提升幅度是实验目标，不是既成事实。先把信息架构、真实样例与开通链路做对，再做大规模内容和生态运营。

P0 · 必须先做
0–4 周

方向与骨架

完成定位、对象模型、三类用户路径和 P0 页面高保真。

  • 金融数据 → 智能 → 工作流架构
  • 首页 / 场景 / 广场 / 详情
  • 2 个可验证样例任务
  • 统一事件与线索口径
P1 · 建立闭环
5–8 周

试用、POC 与治理

让试用结果可验收，并把高意向用户无缝移交销售和管理员。

  • 任务式试用与来源核验
  • POC 申请与进度
  • 权益 / 权限 / SLA
  • 用量账本与服务管理
P2 · 放大增长
9–12 周

案例与开放生态

用真实案例和可治理供给扩大内容、合作伙伴与复购。

  • 案例与同款服务关联
  • 开发者沙盒和调试器
  • 创作者审核与上架
  • 预算预测与价值报告

  • 事实核查：平台功能陈述回到官方页面或官方仓库；不以第三方软文替代核心证据。
  • 分类边界：Manus 仅作交互参照；Morningstar 归为海外金融数据与 AI 平台，不按中文品牌名误归国内。
  • 可见边界：登录态控制台、真实报价和机构合同条款无法公开核验，报告不编造界面与价格。
  • 分析边界：评分、页面优先级、转化提升幅度均为研究判断或实验目标，不是平台官方结论。
  • 完整性：已覆盖 MCP、Skill、Agent、案例、服务开通、试用、工具、广场、个人中心、积分/用量、统计与服务管理。
