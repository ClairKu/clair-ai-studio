04 / VALUE & MEASUREMENT

展业成效，要沿业务链逐段验收

不同合作模式使用各自的价值指标。金融问答、开发者工具与营销投放不能共用一个“转化率”。

面向客户的展业闭环

以下为建议量度框架。公开来源未给出统一、可复核的跨平台经营数据，本报告不填估算值。

01 / ENTRY

入口可见

目标用户能否在真实场景找到服务

量度：曝光、有效到达
02 / CONSENT

授权归因

能否在用户授权下保留来源关系

量度：授权率、归因覆盖率
03 / TASK

有效任务

是否解决问题并形成可用结果

量度：成功率、复用率
04 / RELATION

客户绑定

是否承接为可持续服务的客户

量度：绑定率、有效客户数
05 / INVEST

开户 / 首投

来源可归因的真实业务行为

量度：开户率、首投率
06 / RETAIN

持续留存

后续服务、持有与客户价值

量度：30 / 90 日留存
专业工作流：以有效任务完成率、活跃使用者、交付复用、节省工时与付费为主要指标。
开发者分发：区分订阅、激活、生产使用与续费；API 调用不能直接视为获客成效。

先拿到可追踪的样板，再扩渠道

验证订阅激活 → 生产使用 → 续费，识别能够持续付费的用户和任务。

先补证 手机与待公开入口

先取得具名分发依据、真实客户端入口与验收条件，再决定试点投入。

DAY 01—30 / 核实入口

把“合作”拆成可验收清单

  • 对营销合作、AI 服务与技术适配分别建账。
  • 选 2—3 个有真实用户入口的样板渠道。
  • 统一授权、来源标识与事件定义。
  • 记录可见入口、服务范围和版本日期。
阶段验收：每个样板有入口证据、责任人、用户路径与可复核的归因方案。
DAY 31—60 / 跑通任务

把任务完成与客户承接连起来

  • 围绕高频金融问题设计少数完整任务。
  • 量度失败、超时、人工接管与重复请求。
  • 在用户授权下验证客户绑定与后续服务。
  • 比较入口差异，识别真正有效的使用场景。
阶段验收：能逐笔追踪入口到有效任务；样本、分母与异常均保留。
DAY 61—90 / 决定扩张

依据业务结果决定投入

  • 营销渠道看有效客户与可归因首投。
  • 专业工作流看完成、复用与付费意愿。
  • 开发者渠道看生产活跃与持续订阅。
  • 按成本和 30 / 90 日留存决定续投或调整。
阶段验收：形成有成本、有客户质量、有后续价值的渠道比较，而非调用量排名。

06 / SOURCES & SCOPE

来源索引与核验口径

核验截止：2026-10-22。仅收录可公开查阅的材料；来源发布日期与本次核验日期分别记录。

如何阅读证据状态

  1. 正式披露证明列名合作关系；不据此推定具体经营规模。
  2. 企业文章按原文陈述范围引用；计划、发布、适配与实际活跃分开。
  3. 接入说明证明文档中描述的配置或调用路径；不自动证明生产客户使用。
  4. 同集团不同产品分行；缺少公开依据的项目保留待核验。

这份报告的边界

本报告是公开证据盘点，不是公司内部经营报表。未披露的客户数、交易金额、收入、成本、转化率与留存均不推算。90 天行动与验收框架为本报告建议；阶段阈值、资源规模和责任人应由业务确认。
