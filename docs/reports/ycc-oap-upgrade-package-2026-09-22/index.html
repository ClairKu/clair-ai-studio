01

为什么要做 YCC

盈米对外的科技产品越来越多，但"卖东西"这件事还是一个产品一套做法。

现状 一个产品一套帐、一套钱、一套权益

  • !帐号各自为政。OAP 官网个人用户借用且慢登录，机构用户走慧客通（yingchat）身份，WealthWork / AI 编辑部各有一套；同一个客户在不同产品里是不同的人。
  • !收费靠合同 + 线下。机构合同按"预充值积分"计费（如山西证券 12 万元 / 12 个月），但积分入账、扣减、对账多靠人工表格，客户无法自助查看。
  • !个人用户想付钱也没入口。OAP 只有免费申请 API Key，没有商品、没有收银台，用量做不成收入。
  • !权益口径不统一。Token 额度、MCP 权限、积分余额、席位数分散在各系统，业务侧无法回答"这个客户到底还剩多少、能用到什么时候"。
  • !每个新产品都要重造一遍。Vesta、更多产品要商业化，就得再做一次登录、购买、发票、售后。
→

YCC 之后 一个客户、一个帐、一张单、一份权益

  • ✓统一登录身份。手机号为主身份，微信 / 且慢 App 快捷登录；机构有管理员、采购、使用人角色，成员统一管理。
  • ✓商品上架即可卖。Token 包、MCP 套餐、积分兑换商品由商品管理统一定义、定价、定销售范围。
  • ✓在线 / 对公一个收银台。个人在线支付、机构对公支付、积分抵扣与组合支付，统一主体、统一退款对账。
  • ✓权益随手可查。额度、权限、积分余额、有效期、流水在一处，业务和客户看到的是同一份数。
  • ✓新产品即插即用。接入 YCC 就自带登录、购买、权益、售后，商业化周期从"月"到"周"。

依据：OAP 帐号现状与身份架构来自盈米本体核查（stargate 双 IdP：C 端 pmdj OIDC / 机构 yingchat-gateway，2026-09-22）；机构合同预充值积分计费来自《山西证券基金诊断模块 MCP 技术服务合同》文本。

02

YCC 是什么、不是什么

一句话：YCC 是盈米科技产品的"商业中枢"，不是又一个业务产品。

定位

统一科技服务商业中枢

为盈米面向外部的科技产品（OAP 开放平台、WealthWork、AI 编辑部、内容合规等）提供共用的身份、商品、交易、权益、售后五类能力。各产品专注自己的业务功能，"卖"和"算账"交给 YCC。

做什么

五件事，一条链

用户认证与用户管理（谁在用）→ 商品管理（卖什么）→ 订单与统一收银台（怎么付）→ 权益管理（拥有什么、还剩多少）→ 售后管理（退、撤、争议）。
交易主链路：商品 → 订单 → 收银台 → 权益。

不做什么

三条边界

① 不碰且慢 C 端的基金交易帐户与隐私数据，且慢与 YCC 数据隔离；② 不替代各产品自身的功能与用量执行（如 Stargate 网关的计量），只接收结果做权益扣减；③ 不做业务产品的运营与内容。

怎么向老板一句话讲：YCC 是盈米科技收入的"收银台 + 会员系统"。以前每个产品自己开店、自己收钱、自己记帐；以后统一一个门、一个柜台、一本帐，客户买得顺、我们算得清、新产品上得快。

商品与权益：一个"卖什么"，一个"谁拥有什么"

这是 YCC 最容易被混淆、也最关键的一组概念。

对比维度商品管理 ｜ 定义"卖什么"权益管理 ｜ 记录"谁拥有什么"
核心对象Token 包、MCP 套餐、积分兑换商品Token 额度、MCP 使用权限、积分帐户 / 余额
是否绑定用户否，与具体用户无关（是模板）是，绑定个人 / 机构 / 合同（是实例）
关键属性名称、价格、周期、销售范围余额、有效期、使用范围、权益流水
产生时点商品配置并上架后即存在购买、签约或运营发放后产生
业务动作配置、定价、上下架、积分兑换配置发放、扣减、冻结、回收、退还、补发

类比一下

商品像货架上的"充值卡面额"——100 元卡、500 元卡，谁都能看、跟谁买没关系。
权益像你钱包里那张已经刮开的卡——写着你的名字、余额、有效期、每一笔消费记录。
积分是权益的一种形式：积分帐户属于权益，积分兑换商品属于商品。

交易主链路：商品管理 → 订单管理 → 统一收银台 → 权益管理
售后闭环：订单管理 → 售后管理（退款 / 退订 → 权益或积分回收退还）

带来什么价值，怎么衡量

业务、客户、公司三个视角，各配可量化指标。

对业务团队

  • 签约到开通：从"合同 → 人工建帐 → 手工发额度"缩短到管理员自助，目标 ≤ 1 个工作日
  • 不再维护各产品的客户表、积分表；一处看全部客户在全部产品的权益与用量
  • 续约与加购有数据依据：余额预警、用量趋势自动推送商务

对客户

  • 一个帐号登所有盈米科技产品；机构成员由自己的管理员管理
  • 余额、有效期、每一笔消耗随时可查，不用找商务问
  • 个人可即时购买；机构对公付款后权益自动到帐，统一开票

对公司

  • 把"订阅 + 用量"收入模式从合同文本变成可计量、可对帐、可确认的系统事实
  • 新产品商业化的固定成本大幅降低：接入即具备登录、购买、权益、售后
  • 统一收费主体，财务口径一致，为 AI 科技服务收入预测提供真实数据底座

建设与采用指标

接入 YCC 的产品数（年底）≥ 4
OAP 存量用户迁移完成率≥ 95%
统一登录成功率≥ 99.5%
新产品接入周期≤ 2 周
合同客户自助查余额覆盖率100%

经营结果指标

可按积分计量的用量占比100%
个人付费转化率（活跃用户）目标 3–5%
机构积分池月消耗率监控 · 预警 <20%
对帐差异率（系统 vs 财务）< 0.1%
售后 / 计费类客服工单环比下降 50%

说明：指标目标值为建议口径，需与业务 DRI、财务共同冻结；OAP 用户与调用数据引自 2026-05 官网升级稿及 2026 下半年 OKR。

需要管理层拍板的事项

这些问题不定，后面的产品与技术方案就无法收敛。

1
统一收费主体是谁

YCC 以哪家公司主体收款、开票、签约？这决定收银台的支付通道、发票系统与财务口径。

选项：盈米基金 / 盈米科技 / 按产品线区分
2
积分是否跨产品通用

默认按产品和合同隔离。要不要允许一个机构的积分池同时用于 OAP 与 AI 编辑部？通用会更好卖，但定价与成本分摊更复杂。

建议：阶段二默认隔离，阶段四按合同可配置打通
3
YCC 与且慢帐号的关系

且慢 App 快捷登录是"用且慢身份登录 YCC"，还是"把且慢用户映射成 YCC 用户"？涉及隐私隔离与合规边界。

建议：且慢仅作为登录方式之一（IdP），YCC 独立用户表，不同步且慢交易数据
4
首个接入产品与时间

是否确认 OAP 作为阶段一唯一接入产品，2026 Q4 完成帐号切换？

建议：是；WealthWork 等在阶段三接入
5
Vesta 是否接入

Vesta 已有免费 / 一、二、三级收费帐号体系与年费共建模式。要不要并入 YCC，还是保留独立。

选项：阶段四评估 / 仅接入登录不接入收费
6
Owner 与团队配置

YCC 是横跨多个产品线的中台能力，需要明确产品 Owner、技术 Owner 与财务 / 合规 reviewer。

建议：AI 平台 / 中台产品团队主责，各产品线出接入 DRI

给业务同学的名词卡

YCCYingmi Commerce Core，盈米商业服务中枢。统一帐号、商品、收银、权益、售后。
2P / 2B2P 个人客户（自助）；2B 机构客户（合同、对公、成员管理）。
OAP盈米 AI 开放平台（Open AI Platform），对外提供 MCP / Skills / Agents，后台为 Stargate。
商品可销售的定义 / 模板：Token 包、MCP 套餐、积分兑换商品。与具体用户无关。
权益个人、机构或合同实际持有的实例：额度、权限、积分余额、有效期、流水。
积分用量计量与支付抵扣的统一单位，属于权益；不可提现、不可转让、有有效期。
统一收银台所有产品共用的支付环节：在线、对公、积分抵扣、组合支付、退款、对帐。
合同订单机构签约产生的订单，对公付款后按合同向机构权益（积分池 / 席位）入帐。
数据隔离且慢 C 端交易与隐私数据不进入 YCC；权益默认按产品与合同隔离。
