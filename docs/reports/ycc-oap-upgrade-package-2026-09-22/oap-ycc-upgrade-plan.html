帐号体系切换方案

目标帐号模型 → 登录方式 → 与 Stargate 的关系 → 存量迁移 → 灰度。

3.1 目标帐号模型（OAP 视角）

YCC 用户 P0
  • user_id
  • 手机号（主身份，唯一）
  • 昵称 / 头像
  • 实名状态（机构成员可选）
  • 状态：正常 / 冻结
身份来源 P0
  • 手机号验证码
  • 微信 OpenID / UnionID
  • 且慢 App（OIDC）
  • 机构邀请口令
  • 一个用户可绑多个来源
机构 / 组织 P0
  • org_id
  • 名称 · 统一社会信用代码
  • 开票信息
  • 合同列表
  • 成员：管理员 / 采购 / 使用人
产品开通关系 P0/P1
  • user / org ↔ 产品 = OAP
  • 套餐类型：免费 / 专业 / 团队 / 企业 / 合同
  • 开通时间 · 到期时间
  • 状态：试用 / 生效 / 到期 / 停用
权益 / 积分帐户 P1
  • 个人帐户 / 机构池 / 成员配额 / 合同帐户
  • 余额 · 冻结 · 有效期
  • 使用范围（产品、工具组）
  • 日 / 月限额
  • 流水
Stargate 凭证 保留
  • API Key → 绑定 user_id / org_id
  • OAuth Client / Consent
  • OpenChannel：identity_provider = ycc
  • Scope / 服务分组不变
一个手机号 = 一个 YCC 用户，可同时是个人客户与某机构成员机构成员的 Key 归属机构，离职停用即回收Stargate 只认 YCC 的 user_id / org_id，不再直接依赖且慢或 yingchat 身份

3.2 登录方式

主
手机号验证码主身份，注册即登录；所有其他方式最终绑定到手机号。
微
微信扫码 / 小程序PC 扫码、移动端一键；首次登录要求绑定手机号完成合并。
且
且慢 App 快捷登录且慢仅作为身份来源之一（IdP），不同步交易与持仓数据；隐私隔离。
机
机构成员邀请口令管理员在机构中心发口令 / 链接，成员用手机号登录后自动加入机构。

3.3 存量用户迁移：三类人，三种路径，Key 都不换

A · 只有 API Key 的老用户

最多的一类：通过申请表 / 官网申请拿到 Key，未走 OAuth
  1. 下次访问官网提示"升级为盈米帐号"，输入手机号验证
  2. 系统按申请时留存的手机号 / 邮箱自动匹配并合并 Key
  3. 匹配不到的走人工核验（口令或申请邮箱）
API Key 保持不变；MCP 配置无需改动

B · 通过且慢 OAuth 登录的用户

在官网 / MCP 客户端用且慢帐号授权过
  1. 双轨期内且慢登录仍可用，登录后引导绑定手机号
  2. 生成 YCC 用户并把 Consent、Key 归属迁移
  3. 双轨结束后且慢仅作为快捷登录方式存在
已授权的 OAuth Client 与 Consent 记录保留

C · 合同机构与成员

山西证券等已签约机构，及 yingchat 身份的机构用户
  1. 运营按合同导入机构、开票信息、合同积分帐户
  2. 指定管理员，管理员邀请成员 / 为成员发口令
  3. 历史积分余额按合同附件一次性入帐并对账确认
合同期、协议价、剩余积分完整继承

04

积分方案

积分 = OAP 用量的统一计量与支付单位；属于 YCC 权益，由 Stargate 计量、YCC 扣减。

4.1 定义与四条原则

积分是用户或机构在 OAP 使用工具、Skills、报告生成等能力时的计量单位，同时可在统一收银台抵扣商品价格。参考换算：10 万积分 = ¥600（即 1 积分 ≈ ¥0.006，示例口径，待定价确认）。

不是货币不可提现、不可转让、不计息；对外表述为"服务额度 / 预付费额度"
有有效期赠送积分短效、购买积分长效、合同积分随合同期
默认按产品与合同隔离OAP 积分只用于 OAP；跨产品打通需配置
每一分都有流水获得、扣减、冻结、退还全部留痕，可对账

4.2 为什么用"积分"而不是"直接按元计费"

  • 与合同先例一致：山西证券合同已按"预充值积分"约定，客户与法务已接受该口径。
  • 与现有计量对齐：库内外部渠道计价表本来就是 credits/工具。
  • 解耦定价与计量：工具成本变了改计价表，不必改合同金额；促销、赠送、兑换更灵活。
  • 对个人更友好：免费额度、加油包、活动赠送都可以用积分表达，降低付费门槛。

4.3 四类积分帐户

2P 个人
个人积分帐户
  • 赠送 + 购买两个分池，分别有效期
  • 使用范围：OAP 全部公开工具
  • 可设月度提醒阈值
2B 机构
机构积分池
  • 来源：合同预充值、对公购买
  • 绑定合同与有效期
  • 管理员可查全池余额与消耗
2B 成员
成员配额
  • 管理员从池中分配
  • 总额度 + 日 / 月限额
  • 成员到期或停用自动回收未用额度
2B 合同
合同积分帐户
  • 一份合同一个帐户，多合同并存
  • 协议价、附件额度、到期日
  • 用于对账、验收、收入确认

4.4 积分从哪里来、到哪里去

获得 五种来源

  • 注册赠送（免费版）· 30 天有效5,000 分
  • 购买加油包 · 12 个月有效100,000 分 / ¥600
  • 套餐月度发放（专业 / 团队版）· 当月有效，不结转按套餐
  • 合同预充值 · 合同期有效按附件
  • 运营发放：活动、邀请、Skill 贡献、补偿 · 30–90 天按规则

消耗 按工具计价，失败不扣

  • 基础查询类工具（基金基础信息、指数行情…）1–2 分 / 次
  • 分析类工具（基金对比、持仓穿透、市场信号…）3–6 分 / 次
  • 帐户与重计算类（持仓收益分析、组合回测…）8–20 分 / 次
  • Skills 报告生成（基金深度分析、财富规划等）50–200 分 / 份
  • 收银台抵扣商品价格按换算比例

扣减顺序：先扣即将过期的、再扣赠送的、最后扣购买的；机构成员先扣成员配额，配额不足按策略拒绝或向池申请。计价表沿用现有工具级 credits 口径，由商品管理维护版本。

4.5 规则细则

规则个人帐户机构池 / 成员配额合同帐户
有效期赠送 30 天；购买 12 个月；套餐当月随合同 / 购买批次；成员配额随成员期限合同期，附件另有约定除外
限额可选日限额（防盗刷）管理员设成员总额度 + 日 / 月限额；池级预警阈值合同总额；超额需加购
超额策略拒绝调用并提示购买；可开自动续购成员：拒绝 / 向管理员申请；池：提醒商务拒绝或按合同约定后付
预扣与结算调用开始预扣（冻结）→ 成功结算 → 失败 / 超时自动解冻；Skills 报告按任务粒度预扣
冻结 / 回收违规使用可冻结成员停用即回收未用配额到池合同终止按约定处理
退还未使用的购买积分按售后规则原路退款对公订单退款需财务审批按合同条款
提醒余额 < 20% / 到期前 7 天池余额 < 20%；成员配额 < 10%到期前 60 / 30 天推商务续约
发票在线订单自助申请电子普票对公订单开 6% 增值税专用发票合同约定：开通 + 联调 + 验收后开票

风险与合规

高 / 中 / 低三级，每条附应对。

高
积分的法律属性与财务处理

预付费积分涉及单用途预付卡、预收款与收入确认口径；表述不当可能被视作虚拟货币。

应对：对外统一表述"服务额度"；不可提现 / 转让；按使用确认收入；法务与财务在阶段二前出具口径。
高
迁移导致存量客户中断

5,500+ 用户与 350+ 机构中，大量 Key 分散在各类 AI 客户端配置里。

应对：Key 不变原则；双轨期 4–6 周；影子期先验证；任一阶段可回滚 IdP 配置。
中
计费争议

正式扣减后客户对"这次为什么扣 8 分"有异议；工具计价与文档不一致。

应对：影子期让用户先看到"预计消耗"；公开工具计价表并版本化；每笔流水可追溯到调用记录（requestId）。
中
且慢隐私与数据隔离

且慢快捷登录可能被误解为打通且慢帐户与持仓数据。

应对：且慢仅作 IdP，只传最小身份字段；YCC 独立用户表；隐私政策与授权页明示。
中
双轨期数据一致性

同一用户在且慢身份与 YCC 身份下产生两份权益或两份 Key 归属。

应对：以手机号为合并键；合并前冻结写操作；每日一致性对账任务。
低
外部渠道计量口径冲突

渠道 credits 与用户积分混记导致重复计费。

应对：渠道结算与用户积分分帐户记帐；market_code 维度独立报表。
