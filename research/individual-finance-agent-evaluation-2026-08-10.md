# 个人理财 Agent 候选作品能力测评

## 结论

**45/100。建议进入带修复任务的有条件复试，不建议仅凭该作品认定候选人可独立负责 C 端金融 Agent 上线。**

候选人的强项是复杂场景拆解、系统骨架搭建与模块组织；弱项集中在生产底线：金融数据语义、答案相关性、安全、移动端、可复现安装和持续集成。

## 评测对象与边界

- 对象：`zaz199110/Individual-finance-management-agent`
- 版本：`master@7f117a1ee47adfd1db64ac4e1b3e4e1939ef50f8`
- 截止：2026-08-10（Asia/Shanghai）
- 环境：macOS，Node 24.3.0，npm 11.4.2，Chromium；无 Docker，不使用候选人的私有模型或数据库凭据。
- 原则：构建通过、页面可打开、函数返回 `ok=true` 都不自动等于场景通过。只有用户目标、关键事实与安全边界同时成立才算有效。

## 方法与覆盖

1. 仓库与 GitHub 元数据审计：分支、提交、CI、License、README、依赖与脚本。
2. 干净安装、生产构建、Vitest 与项目自带 Playwright E2E。
3. 本地 Next 运行与桌面 1440×900、移动 390×844 浏览器走查。
4. 15 条 planner 场景用例；画像、目标和持仓解析边界输入。
5. 三只基金、三类问题的确定性 Agent 问答矩阵：019305、000198、217022 × 费率、业绩/回撤、风险适配。
6. 以盈米 MCP 独立复核 019305 的净值、收益、回撤、费率与风险口径。
7. API、设置、Supabase migration、秘密存储与权限边界审计。

## 关键证据

- `npm run build`：通过。
- Vitest：107 个测试文件；562 条测试中 539 通过、22 失败、1 跳过。
- Playwright：52 条官方 E2E 中 10 通过、30 失败、2 跳过、10 未执行，耗时 15.7 分钟。
- 依赖：899 packages；`npm audit` 为 19 个漏洞（1 low、7 moderate、11 high）。
- README 引用的 `supabase:sync-settings`、`data:init`、`env:bootstrap` 均不在 `package.json`；bootstrap 脚本引用缺失的 `automation/`。
- CI 只监听 `main`，而默认且唯一分支是 `master`；E2E 在 workflow 中被注释。
- 桌面端可用；移动端固定 320px 侧栏把 390px 视口的主区挤成约 70px。
- 基金 lookup 能取得 019305 的 0.50% 管理费，但“管理费多少”最终返回招募书绪言，未给数字。
- 000198 被输出为净值 0.2252、近一年 -15.4%、最大回撤 -59.8%，暴露货币基金指标语义错误。
- 回答出现“用 L0 return_1y”“从风险揭示摘 3 条以内”“依产品类型取舍”等内部模板语。
- Supabase migration 对 `anon` 授予全表读取，未发现 RLS；模型 key、service role 与数据库密码存在明文保存路径。
