# 研究结论

且慢 AI 小顾不是从聊天机器人一路升级，而是把 2021 年已经形成的投顾服务蓝图逐步 AI 化、Agent 化和平台化。其核心演进为：

1. 产品入口：页面找功能 → 对话表达目标 → 主动持续服务。
2. 服务编排：剧本 / 场景 Bot → 总指挥 + 专家 Agent → Skill / MCP / Agent runtime。
3. 能力供给：内部 API → MCP / OpenAPI / Stargate → 可鉴权、可审计、可复用的金融服务资产。
4. 模型：私有化 LLM → 云端多模型 → 按速度、成本、深度与可用性路由。
5. 可信度：大模型自由回答 → RAG 引用 + 确定性工具 + 标准卡片 / 报告 + 人工复核。
6. 经营：对话量 / 调用量 → 成功服务任务、采纳、动作、复用、合规与归因。

# 关键证据

- 2021 产品原型已覆盖投前规划、投后诊断、通知陪伴、财富旅程与账户管理，说明产品骨架早于 LLM。
- 2023.11 方案将小顾定义为在线投资顾问与且慢超级入口，采用主动引导、AI 意图识别、智能服务、智能回复、搜索与人工接力。
- 2023-12-20 至 2024-06-13 的生产导出共有 49,495 条事件、10,461 条用户消息记录、31 个 Bot 标识、2,362 条 TRANSFER_TO_BOT 路由事件。
- 2025 技术方案明确 LangChain、Node.js、服务端实时推送、多元混合模型、30+ AI Agent、数据标注、监控与小样本脚本迭代。
- 2025 产品素材明确 Qwen、DeepSeek-V3、DeepSeek-R1 三类模型选择及深度模型工具可用性限制。
- 2026-08-31 生产审计确认 Stargate 为 Node.js 三进程，MCP 支持 SSE / Streamable HTTP；小顾 3.0 通用渠道 89 工具、卡片渠道 15 工具。

# 证据边界

- Dify 的 20+ Agent / 120+ 节点证据来自共享 AI 图书馆场景，不能外推为小顾全链路都使用 Dify。
- OCR / ASR / TTS、多模态、SFT、GRPO 属于盈米共享 AI 能力栈或路线，不等于小顾已全量上线。
- 1.0—4.0 是能力演进模型，不应误写为对外版本发布时间线。
- 用户量、问题量、解决率、转化率等历史材料存在不同快照和口径，报告不拼接为连续增长曲线。
- 2026.09 的记忆、用户 Skill / 系统 Skill、事件触发、VPC 需求来自产品讨论，仅作为当前问题与目标态。
