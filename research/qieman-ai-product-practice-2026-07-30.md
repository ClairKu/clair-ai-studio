# 盈米 AI 产品实践

> 且慢产品团队

## 一句话结论

盈米 AI 的终极形态不是一个更聪明的聊天入口，也不是一批分散的工具，而是一套由且慢产品团队参与实践和验证的金融服务操作系统：

**AI 开放平台把数据、工具与专家方法变成标准能力；AI 实验室把能力组装、测试、治理并发布成服务；AI 小顾让用户发现、获得并持续使用服务；AI 投顾工作台让专业人员复核、接力和完成高价值交付；服务结果再回流为记忆、质量与经营数据。**

这条链的共同北极星应从“有多少工具、多少次对话”升级为：

**成功金融服务任务数 × 服务复用率 × 结果采纳率 × 合规质量。**

## 01 为什么做：从“拥有能力”转向“完成服务任务”

金融 AI 的瓶颈正在从“模型会不会、工具多不多”转向：能否把专业能力组织成用户愿意授权、能够持续使用、最终产生结果的金融服务。

因此，四个产品不应分别优化工具数、调用量或对话量，而要共同围绕“成功金融服务任务”协同：既看任务是否完成，也看服务能否复用、结果是否被采纳、过程是否符合合规与质量要求。

## 02 总体蓝图：主线从“能力”走到服务“结果交付”

报告主线统一为：

**为什么做 → 总体蓝图 → 如何运转 → AI 小顾实践 → AI 投顾工作台 → 多端分发 → 规模验证 → 治理与经营 → 路线图。**

总体蓝图可概括为：

**一个底座、一座工厂、两个终端、一个增长飞轮。**

- 一个底座：盈米 AI 开放平台负责能力供给与治理。
- 一座工厂：AI 实验室负责服务的组装、测试、审核、发布与运营。
- 两个终端：AI 小顾服务投资者，AI 投顾工作台服务顾问与运营。
- 一个增长飞轮：结果、采纳、失败与反馈进入下一次服务。

这张总图承担“系统是什么”的解释；后续章节不再平铺模块，而是逐层展开总图中的能力、产品、交付和结果。

### 核心判断

1. 一个底座：数据、知识、MCP、Skills、Agent 不应在不同产品重复建设。
2. 一个生产层：AI 实验室不是工具列表，而是服务的生产、测试、审核、发布与运营系统。
3. 两个交付端：AI 小顾服务投资者，AI 投顾工作台服务顾问与运营；双方共享授权、任务、报告和结果。
4. 一个闭环：用户获得服务，创作者生产服务，平台治理服务，结果持续回流。

## 03.1 如何运转：五层能力生产线

能力自下而上分为五层：

1. 数据与知识：用户授权数据、资产持仓、市场与基金数据、投研观点、投顾规则、RAG。
2. MCP / Tool / API：标准化查询、计算、分析和业务动作。
3. Skills：将 SOP、规则、脚本、模板和质量检查封装为可复用能力。
4. Agent / Workflow：理解目标、规划步骤、编排能力、调用人工复核并交付结果。
5. 服务与应用：AI 小顾、AI 投顾工作台、AI 实验室应用广场、合作方 Agent 和外部平台。

身份权限、合规、人工确认、版本、质量、计量计费与审计贯穿所有层。

## 03.2 如何运转：四个产品共同完成一个任务

| 产品 | 核心角色 | 主要用户 | 核心指标 |
|---|---|---|---|
| AI 开放平台 | 金融 AI 能力底座与经营平台 | 开发者、机构、内部产品团队 | 有效调用、成功任务、复用、质量、SLA、收入 |
| AI 实验室 | 金融服务生产与发行层 | 业务人员、产品经理、开发者、创作者 | 生产周期、发布数、复用数、活跃创作者、服务效果 |
| AI 小顾 | C 端金融服务入口 | 且慢用户、投资者 | 任务开启与持续率、问题解决率、建议采纳、服务转化 |
| AI 投顾工作台 | 专业复核与高价值交付端 | 顾问、理财经理、运营、投研 | 交付时长、一次通过率、客户覆盖、后续动作完成率 |

## 03.3 如何运转：能力递进与服务产品化

- MCP 解决“能不能准确调用”。
- Skills 解决“能不能稳定交付”。
- Agent 解决“能不能端到端完成复杂任务”。
- AI 实验室解决“能不能把能力生产、治理和发行成用户理解的服务”。
- AI 小顾与 AI 投顾工作台解决“服务能不能进入真实用户任务并产生结果”。

## 04.1 C 端实践：小顾产品升级路线图

小顾不是一个被不断塞入功能的 APP 模块。产品主线先从真实账户痛点建立价值，再扩展复杂问题的解题广度和长期服务深度，最终帮用户完成投资任务；成熟服务随后走出小顾、走出 APP、走出且慢。

### 小顾 1.0—4.0：每一代解决一个核心跃迁

进程：**1.0 基础完成 → 2.0 能力成形 → 3.0 当前建设 → 4.0 终局规划**。这里表达产品能力演进，不等同于对外版本发布时间表。

1. **1.0｜基础完成**：围绕投后用户账户服务解决真实痛点，并向前整合投前规划、向后延伸日常陪伴。
   - 围绕账户、持仓、产品与市场开展服务。
   - 一句话：先把账户服务做成用户真正需要的连续体验。
2. **2.0｜能力成形**：提高大模型在治理边界内的规划与调度权，协调多专家能力解决广度上的多元复杂问题。
   - 总指挥动态规划问题，调度市场、投研、规划等专家 Agent。
   - 通过能力复用降低新场景扩展成本。
   - 一句话：用“总指挥 + 多专家”扩展解题广度和场景效率。
3. **3.0｜当前建设**：解决长期记忆、持续任务与动作执行问题，把一次问答推进为更准确、更有延续性的长期服务。
   - 长期记忆目标、偏好、持仓和历史结果。
   - 建立持续任务、主动触发、动作执行和结果写回。
   - 一句话：让小顾记得住、跟得上，并把服务持续做下去。
4. **4.0｜终局规划**：形成用户服务闭环，从发现需求、生成方案到授权执行与结果反馈，真正帮用户完成投资任务。
   - 生成或匹配所需服务，人机协同完成关键动作。
   - 将运行结果沉淀为下一次服务的上下文。
   - 一句话：不只告诉用户怎么做，而是帮助用户把投资任务做完。

主线是：**1.0 做真实价值 → 2.0 扩解题广度 → 3.0 做服务深度 → 4.0 完成用户任务。**

服务触达需要完成三次跨越：

1. 走出小顾：进入且慢首页、持仓、交易、消息和任务等完整用户旅程。
2. 走出 APP：进入企业 AI、协作工具、机构工作台和其他 Agent。
3. 走出且慢：面向盈米机构客户与生态伙伴交付同一套金融服务。

与此同时，产品服务的生产权也需要完成三次跨越：

1. 走出产研：业务专家、顾问和运营可以组合能力、生产服务。
2. 走出盈米：机构和合作伙伴可以创建、发布并运营自己的服务。
3. 生态共建：用户反馈、运行结果与创作者收益共同推动服务迭代。

最终解决的是能力在不同产品和终端中重复建设、重复封装、交付效率低的问题：

**能力沉淀在 AI 开放平台，服务生产在 AI 实验室完成，通过 AI 小顾、AI 投顾工作台和外部入口一次建设、多端复用。**

## 04.2 C 端实践：从主动服务到服务生态

### 小顾的价值主张与服务范围

小顾的目标不是回答更多问题，而是让普通投资者随时获得可信、个性化、有温度的专业服务：

1. 7×24 小时陪伴：围绕账户、产品、市场和长期目标，随时提供解释与下一步。
2. 个性化、有温度：结合持仓、计划、风险偏好、投资行为和服务记忆。
3. 解决多元复杂问题：按需调度专家 Agent、MCP 与 Skills，不把复杂工具暴露给用户。
4. 准确的数据卡片：以标准组件承载事实、图表、结论和动作，使内容可读、可复核。

服务范围分为三组：

- 投资规划与产品咨询：家庭财务规划、投资规划、产品推荐、诊断、对比、筛选和基金经理分析。
- 账户分析与投后服务：收益、资金流、资产、行业分布、账户诊断、交易提醒、投顾陪伴内容、报告与待办。
- 市场动态：市场温度、指数估值、行业观点、热点资讯、每日陪伴和事件解读。

### 第一幕：AI 小顾基于持仓与服务记忆主动发现问题

整个演示沿用且慢小顾手机端，而不是把能力呈现为 PC 操作后台。用户进入小顾时不需要先提问；小顾在授权范围内读取持仓、长赢计划、定投任务、风险偏好、关注基金和提醒偏好，主动筛选“此刻与本人真正有关的投资问题”。

演示使用小顾历史真实问题类型作为原型，包括：

- 市场下跌时，长赢计划是否需要调仓或继续定投；
- 自动跟车失败的原因、影响和下一步处理；
- 持仓的资产分布、风险等级、集中度与配置问题；
- 基金阶段收益、同类排名与基金经理季报变化；
- 指数估值处于偏低、合理还是偏高区域。

数值采用脱敏示意，不作为当前用户、当前行情或已上线功能证明。

### 第二幕：延伸追问把行情解释变成个人行动判断

用户可继续追问“为什么我的组合比沪深300跌得少”“是否还要继续定投”“当前最大风险在哪里”。小顾结合用户真实持仓结构、计划规则和风险偏好，先给出“无需动作、继续观察或需要处理”的结论，再通过资产配置、持仓诊断、阶段收益和同类比较卡片解释原因。

经用户确认后，小顾把新的关注点和解释偏好写回记忆，例如：

- 普通波动不需要频繁提醒；
- 优先给行动结论，再解释资产结构；
- 重点关注权益集中、基金风格漂移和任务失败。

由此形成闭环：

**读取持仓与记忆 → 主动发现相关问题 → 个性化解释 → 用户追问 → 更新记忆 → 生成服务 → 持续运行。**

### 第三幕：对话生成与进阶创建都保持手机端体验

简单问题由小顾直接生成服务。例如用户说：“以后大跌时，不要只告诉我跌了多少，请结合我的长赢计划直接告诉我要不要行动。”小顾自动生成“长赢行动提醒”，抽取触发条件、授权数据、回复规则和记忆策略，用户确认后即可固化。

复杂问题继续进入 AI 实验室能力，但用户侧仍表现为小顾手机端的“进阶创建服务”。例如创建“我的基金周报”，系统自动匹配持仓查询、阶段收益、同类排名、季报解读和估值温度等能力；用户确认运行周期、提前触发、回复方式、触达偏好与数据授权。

底层 Prompt、MCP、Skills、Agent、异常处理和治理规则由 AI 实验室完成。普通用户只需要理解“什么时候运行、读取什么、告诉我什么”；进阶用户再按需展开工具与 Prompt 详情。用户也可以直接从手机端新建一个金融服务。

### 第四幕：同一个服务可以交付为多种产品形态

金融服务不是单一页面或文件，而是以下对象的统一抽象：

1. 服务卡片组件：嵌入小顾对话、首页或 AI 投顾工作台。
2. 一组服务：围绕一个目标组织多个持续服务。
3. 一份报告：沉淀事实、图表、判断、动作和证据版本。
4. 一个任务设置：定义触发时间、数据、能力和触达方式。
5. 一次运行结果：保留输入、调用、输出、复核与反馈。

这些形态都可以被收藏保存、固化为自定义服务、持续运行、修改版本，并在通过质量与合规审核后发布。

### 第五幕：应用广场形成服务生态

用户可以在“小顾服务广场”把自己创建的服务发布给其他人，其他用户能够发现、启用、评价和反馈；用户也可以直接使用投顾团队、研究员、机构或其他用户发布的基金季报追踪、估值温度提醒和持仓诊断等服务。

服务使用中的采纳、修改、失败原因和结果继续回流，推动服务版本、能力质量和推荐机制进化。整套生态由盈米 AI 开放平台统一提供金融数据、MCP / API、Skills、Agent、模型、知识与信任控制。

> 以上为目标形态的交互概念原型，用于定义产品闭环，不代表所有功能已经上线。

### 面向AI的标准化可复用服务组件

资产分布、风险诊断、基金业绩、收益日历、估值温度、资讯和任务提醒，共用“数据—图表—结论—动作”的服务契约，并被封装成 AI 可调用、跨端可复用、过程可审计的标准服务组件。

卡片不是单纯的视觉组件，而是服务资产：

- 对用户：在小顾手机端获得清晰、可信、可行动的专业内容。
- 对产品：同一个服务组件可以嵌入首页、对话、报告和任务结果。
- 对平台：输入、数据来源、计算、结论、动作和版本可以被测试、复用和审计。

## 05 A 端实践：从使用系统到调用服务能力

顾问在 AI 投顾工作台，或在企业 AI 助手、飞书、其他 AI Agent 中输入意图：

**“帮林先生一家生成一份完整的财务规划。”**

系统先完成调用身份、机构权限、客户授权、能力范围和合规边界的校验。鉴权通过后，Agent 自动依照盈米顾问服务规范完成标准任务：

1. 获取客户家庭成员、资产负债、收入支出、账户持仓与目标。
2. 解析历史沟通记录，识别诉求、偏好、承诺、疑问和未决事项。
3. 判断完成规划所需的信息是否齐备；仅在存在关键缺口时，引导顾问补充必要信息。
4. 调用现金流、保障、教育、养老、投资和压力测试等规划能力。
5. 生成包含事实、诊断、目标、方案、行动计划与风险揭示的完整财务规划报告。
6. 通过数据完整性、计算复核、表述边界、版本和审计等质量与合规检查。

AI 完成标准化工作，但不取代顾问责任。报告进入顾问复核环节后，顾问可以编辑修订、调整建议、保留修改记录，再发送给客户或进入对客宣讲模式；客户反馈和需求变化会继续驱动方案调整。

### 产品重心的变化

过去以“系统”为中心：一套系统承载数据、功能、流程、表单和操作界面；只有进入特定系统，才能使用特定能力。

现在以“能力”为中心：顾问 SOP、计算方法、Prompt、报告模板、质量门和合规规则被封装为可鉴权、可调用、可编排、可审计的服务能力。因此不用先搭一整套系统，也能在不同 AI 入口中获得一致的专业交付。

### 顾问报告 Skill：两条入口，一套标准化生产能力

内部专项材料《顾问报告 Skill 工具介绍》给出了从当前实践到 AI 投顾工作台的实现路径：

1. **Agent 对话发起（材料标注“已上线”）**：既可以在顾问授权后通过 MCP 拉取并解析 SCRM 对话记录，也可以上传已经整理好的客户事实表或访谈纪要。两条路径只在事实数据来源上不同，后续都进入“AI 校验补全 → Skill 生成 → 顾问修订 → 在线交付与讲解”。
2. **AI 投顾工作台直接生成（下一阶段规划）**：日常沟通持续更新客户画像，生成时叠加账户与持仓接口数据；顾问选定客户后直接调用 Skill，报告统一进入文档中心，完成版本留痕、复核、发送、下载和后续任务。

顾问报告 Skill 不是一段 Prompt，而是三层可执行标准：

- 确定性脚本：财务指标、目标测算与资产配置规则由脚本执行，保障关键数字准确。
- 大模型叙述：把结构化事实转成家庭化解读，支持顾问追问、改写与确认。
- 报告模板：统一结构、品牌与合规口径，保证跨 Agent、跨入口交付稳定。

材料中的财务规划报告 V1 已展示“上传客户数据 → 生成家庭资产分析规划报告”的实际效果。效率快照显示，包含信息整理、报告生成、顾问修订与发布在线链接在内的单份报告制作，由人工约 1 天压缩至 AI + 人工 1～2 小时，对应 4～8 倍效率提升、预计节省 75%～85% 制作时间。该数字为经验估算，仍需试点校准，不能视为实时后台指标。

下一阶段三类报告 Skill 为 V2 财务规划报告、持仓分析报告和投资规划报告。AI 投顾工作台进一步将“生成好的报告”升级为“可持续运营的服务资产”：

**多入口生成 → 文档中心归集 → 修订与复核 → 发送 / 下载 → 反馈与任务 → 客户服务时间线。**

### AI 投顾工作台与 AI 小顾使用同一套产品逻辑

**理解意图 → 身份鉴权与上下文 → 编排能力 → 人机确认 → 结果交付 → 反馈回流 → 再造服务。**

- AI 小顾从用户目标与记忆出发，主动提供持续服务。
- AI 投顾工作台从顾问意图与客户上下文出发，完成标准专业任务。
- 两者的差异在服务对象、专业责任和交付界面，底层能力体系与服务闭环一致。

盈米在提供通用能力和最佳实践、解决主要痛点的同时，也允许顾问基于现有能力调整 Prompt、规则、流程、报告模板和触发方式，扩展并再造符合自己客户群与服务方法的顾问服务。

> “林先生家庭财务规划”是目标产品概念演示，不使用真实客户数据，不代表当前功能、合规审批或商业状态。

## 06 多端分发：走出且慢，在各大 AI 平台交付服务

小顾走出且慢，不是把一个聊天窗口复制到其他平台，而是让且慢的专业金融服务在用户提出问题的地方被发现、调用和承接。用户可以在千问、微信或其他 AI 平台直接发起投资问题；外部 Agent 识别任务后路由至且慢金融 Skills，在用户完成身份绑定和最小范围授权后，调用本人的且慢账户数据完成个性化服务。

合作模式分为四层：

1. 意图识别与路由：外部 Agent 识别市场、持仓、配置、产品或交易问题，路由至对应且慢 Skill。
2. 身份绑定与数据授权：用户绑定且慢账号，按用途授权账户、持仓、交易等字段，授权可查看、可撤回、可审计。
3. 专业服务原位交付：资产全景梳理、E 账户分析、财务诊断、资金与资产规划等结果直接返回当前对话。
4. 小程序承接与联合经营：涉及开户、交易、产品购买或长期陪伴时，由且慢小程序 / APP 承接并完成用户确认。

三类平台对应三种接入范式：

1. **微信｜Skills + 小程序**：微信 Agent 识别投资问题或购买意图，且慢 Skills 提供专业判断，小程序承接身份、账户、交易和持续陪伴。
2. **千问｜MCP + A2A**：
   - MCP 模式让千问 Agent 直接调用盈米标准金融数据、工具与 Skills；
   - A2A 模式把且慢小顾作为完整 Agent 嵌入千问，保留记忆、能力编排和持续服务。
3. **百度｜MCP 历史接入与再升级机会**：项目材料记录，2025 年百度 AI 搜索曾接入盈米 MCP，后下架并替换为自有服务；2026 年拟重新对接并升级。此项为历史与合作意向，不代表当前已上线。

千问 Demo 展示一条完整的个人金融服务链：

**外部提问 → MCP 能力调用 / A2A 小顾服务 → 绑定且慢账号 → 授权本人账户数据 → 金融资产全景 → E 账户分析 → 财务诊断 → 资产规划 → 产品方案 → 且慢承接。**

微信 Demo 展示两种入口：

- 用户在微信 Agent 中问到投资问题，Agent 自动路由调用且慢金融 Skills；
- 用户表达明确购买意图后，Agent 打开且慢投顾小程序，由用户完成账户选择、风险适配和下单确认。

这条链路的业务价值不只是扩大服务触达，更重要的是形成新的获客来源：

**外部问题流量 → 服务价值建立信任 → 用户授权与账号绑定 → 完成一次个性服务 → 产品匹配与下单转化 → 持续服务关系。**

建议以渠道新增、账号绑定率、授权完成率、服务完成率、下单转化率和持续服务率衡量。没有已确认的真实统计口径前，不展示推算数字。

数据与交易边界必须保持清晰：

- 服务走出且慢，用户对本人且慢数据的使用权不变；
- 外部 AI 平台不直接获得且慢账户数据；
- 且慢只在用户明确授权的身份、字段、用途与期限内调用；
- 交易与高风险动作必须回到且慢小程序或 APP，由用户本人确认。


## 07.1 规模验证：三端业务结果

第二张总图放在两段产品演示之后，用来收束“同一套能力为什么值得统一建设”：

- C 端：从问答升级为记得用户、主动触发、持续跟进、有结果的服务。
- A 端：把专家方法、计算规则和报告模板复制给每位顾问，同时保留人工判断。
- B 端：把金融能力以 MCP、Skills、Agent 和服务形态嵌入机构系统。

这三端不是分别建设三套 AI。统一的能力资产、服务标准和信任控制，使不同入口可以产生差异化结果；供给侧则让内部专家、业务团队与生态伙伴持续生产和运营服务。

## 08.1 治理与经营：统一控制面与指标

每个服务至少包含：owner、版本、适用人群、权限范围、数据依赖、能力依赖、质量门槛、人工确认、SLA、下线机制和结果指标。

共同经营看板建议分为四层：

1. 供给：正式能力、通过质量门的服务、活跃创作者。
2. 使用：启用用户、周期任务、有效调用、服务复用。
3. 结果：问题解决、建议采纳、后续动作、成功任务。
4. 信任：失败率、人工退回、合规命中、授权撤回、投诉与事故。

## 08.2 治理与经营：从能力调用到共同经营

合作深度应随着对方成熟度递进：

1. 能力调用：以 MCP、API、Skills、开发文档、配额和监控快速验证金融能力价值。
2. 场景共建（推荐）：围绕基金诊断、智能投顾、投研、客服等真实任务，共同封装业务 SOP、专属 Skill / Agent，并设置效果评估与 HITL。
3. 平台集成：嵌入机构工作台、AI 平台或员工助手，完成身份权限、专属渠道、审计、计量和 SLA。
4. 联合运营：内容、陪伴、活动和转化协同经营，形成用户运营、场景增长与商业化分成或共建。

对应的成熟度路径是：

**验证能力价值 → 共建真实场景 → 嵌入业务入口 → 联合经营结果。**

## 09 路线图：从种子服务走向增长与商业闭环

七项工作不是并列清单，而是一条前后依赖的经营链：

1. **AI 基础能力｜权限体系升级**：先建立最小权限、分级授权与可撤回机制，平台才敢连接更多人和更多数据。
2. **AI 能力治理**：统一分类、三层能力管理和质量把关，让每次开放都可控、可测、可追责。
3. **AI 实验室**：让业务方组装、测试、发布和复用能力，把服务生产权从产研扩展到生态。
4. **AI 解决方案输出**：以 Agent 封装数据、工具、流程和行业方法，把分散能力变成客户愿意采购的业务结果。
5. **AI 能力持续上架主流平台**：把金融能力放到用户已经在用的 AI 入口，建立持续可发现、可调用、可更新的分发网络。
6. **AI 接入 C 端大流量平台**：从等用户进入 APP，转为在外部问题现场完成服务、授权与回流转化。
7. **AI 商业化进程**：用积分连接使用与贡献，用个人订阅和机构采购方案连接收入与规模化经营。

这条链的关系是：

**权限与治理解决“敢不敢开放” → 实验室解决“谁来生产、如何复用” → Agent 解决“如何变成业务结果” → 主流平台与 C 端入口解决“如何被发现” → 积分、激励和采购方案解决“供给如何持续、价值如何回收”。**

核心判断：开放平台下一阶段的目标不是“能力更多”，而是“高质量能力更快变成服务、流量和收入”。

### 现在：先立控制面，跑通种子 Agent

完成权限分级、授权撤回、统一分类、三层治理与质量门，以一个真实金融任务验证从授权到交付的完整闭环。

### 接下来：形成生产与分发双轮

让 AI 实验室的组装、测试、发布和复用标准化；连续上架主流 AI 平台，并打通 C 端授权、服务、回流和转化指标。

### 之后：启动商业化与生态经营

建立积分、贡献与用户激励体系，推出个人订阅与机构采购方案，并配套计量、分成、SLA 和联合运营。
