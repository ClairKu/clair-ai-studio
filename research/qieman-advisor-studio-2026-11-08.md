# 且慢顾问工作台｜Qieman Advisor Studio

发布日期：2026-11-08

生产入口：`https://clairku.github.io/clair-ai-studio/reports/qieman-advisor-studio-2026-11-08/`

## 中心判断

Qieman Advisor Studio 不是给 CRM 增加聊天入口，而是以“服务事项（Service Case）”为工作单位，把客户状态、机构方法、受控动作与结果回流连接成一套持续运行的顾问工作系统。YingWork 提供 Agent 运行时、模型与工具、记忆、连接器、权限和审计底座；且慢工作台负责定义顾问服务方法、客户状态和责任边界。

## 公开内容边界

- 公开产品型态、目标态能力、虚拟演示画面与方法论判断。
- 不公开企微原始文件、真实客户数据、内部人员分工和系统凭据。
- 不使用缺少统一业务基线和生产验证的自动承接率、效率提升数字。
- V1.7 画面明确标注为概念原型，不代表真实数据连接、模型效果、权限和生产上线状态。

## 沉淀方案

1. 产品介绍统一围绕“工作单位—产品型态—端到端闭环—责任边界—价值验证”组织，避免罗列菜单。
2. 用“静态页面承载事实、动态 AI 承载意图、后台 Agent 持续运行”解释混合态交互。
3. 用“事件—状态—工作流—服务事项—顾问确认—结果回流”作为各场景的统一产品骨架。
4. 将 MCP、Skill 与 Agent Runtime 分层表达：连接、方法、编排与责任不能混为一谈。
5. 后续先验证资金异动、适当性临期、定期检视/投后报告三条穿透式闭环，再扩功能广度。
