# 盈米 AI 开放平台 8·3 项目汇报：研究源稿

> 本源稿按飞书汇报文档《8/3 盈米AI開项平台项目汇报》（wiki ELoLwjzXmidhs6kscvbczByYnod，revision 1934）的框架与内容整理，供 Clair Executive Visual Report 渲染。源稿大纲：年度目标 · 关键举措 · 用户增长 · 新流量入口 · 产品规划 · 能力建设 · AI 实验室 · 商化准备 · 行业机会 · 问题回顾。

## 一句话结论

申请用户 8,569、月活 1,812 逼近年度目标，累计调用 919 万冲向千万关口；微信、千问两大超级入口接通，平台从能力开放走向多端交付与商业验证。

### P2 关键举措

- 两类接入模式・放大势能：大厂 AI「平台」、C 端流量平台「产品」。
- 四个持续举措，抓新机会：持续建设、持续抢先、持续合作、持续曝光。
  - 持续建设：MCP、Skills、Agent。
  - 持续抢先：首个财富 MCP Server、首个理财测评集 / 投顾智能立体模型、首个投顾龙虾 OpenClaw、首批千问 MCP / A2A 接入合作商、首批微信 AI 接入合作方。
  - 持续合作：阿里云 / 百炼、百度、火山引擎 / 扣子、华为 / 小艺、夸克 / 千问、腾讯 / 微信 / WorkBuddy、智谱、金融机构。
  - 持续曝光：自家平台公众号文章视频 50+、阅读 3 万+、全网渠道发布 300+ 篇；全网媒体盈米 AI 相关报道 8,965 篇（其中盈米 MCP 3,329 篇）、全网互动超 300 万、浏览超 1,000 万；活动 10 场+、交流机构 30 家+。

  - MCP 模式：在千问 Agent 中调用盈米 Skills / MCP / Agent；同时推进盈米 MCP 在千问 PC 端—连接广场的展示，提升对千问场景的覆盖和品牌露出。
  - A2A 模式：在千问使用盈米且慢小顾 Agent。成功入围千问首批合作的第三方品牌智能体，预计且慢 AI 小顾是一期唯一接入的金融 Agent，双方预计 8 月 10 日完成联合宣发。本次合作意味着盈米 AI 能力首次成功切入 AI 时代的超级流量入口，并在产品形态上实现了「新用户获取 → AI 服务 → 外链完成交易」的流量转化闭环。

## 2. 产品规划

### 能力体系

- P7 分类框架：新分类体系采用「三维分类」——业务域、能力类型、权限和生命周期。将来增加新的能力、或者新的类型的资产（如知识库）时，不需要重新推翻分类，可直接纳入管理。
- P8 能力建设与治理（MCP、SKILL、AGENT；资产治理多维表格：盈米AI开放平台资产治理）：
  - MCP：已对外的接口——已梳理当前 OAP 对外接口存在的问题，并提交给到老吴团队专人对接各接口提供方修复（附件：盈米MCP质量审计报告.md）；规划新增开放的 MCP——10 个持仓类的 MCP，但是鉴权方式需要走登录授权，需要同步开发。
  - SKILL：下一步的迭代围绕 MCP 的迭代进行，不追求数量，需要对先前一批的 Skills 做收敛和精细化修改，优化第三方平台在调用盈米 MCP 的准确性与调用质量；正在开始多个来源的 Skills 也做统一化管理，逐步把散落在各个 BU 或者产品的 Skills 纳入 Stargate 的治理体系。
  - AGENT：老吴团队正在搭建盈米自有的 Agent runtime，盈米内部搭建的 Agent 也会基于这一体系，治理与调试通过 Stargate 和 AI marketplace 或者盈米 AI 实验室来承接；未来还会有很多基于第三方平台的 Agent runtime 搭建 Agent 的场景，所以更重要的是保持 Skills＋MCP 能力矩阵的模块化管理和精细化设计。
- P9 内外部能力接入：
  - 内部-薛老师团队：财报 MCP 已纳入 OAP 的规划，先支持盈米内部员工通过 OAP 调用相关能力。
  - 内部-投研 Vesta 团队：先前与 Vesta 团队同步了后续 OAP 的商业化模式，7.21 反馈其内部还在规划中。
  - 外部-火富牛私募数据：评估合作接入进展。7.28 反馈与火富牛 MCP 合作模式有调整，正在与合规沟通，待同步沟通结论。

### 系统建设

- P10 系统关系图（Stargate 管理后台、Agent/Skills 平台、官网……）：源稿插图。
- P11 服务关系图（AI 开放平台、AI 实验室、AI 小顾、AI 工作台……）：源稿插图。
- P12 关键能力建设：身份鉴权（OAuth/SSO）、账号体系、合规审计、上架渠道管理、计量计费、数据统计……
  - 账号体系：OAP 官网目前还是基于且慢的账号体系，8 月拟新增 SSO 登录，支持盈米员工也可以在第三方 AI 平台调用更丰富的盈米的 AI 能力。
  - 身份鉴权：先前的 MCP 都是通过 API Key 的方式，不好追溯。规划是短期先是 API＋OAuth 两种方式共存，逐步过渡到 OAuth 形式，方便追溯每次调用对应的平台、客户端、用户、Scope 和 MCP。
  - 合规审计、上架渠道管理、计量计费、数据统计：由 Stargate 来承接。当前 Stargate 功能还不够完整，已开始推进相关能力的迭代完善，支持授权查询、撤销、调用审计和异常排查，形成统一、可下钻的接入治理看板。
  - Stargate MCP OAuth 接入治理 PRD：wiki.yingmi-inc.com/x/PIZwEw；设计：stargate-oap.lovable.app。
- P13 下一步：AI 实验室
  - 为什么做：1）提高金融服务生产效率，AI 产品建设需要这些面向 AI 的能力与工具储备。2）AI 小顾、且慢如何破圈的问题（2025 年 2 月）：肖总永哥在 AI 会上提出，希望找到破圈办法，因此有了实验室的最初想法（当时 MCP 还没盛行），然后 MCP 协议火了后，开启了一系列 AI 开放平台能力建设。
  - 最初思路：单场景破圈速度有限，希望集众人之力，想在且慢小顾上做个全民 AI，有点像豆包这样的工具集场域，不仅快速放上基于新推理模型做出来的工具 / 服务场景，也放公司员工竞赛成果、甚至让用户可自主去探索、发布、分享自己的场景服务 / 智能体。
  - 优势：可以在模型上，集成用户自身数据、平台数据、投顾工具 API 接口等能力，快速落地各式各样的场景服务，提升大众用户参与感。目的：1）吸引用户，让用户能用上推理模型在金融投资场景，参与到 AI 热潮中；2）规避风险，与用户也做好约定告知，明确是个探索的实验室场域；3）集结大家力量去找到破圈点。
  - 初步规划：后续和 OAP 官网结合在一起，支持创作类的用户通过低代码的方式搭建自己的 AI 应用，并把搭建好的 AI 应用快速便捷地分发到自己的工作环境（小顾也有可能是其中的一个）。并参考电商的方式，区分使用和创作两种界面形态。
  - 初版设计：yingmi-ai-hub.lovable.app（还在持续设计中）。商业模式：能力调用＋AI 资产交易。

## 4. 往外看：行业需求、竞品

- 金融机构需求：金融机构使用情况——400+ 金融机构，分布广泛，展示知名的金融机构名称，高亮用量靠前的几家（附件：Stargate 平台金融机构使用统计 · 2026-08-02，HTML / PDF）。交流咨询机构。机构需求：Agent 模式输出。
- 竞品分析——定位：可信的金融 AI 服务基础设施。不是更多工具的集合，而是把合规能力变成可被 Agent 安全调用、稳定交付和持续经营的系统。
  - 买方投顾与账户服务闭环：从公开信息到授权后的个人化服务。
  - 统一控制面：开放、授权、审计、计量、结算在同一资产体系。
  - 持续服务飞轮：小顾发现问题，实验室验证，OAP 沉淀，渠道规模化，结果再回流。

## 5. 向内看：问题回顾

- 技术：AI 协议与技术框架更迭快，需要频繁升级，及多套兼容问题（SSE→HTTP，APIKey→OAuth）。
- 资源：复合人选难招，产品持续补位商务运营；技术团队转移、跨多 BU 多团队分工分界与稳定资源。
- 用户：MCP 质量问题跟进、用户需求跟进、市场行业内大量机构沟通交流需求。
- 数据：金融数据采购 / 联盟合作评估（股票、财报、私募、海外等数据）。
