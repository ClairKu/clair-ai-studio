# 长赢同路人小组详情页双版评审

## 结论

**有条件通过右版方向，但不能直接定稿。**

右版把“组长、加入条件、内容预览”拆成独立层级，阅读、信任感和后续扩展性明显优于左版；左版仅在首屏紧凑度上占优。建议采用右版的信息架构，再压缩约 80–120 px 的首屏高度，形成“右版分层 + 左版效率”的混合方案。

设计锁定前需补齐两项 P0：

1. 明确“加入小组”的资格判断、协议有效性、加入成功/失败和退出后的状态机；
2. 不得用省略号或“查看更多”隐藏影响加入资格的必要条件，并确保资格、协议与客服均可追溯。

## 证据范围

- 已确认：仅基于 2026-07-30 提供的一张左右双版视觉稿。
- 可观察：页面包含小组信息、组长、加入条件、成员内容预览、底部“联系助理 / 加入小组”操作。
- 推断：该页面可能以有效投顾服务关系作为小组内容权限条件。
- 未验证：PRD、完整交互原型、加入接口、协议状态、埋点、客服后台、异常流程及合规意见。

## 双版判断

| 维度 | 左版 | 右版 | 结论 |
|---|---|---|---|
| 信息层级 | 组长与须知挤在渐变区 | 独立白卡，结构清楚 | 右版胜 |
| 可读性 | 低对比灰字、描边弱 | 黑白层级稳定 | 右版胜 |
| 首屏效率 | 更紧凑，内容更早出现 | 页面头部过长 | 左版胜 |
| 信任与服务感 | 像附属说明 | 更像正式服务说明 | 右版胜 |
| 扩展性 | 条件变多后拥挤 | 可容纳更多状态与条款 | 右版胜 |
| 转化语义 | CTA 与条件关系弱 | 有预览提示，但仍未闭环 | 两版均需补 |

## 阻断项与重要问题

| 优先级 | 问题 | 影响 | 建议改法 |
|---|---|---|---|
| P0 | “加入小组”缺少资格与协议状态机 | 无法研发、测试或客服追溯；可能让用户误解为普通社区加入 | 定义未登录、符合资格、未签/失效、校验中、加入成功、接口失败、已加入、退出/解约等状态 |
| P0 | 必要条件被截断在“查看更多”后 | 用户点击前无法获知完整门槛；高风险信息披露太晚 | 影响资格的条件首屏完整展示；“查看更多”只承载解释性细则 |
| P1 | “满足任一条件”但画面仅显示一条 | 规则表达自相矛盾 | 若只有一条改为“加入小组需同时满足”；若有多条，显示数量并完整列出 |
| P1 | 组长名称不一致：左版“E大”，右版“ETF拯救世界” | 用户无法确认服务主体；客服和内容署名可能不一致 | 确定唯一主显示名，另一名称作为别名，例如“ETF拯救世界（E大）” |
| P1 | 右版首屏过长 | 首条内容图片和价值证明被推到第二屏，预览吸引力下降 | 合并为一个紧凑白卡；默认展示一行条件摘要，卡片总高控制在约 180–220 px |
| P1 | “加入后解锁全部精彩内容”承诺过满 | 若内容还有策略、权限或服务状态限制，会造成投诉 | 改为“加入后可查看该小组向成员开放的内容” |
| P1 | 不符合资格用户仍看到“加入小组” | 可能诱导为了内容权益去购买投顾服务，混淆内容与交易/服务决策 | 未满足资格时主按钮改为“查看加入条件”或“了解投顾服务”，并走独立适当性与风险披露流程 |
| P2 | 灰色分段控件像禁用态 | 降低可点击感与可发现性 | 强化选中态底色、字重与焦点；滚动后吸顶 |
| P2 | “联系助理”图标和文字过弱 | 用户遇到资格异常时难以恢复 | 提升触控区与对比度，并带入具体失败原因 |

## 推荐混合方案

1. 保留右版白底分层。
2. 把“组长”和“加入条件”合并为一个紧凑卡片：组长一行、分隔线、条件摘要两行。
3. 条件少时全部展开；条件多时显示“共 3 项”，但所有必要条件在点击加入前必须可见。
4. 使用一条浅色提示说明公开预览范围，不占用完整卡片高度。
5. 分类标签滚动后吸顶；底部操作栏固定。
6. 主按钮随资格状态变化，不允许所有用户固定显示同一“加入小组”。

建议首屏顺序：

`小组身份与数据 → 组长/加入条件 → 公开预览说明 → 吸顶分类 → 首条内容 → 固定操作栏`

## 可直接替换的文案

### 条件卡

**加入条件**

正在跟投「思远定投全球好资产」，且投顾服务协议处于有效状态。

若确有多条互斥条件：

**满足以下任一条件即可加入（共 2 项）**

### 预览提示

你正在浏览公开内容。加入后可查看该小组向成员开放的帖子、直播、课程、工具和策略。

### 主按钮状态

| 用户状态 | 主按钮 |
|---|---|
| 未登录 | 登录后查看资格 |
| 符合资格、未加入 | 加入小组 |
| 服务有效但协议待签 | 去签署协议 |
| 不符合资格 | 查看加入条件 |
| 校验中 | 正在检查资格… |
| 已加入 | 进入小组 |
| 校验失败 | 重新检查 |

## 验收标准

1. Given 用户已登录、投顾服务和协议均有效，When 点击“加入小组”，Then 创建成员关系、解锁成员内容、按钮切换为“进入小组”，And 后台可查询资格快照、协议版本、确认时间与结果。
2. Given 用户不符合资格，When 进入页面，Then 不直接显示可执行的“加入小组”，And 完整告知缺失条件与下一步，不以内容权益替代适当性说明。
3. Given 协议失效或已撤销，When 用户尝试加入，Then 保持公开预览状态并解释原因，And 可联系助理且带入失败原因。
4. Given 加入接口超时或失败，When 用户点击主按钮，Then 不做乐观解锁，And 提供重试与客服恢复路径。
5. Given 用户已经加入，When 再次打开页面，Then 直接显示“进入小组”，And 不重复创建成员关系。
6. Given 条件或协议版本发生变化，When 用户再次加入或恢复资格，Then 系统使用当前有效规则判断，And 历史判断仍可追溯。

## 指标建议

- 核心指标：符合资格用户的加入成功率。
- 诊断指标：条件查看率、资格校验失败原因、加入接口失败率、公开内容浏览深度、联系助理率。
- 护栏指标：误解/无法加入类客服咨询率、加入后 7 日退出率、协议或资格相关投诉率。
- 当前截图未提供基线、目标、数据源与 Owner，需在上线评审中补齐。

## 最终建议

视觉上选择右版，产品上采用压缩后的混合方案。完成 P0 状态机与资格披露闭环后，再进入设计锁定；否则这仍是一张“更清楚的静态页面”，不是可上线的加入流程。
