## 1. 产品目标

看板只回答一个日常运营问题：千问接入上线后，有多少账号成功建立千问—且慢映射，其中多少是既有且慢账号，多少是在接入后新注册；增长脉冲是否仍在延续。

## 3. 口径裁定

- 成功映射账号：上线节点后成功建立千问身份与且慢账号映射的去重账号数。
- 接入后新注册：且慢注册时间不早于上线节点的映射账号；包含静默注册，不等于已激活、回访、签约或交易。
- 绑定既有且慢账号：且慢注册时间早于上线节点，之后通过千问完成身份映射。
- 当前不能计算完整“千问引流转化率”：缺少千问侧曝光、进入智能体、绑定失败等上游分母。

建议对外表述：千问上线以来成功建立千问—且慢账号映射 1,065 个，其中 756 个为接入后新注册且慢账号、309 个为绑定既有且慢账号。

## 5. 看板结构

1. 核心映射总数与新老账号构成。
2. 每日新增柱形与累计映射曲线。
3. 去重、关联、缺失、边界四项数据健康度。
4. 指标合同与归因边界。
5. 下一阶段的 24 小时激活、7 日回访、服务转化证据缺口。

## 6. 更新架构

公开 GitHub Pages 不直连内部数据库。Clair 的 Mac 安装仅监听回环地址的只读更新器：看板按钮发起固定查询，更新器通过本体获取生产聚合结果，完成闭合校验后再返回页面；其他设备只刷新最近发布快照。

更新器约束：

- 只绑定本机回环地址；
- 只接受指定看板来源和固定请求头；
- 查询内容固定，不接受浏览器传入 SQL；
- 同一时间只允许一个任务，并设置冷却时间；
- 只返回聚合指标与每日趋势；
- 本体凭证留在本机，不进入网页或 Git 仓库。

| 优先级 | 指标 | 成功定义 |

| P0 | 24 小时激活 | 映射后完成首次打开或首次有效服务 |
