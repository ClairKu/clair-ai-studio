## 中心判断

个人电脑新增可见 Token 9,697,625,567，占双设备总可见量 72.1%，是当前主力设备；公司电脑可归因量 3,065,748,642，占 22.8%；Cursor 686,153,337 为账号级数据，没有设备字段，必须单列且只计一次。

## 统一口径

`总调用量 = 新内容 + 复用内容 + 模型生成`

- 新内容：首次处理的输入；Codex/WorkBuddy 从输入中扣除缓存读取后得到。
- 复用内容：cache read / cached input。
- 模型生成：模型输出；reasoning token 是输出子集，不重复相加。
- 本地缺失：表示没有可恢复记录，不按 0 解释。
- 设备归因：只有设备本地日志可归因；账号级接口没有设备字段时放入 `shared`。

个人电脑 Codex 本地可恢复 9,632,909,358，与原截图约 9,670,000,000 的近似累计值相差约 37.09M，覆盖 99.6%。这支持“截图主要对应个人电脑本地历史”的判断，但截图没有设备范围元数据，因此不能据此证明公司电脑数据是否被截图包含。

## 增量同步方案

1. 每台电脑固定一个脱敏 `device_key`，本地采集时保留 `platform + event_id + timestamp`。
2. 设备本地日志按事件 ID 去重后追加；不覆盖历史快照。
3. Cursor 等账号级平台只由一个采集端更新到 `shared`，禁止在每台电脑各加一次。
4. 无时间戳记录进入 `undated`，不伪造日期。
5. 每次发布前复算四个等式：全局 = 设备桶；全局 = 平台桶；逐日 + 无日期 = 全局；共享平台仅出现一次。
