# 盈米 AI 开放平台项目汇报：从能力规模走向可经营的金融 AI 服务

## 一句话结论

OAP 已经跨过“能不能被调用”的验证期：截至 2026-07-31，累计用户 8,560、累计调用 9,194,916、MAU 1,812。调用达到 1,000 万阶段线的 91.9%，达到 1,300 万年末正式 OKR 的 70.7%。下一阶段的主要矛盾已经不是“有没有能力”，而是能否把 69 项正式能力、外部渠道与机构项目治理成一套可授权、可追溯、可计量、可成交的服务体系。

## 建议本次管理层拍板六件事

1. **治理基线**：批准“69 项能力一套资产、5 个 Scope、API Key / OAuth 双轨、全链路审计”的统一基线。
2. **黄金闭环**：H2 只选两条端到端样板——千问品牌 Agent 的“公开信息 → 账号授权 → 账户服务”，微信的“卡片 → 接力页 → 可审计服务完成”。
3. **商业化样板**：个人专业版、机构服务版、平台用量版三类包装先各跑一个付费/签约试点，不以功能清单代替成交验证。
4. **组织机制**：OAP、STARGATE、Agent Platform、AI 实验室、小顾共同使用一张资产台账、一套质量门槛和一个周度发布闸门。
5. **稳定战队**：产品、技术、数据、安全合规、渠道运营和商务形成固定 DRI，解决跨 BU 资源不稳与产品持续跨岗补位。
6. **经营记分牌**：规模指标和价值指标双轨验收；新增任务完成、复用、付费、收入和单位任务成本。

> 上半场证明能力能被调用，下半场必须证明服务能被持续使用、复用和付费。

> 渠道接通只是握手；授权完成、任务交付、结果回流，才叫获客。

> 免费调用验证需求，持续付费验证产品，单位经济性验证生意。

### 1.2 趋势与阶段成果

- 2026-07-21 至 07-31：累计用户增加 1,117（+15.0%），有调用用户增加 630（+14.0%），累计调用增加 165,615（+1.8%）。
- 截至 2026-07-28 的近 30 日：新增用户 1,620、调用 439,950、日均调用用户约 267；近 7 日日均调用用户约 337。
- 能力供给已经从接口集合演进为三层：
  - MCP：标准连接与工具调用；
  - Skills：流程化、可复用的稳定交付；
  - Agents：围绕具体任务形成业务闭环。
- STARGATE 已具备能力目录、发布申请、API 来源/路由/密钥、开放渠道、OAuth 客户端、授权管理、审计等控制面模块。

### 1.3 金融机构使用

证券类机构数据（2026-07-24）：

- 后台原始口径：85 条机构记录、319 名用户、累计调用 28,322 次；
- 完全同名去重：78 个机构标签；
- 用户明细汇总：28,266 次，与后台聚合相差 56 次；
- 前 5 个机构标签贡献约 56.6% 调用，前 10 个贡献约 74.3%，需求已经出现，但集中度高；
- 多个机构标签不标准或重复，正式对外前需完成法定机构名映射。

口径边界：盈米官网截至 2026 年 6 月公开披露“近 400 家机构、累计调用超 860 万次”，代表整体合作覆盖；上述 78 个去重标签只来自后台“证券”分类切片，不能解读为全部金融机构数。

结论：金融机构使用不是“零到一”问题，而是从离散试用转成可识别客户、可归属场景、可承诺 SLA、可形成合同的经营问题。

### 1.4 外部渠道与上架

- 7 月 12 日对外口径曾披露百炼、火山、腾讯、百度 AI 搜索、华为小艺等渠道；本报告将其作为历史披露，要求用渠道台账逐项复核当前可用性。
- **千问 Agent**：开发完成并进入生产，当前处于 Bug 修复、产品体验、服务文案、合规与上线前准备；计划 8/5 起逐步开放、8/10 联合宣发，计划节点不提前写成已完成。
- **千问 MCP**：能力已完成接入；PC“连接广场”仍需以实际可见与可调用验收为准。Agent 承接盈米品牌和完整服务，MCP 承接底层金融能力进入千问生态。
- **微信**：已形成“小程序卡片 + 接力页”的可行服务模式和内测治理准备；候选/内测材料不作为正式上线证据。
- **WorkBuddy**：作为 STARGATE OAuth 统一接入方案的首个平台级验证，目标链路为 `Platform → Client → User → Scope → MCP`。
- **阿里云百炼**：OneKey MCP 上架流程基本完成、处于自测；生产可见与可调用验收前不写“已上架”。
- **山西证券**：基金诊断 MCP 招投标已完成、等待结果，作为 B 端机构商业化验证，不提前写成“已中标/已签约”。

## 2. 产品规划

### 2.1 能力体系

建议新版分类同时回答四个问题：

1. 这是什么资产：MCP / Skill / Agent；
2. 服务什么任务：数据查询、投顾、投研、内容、通用；
3. 谁能使用：平台、客户端、用户、机构、授权范围；
4. 如何经营：质量、调用、成本、收入、复用、业务完成。

当前 69 项正式能力可按五类 Scope 管理：

- `fund:read`
- `strategy:read`
- `portfolio:read`
- `analysis:run`
- `content:generate`

内外部能力接入不应以“接进来”作为完成，而应进入同一套准入：来源合规、身份授权、稳定性、输出质量、成本、日志与退出机制。

新版分类采用三层交叉框架：

1. **资产形态**：MCP 是标准工具，Skill 是口径/流程/输出契约，Agent 是面向用户的任务编排与持续服务；
2. **业务任务**：数据查询、基金研究、组合分析、账户诊断、内容生产、客户陪伴、机构工作台；
3. **经营属性**：公开/授权/内部权限，免费/积分/订阅/机构合同，实验/内测/正式/退役。

能力生命周期统一为：注册 → 评审 → 测试 → 发布 → 运营 → 降级/退役，并由唯一资产 ID 串联 Owner、版本、质量、渠道、用量、成本和收入。

### 2.2 系统建设

建议系统关系：

- **统一控制面**：STARGATE 管理后台，负责服务组、路由、OAuth Client、Scope、用户授权、发布审核、审计与计量；
- **能力生产面**：Agent/Skills 平台、AI 实验室、能力市场、开发者控制台；
- **服务交付面**：OAP 官网、AI 小顾、AI 工作台、千问/微信/百炼/WorkBuddy 等外部渠道；
- **基础供给面**：金融数据、知识研究、模型评估和账户/业务系统。

本期优先级：

- 把 69 项能力统一为唯一资产 ID；
- 保留 API Key，同时增加 OAuth 2.1 + PKCE；
- 完成客户端、用户、Scope、能力、调用日志的全链路追踪；
- 授权撤销后令牌立即失效，并写入系统审计；
- 质量与经营看板统一到同一资产口径；
- 不破坏现有发布审批和 API Key 链路。

六项关键系统能力：身份鉴权（API Key / OAuth / SSO）、账号体系、合规审计、上架渠道管理、计量计费、统一数据统计。

AI 实验室的角色不是另一个工具列表，而是“发现问题、组合能力、验证应用、把可复用结果沉淀回开放平台”的生产环境；小顾和外部 Agent 则负责把能力变成持续服务。

AI 实验室下一步按四步建设：按任务发现 MCP/Skill → 编排输入输出与失败兜底 → 用真实任务集评估正确、时效、合规和成本 → 生成统一资产身份并回流 OAP 多渠道上架。首批黄金任务集建议选择基金诊断、组合分析、市场影响解读、客户陪伴和机构研究助手。

### 2.3 商业化准备

| 包装 | 用户 | 核心价值 | 管理讨论价格带 | 首个验证 |
|---|---|---|---|---|
| 个人版 | 研究者、顾问、专业个人 | 更高额度、专业 Skills、个人空间 | Free ¥0；Pro ¥99/月或 ¥899/年 | 付费转化、30 日复用、续费 |
| 企业版 | 券商、银行、财富机构 | 专属能力、团队管理、审计、SLA | 试点 ¥5–10 万；标准 ¥20–50 万/年 + 用量 | 1 个签约试点 |
| 平台合作版 | AI 平台、渠道、Agent 开发者 | 标准 MCP/OAuth、计量、渠道分发 | 平台费 ¥5–20 万/年 + 用量/分成 | 1 个渠道结算闭环 |

原则：先把“可卖的任务结果”定义清楚，再定套餐；不以接口数量、Skill 数量替代客户价值。

以上不是正式报价。正式定价前需按数据授权、模型成本、交付工作量、SLA、并发与部署方式重算单位经济性，并经商务、财务、法务和合规评审。

积分只奖励有效行为：首次授权、任务复用、可复现问题反馈、发布合格应用、邀请有效团队成员；高成本任务按资源点扣减，订阅与机构合同提供月度额度。

机构合作模式分为四类：标准能力订阅、联合解决方案、渠道分发/分成、私有化/专属域；分别以生产任务完成、端到端业务闭环、授权结算可追溯和安全性能验收作为首个完成标准。

## 3. 往外看：行业需求与竞品

金融机构的共同需求可归纳为四类：标准协议与沙箱带来的快速接入；OAuth/SSO/Scope/审计带来的安全可控；Skill 化 SOP 带来的专业可交付；用量、SLA、结算和单位任务成本带来的成本可经营。

| 竞品 | 强项 | 对 OAP 的启示 |
|---|---|---|
| 中金 | 公开媒体披露首批首席分析师 Skills，覆盖宏观、策略、资产配置等任务 | 专家方法、品牌信任和高质量交付正在被 Skill 化 |
| 东方财富 | 金融大模型、数据、图表、Agent 与公开生态 Skills | 数据覆盖与流量入口形成壁垒，OAP 需突出授权后的长期账户服务 |
| 同花顺 | 公开信息显示 iFinD 已布局 MCP、Skills 与研报/风控/舆情 Agent | 从查询入口扩展到机构 Agent 能力基础设施 |
| 聚源 | AI 原生数据集、Agent 协同、MCP/Skills 控制面、私有化和资源点计量 | 最直接的平台化参照；OAP 应强化授权治理、投顾 SOP 与渠道飞轮 |

OAP 的差异化不应是“也有 MCP/Skills/Agent”，而应是：

1. 买方投顾与账户服务的合规闭环；
2. 能力从开放到授权、审计、计量、结算的一体化控制面；
3. AI 小顾 → AI 实验室 → 应用/渠道 → 真实反馈回流的持续服务飞轮。

## 4. 向内看：问题回顾

### 4.1 协议与治理债务

- SSE → Streamable HTTP、API Key → OAuth 是产品化升级，不是简单技术迁移；
- 2026-07-21 资产盘点显示：85.3% 路由未分组、96.2% 未分类、471 条缺少 Operation ID；
- 如果不先统一资产身份，授权、计费、质量和经营分析都会产生多套口径。

### 4.2 用户与质量

- 当前应从“调用成功”升级到“任务是否完成、结果是否可用、是否被复用”；
- 质量评估需要覆盖正确性、时效性、稳定性、可解释性、合规性与单位成本；
- 证券机构标签存在重复和非标准命名，机构运营尚未形成可靠 CRM 口径。

### 4.3 资源与组织

- OAP、STARGATE、AI 实验室、Agent Platform、小顾和外部渠道是一个系统，不宜分别以功能上线衡量；
- 建议设置单一项目 Owner 和周度发布闸门，产品、研发、数据、安全、合规、运营共同签署；
- 数据采购以“高价值任务缺口 + 商业化机会 + 单位经济性”排序，避免先买数据再找场景。
- 产品持续补位商务与运营、技术团队转移、跨 BU 分工不稳，需要固定核心战队和关键岗位招聘/借调时限；
- MCP 质量问题、用户需求和大量机构交流要进入统一 VOC/缺陷/商机池，周度归因到资产 ID 与 Owner。

## 5. H2 路线图

### 8 月：统一基线

- 69 项能力唯一资产 ID；
- 五类 Scope、双鉴权、审计与撤销闭环；
- 质量分层、机构法定名映射、渠道台账；
- 千问/微信各跑通一条可审计 P0 闭环。
- 8/15 前完成 STARGATE 接入治理、WorkBuddy OAuth 和首批 P0 MCP 缺陷优化；8/31 前完成 SSO 与员工渠道基础能力。

### 9—10 月：形成可卖样板

- 个人、机构、平台三类产品包装；
- 任务完成率、复用率、业务转化与成本看板；
- 1 个机构签约试点、1 个平台结算试点；
- AI 实验室沉淀可复用应用，回流 OAP 目录。

### 11—12 月：规模化

- 达成 1,300 万调用、10,000 用户、MAU 2,000 的正式 H2 OKR；
- 建立稳定的发布、SLA、计量计费与运营机制；
- 验证三个新增 AI 渠道，而不是只完成技术接入。

## 6. 管理层看板建议

北极星：**有效服务完成量 × 复用率 × 可变现率**

配套指标：

- 增长：累计用户、激活率、WAU/MAU；
- 使用：任务完成量、成功率、时延、30 日复用；
- 供给：正式能力数、分级覆盖、质量通过率；
- 渠道：生产可用渠道、授权完成、渠道任务完成；
- 商业：试点数、合同额、收入、毛利、单位任务成本；
- 风险：审计覆盖、授权撤销时效、数据异常、重大质量事件。
