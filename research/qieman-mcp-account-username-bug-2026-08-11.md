## 一句话结论

页面展示的“CLI申请的占位符”不是前端写死文案，而是申请记录中的 `name` 脏值；前端把申请记录姓名作为最高优先级直接显示。生产环境确认共有 **4 位用户**命中，占已批准申请用户 **4 / 9,379，约 0.043%**。影响面小，但最近一次仍在 2026-08-10 06:31（北京时间）写入，说明异常写入链路尚未停止。

## 这里本来应该展示什么

业务语义是“申请人姓名”。当前页面规则是：

1. 优先展示 API Key 申请记录中的 `application.name`；
2. 没有申请姓名时，回退到且慢账号身份中的 `poManagerName`；
3. 两者都没有时展示 `--`。

因此这里应展示用户提交的真实申请姓名；自动开通且没有填姓名时，应展示账号身份姓名或 `--`。不应展示 CLI、测试、占位符或其他技术标记。

## BUG 定义与分级

- 用户现象：个人中心头像下方显示“CLI申请的占位符”。
- 用户影响：破坏账号可信感，用户无法判断资料是否串号、测试数据泄露或账号异常。
- BUG 严重度：**P2**。命中率低，但发生在账号中心、仍持续新增、用户感知强。
- 交付风险：**红色风险**。实践文档明确把账号、接口、数据库、权限相关变更划为红色，不能由产品直接改完上线，必须转研发评审、测试和 DBA 受控执行。

## 根因分析：证据分级

### 已确认

1. 前端三个展示入口都使用 `application.name || poManagerName || '--'`，因此申请记录一旦有非空脏值，就会遮住正常账号姓名。
2. 调用链为：`albus → pmdj-service → STARGATE → api_access_application`。
3. `pmdj-service` 当前只是补入用户 ID 和平台类型后透传请求，不生成占位文案。
4. 当前可访问的 `albus`、`pmdj-service` 主干代码均未包含“CLI申请的占位符”字面量；且慢网页表单要求填写姓名，普通自动开通路径提交空对象，不会主动生成该文案。
5. 生产 4 条异常记录的姓名、组织、职位完全一致，且全部呈 CLI 特征。
6. 最早脏数据写于 3 月 18 日；个人中心姓名展示逻辑在 3 月 31 日至 4 月 3 日上线。即：脏数据先存在，后来被新页面显性暴露。

### 合理推断

某个 CLI 或自动化申请客户端把临时占位文案作为正式的姓名、组织、职位提交；STARGATE 对“非空但无业务意义”的哨兵值缺少语义校验，因而自动批准并落库。前端随后按既定优先级忠实显示了脏值。

### 仍待确认

- 具体是哪一个 CLI 仓库、版本和调用方写入该值；当前 GitLab 可见项目中未定位到字符串来源。
- STARGATE 对应仓库的当前实现细节与负责人；当前账号无该项目访问权限，后台也返回 403。
- 4 位用户是否都来自同一 CLI 版本或同一自动化任务；需要以 STARGATE 接入日志按创建时间、来源和 API Key 归因。

## 需要改动哪些服务

### 必须改

1. **CLI / 自动化申请端（根治源头，仓库待定位）**
   - 不再提交姓名、组织、职位的占位符；未知信息用空值。
   - 显式提交 `applicationSource` / `clientId` 等来源标识，便于审计。

2. **STARGATE（根治守门）**
   - 在新增和更新申请时统一做 trim、空值规范化和哨兵值校验。
   - 对姓名/组织/职位三字段相同、包含 placeholder/占位符/CLI 申请等模式告警或拒绝。
   - 自动开通场景用显式来源与空字段表达，不能用自然语言占位。
   - 对字典推断增加保守条件，避免脏组织被自动沉淀为正式字典项。

3. **生产数据修复（DBA 受控）**
   - 先备份并复核精确 4 条记录，再把姓名、组织、职位、组织 ID 恢复为缺失态或经业务确认的真实值。
   - 评估禁用/删除异常组织字典项 `user_org_cli`，先确认没有其他引用。
   - 本准备包只提供只读审计 SQL，不提供可直接复制执行的生产 UPDATE。

### 建议改

4. **albus（前端兜底）**
   - 抽一个统一的 `resolveMcpDisplayName`，移动端、PC、详情页共用。
   - 对已知哨兵值视为缺失，回退账号姓名或 `--`。
   - 这是防御层，不应替代 CLI 与 STARGATE 根治。

### 默认无需业务逻辑改动

5. **pmdj-service**
   - 现状是薄代理，默认无需新增占位符规则。
   - 如果接口要新增 `applicationSource` 或错误码映射，需要同步协议透传、类型和回归测试。
